## 2차 개선 결과 — 같은 요청, 줄어든 DB 부담 (2026-10-15)

[PR #749](https://github.com/woowacourse-teams/2026-poudy/pull/749)를 dev에 합치고 스테이징 전체 파이프라인 배포를 확인했다. **같은 44 req/s에서 로컬 p95는 46.0%, DB 평균 CPU는 50.5% 줄었다.**

### 수정 내용

| 대상 | 변경 |
|---|---|
| 자동완성 | 검색과 표시 정보만 조회. 결과가 있으면 2 SELECT |
| 상품 목록 | 카드에 필요 없는 성분 재조회 제거. Repository 본조회 4 SELECT, 필터 검증은 별도 |
| 성분 필터 | 빈 제외 검사 생략, 포함 성분을 가진 상품 먼저 선별 |

검색 순서·강조·필터별 개수·첫 옵션·상세·유사제품 동작을 유지했다.

### 응답 시간

같은 8종 비율·입력값으로 전후 각각 1회 측정했다. 7 req/s는 10분, 44는 로컬·AWS가 22씩 5분간 실행했다(시작 차이 약 5초).

표는 **p95 / p99, 단위 ms**다. 출발지가 달라 응답 시간은 합치지 않았다.

| 조건·출발지 | 수정 전 p95/p99 | 수정 후 p95/p99 |
|---|---:|---:|
| 7·로컬 |85.12/172.92|52.70/61.45|
| 44·로컬22 |95.88/223.98|51.75/62.01|
| 44·AWS22 |73.84/226.51|34.86/47.95|

**모든 구간에서 HTTP·내용 검증 실패, timeout·통신 실패·누락은 0건**이었다. API별 임시 기준도 통과했다.

요청 수는 7에서 4,201 → 4,200건, 44 합계는 13,202 → 13,201건이었다. 1건 차이는 시험 종료 경계에서 생겼고 누락 지표는 0이다. 별도로 5개 API를 30회씩 호출했으며 대표 응답 JSON도 전후 같았다.

### 자원 사용과 SQL 비용

CPU는 **평균 / 최대, 단위 %**다. DB는 10초, 백엔드 컨테이너는 약 16초마다 읽었다. 컨테이너 CPU의 100%는 1코어를 뜻한다.

| 대상·부하 | 수정 전 | 수정 후 |
|---|---:|---:|
|DB·7|11.52/16.52|5.93/10.63|
|DB·44|67.99/74.41|33.68/41.03|
|BE·7|7.59/16.87|7.59/33.36|
|BE·44|36.44/43.72|26.62/42.20|

44 구간에서 DB 연결을 빌려 쓰는 시간은 평균 **42.37 → 17.76ms**, 빌리기까지의 대기는 **0.892 → 0.179ms**였다. 연결을 기다리는 요청(pending)의 최대는 전후 0이었다.

SQL은 44 구간의 스테이징 DB OID + `poudy_user` 통계 증가분이다. health·주변 요청도 포함한다. 초기화 시각은 같고 통계 항목 제거(`dealloc`)는 0이었다.

| 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| SQL 실행시간 합계 |411.72초|173.11초|
| SQL 반환 행 |27,053,557|5,484,487|
| 성분 태그·효능 출처 반환 행 |6,140,880|430,950|

SQL 실행시간 합계는 **58.0%**, 반환 행은 **79.7%** 줄었다. 반환 행은 디스크에서 읽은 행 수와 다르다.

**해석:** 필요 없는 데이터 조회와 성분 검사 비용을 함께 줄인 효과다. 각 수정의 효과를 따로 측정한 것은 아니다. 백엔드 CPU는 7에서 평균이 비슷하고 최대는 늘었으므로 모든 자원 수치가 좋아졌다고 해석하지 않는다.

### Grafana 전후 그래프

44 req/s 시험은 UTC 기준 수정 전 04:48–04:53, 수정 후 05:17–05:22다. 사이의 배포·기동 시간은 비교에서 제외했다.

**DB CPU 캡처 정정:** 첨부했던 원본 이미지에도 그래프가 없어 제거했다. 앞서 그래프에서 CPU 감소를 확인할 수 있다고 쓴 설명은 잘못이었다. DB CPU 수치는 위 표와 첨부 원본의 10초 간격 표본을 근거로 한다. 압축 파일에 남은 해당 빈 캡처는 증거로 사용하지 않는다.

![상품 목록의 서버 측 p95 전후](https://github.com/user-attachments/assets/baac76bf-0e23-4e26-8733-b23c6bc89ee9)

서버의 상품 목록 응답 시간이다. 피부·카테고리·성분 필터가 같은 주소로 합쳐지고 5분 통계로 추정하므로, 위 k6 API별 수치와 구분한다.

### 자동 테스트와 종료 확인

[ProductReadQueriesTest](https://github.com/woowacourse-teams/2026-poudy/blob/366bf382017aa81f4a66d9201ed090e02c5cc141/server/src/test/java/com/poudy/product/repository/ProductReadQueriesTest.java)는 조회 횟수·표시 정보를, [ProductDatabaseQueryTest](https://github.com/woowacourse-teams/2026-poudy/blob/366bf382017aa81f4a66d9201ed090e02c5cc141/server/src/test/java/com/poudy/product/controller/ProductDatabaseQueryTest.java)는 여러 구성품·중복 성분 ID 등의 결과를 검사한다.

로컬 전체 검증은 **1,160개 테스트·실패 0건**, [최종 Server CI](https://github.com/woowacourse-teams/2026-poudy/actions/runs/38683689580/job/116253673461)와 gate도 성공했다. OpenAPI 변경은 없다. DB 객체를 바꾸지 않아 새 Flyway 파일은 없다.

DB swap은 전 구간 0이었다. 종료 후 DB CPU 약 0–1%, 운영·스테이징 공개 API 200을 확인하고 임시 프로세스를 종료했다.
