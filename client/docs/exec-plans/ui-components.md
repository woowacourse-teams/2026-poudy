# 공통 UI 컴포넌트

> 상위 문서: [MVP 화면 구현 계획](./mvp-screen-plan.md) · PR 4 / `feat/client-ui-components`

## Goal

`v1.pen` 의 재사용 컴포넌트를 구현한다. 여러 화면에 반복되는 것만 만들고, 한 화면에서만 쓰는 것은 해당 화면 PR 에서 만든다.

## Decisions

### UI 라이브러리를 쓰지 않는다

`client-requirements.md` 가 Bootstrap · MUI · Chakra 등을 제한한다. 직접 마크업하고 스타일링한다.

### 상단 영역은 두 종류뿐이다

디자인의 상단 영역 프레임은 이름이 8 가지였지만 구조는 두 개다.

- **루트**(제목만): S01 홈 · S07 저장함 · S08 카테고리 · S10 브랜드
- **하위**(뒤로가기 + 제목): 나머지

`Right Slot` 44x44 빈 프레임이 반복되는데 좌우 균형용 여백이다. 왼쪽 뒤로가기 버튼과 같은 크기로 오른쪽을 채워 제목을 가운데 정렬한다. 지우면 제목이 왼쪽으로 쏠린다.

디자인의 `디바이스 상태바`(시간 · 통신 · 배터리)는 목업 표현이라 구현하지 않는다.

### 하단 내비게이션은 layout 에 둔다

4 탭(홈 · 카테고리 · 탐색 · 저장)이고 대부분의 화면에 나온다. 활성 탭만 prop 으로 받는다. S03a(성분 자동완성)에는 없으므로 해당 라우트에서 숨긴다.

### 접근성

`client-requirements.md` 의 접근성 과제가 시맨틱 태그와 스크린리더 사용을 요구한다. 컴포넌트 단계에서 지키는 편이 나중에 고치는 것보다 싸다.

- 내비게이션은 `<nav>`, 목록은 `<ul>`/`<li>`
- 아이콘만 있는 버튼(저장 · 검색어 지우기)에 접근 가능한 이름을 준다
- 바텀시트는 열렸을 때 포커스를 가두고 `Esc` 로 닫는다
- 물방울 레벨처럼 색과 모양으로만 표현한 값에 텍스트 대안을 준다

## 컴포넌트 목록

| 이름 | 프레임 | 쓰이는 화면 |
| --- | --- | --- |
| 상단 영역 · 루트 | — | S01 · S07 · S08 · S10 |
| 상단 영역 · 하위 | — | 나머지 |
| 하단 내비게이션 | C01 · C02 | 대부분 |
| 제품 목록 카드 | C03 | S01 · S04 · S07 · S09 · S11 |
| 제품 저장 버튼 | C04 · C05 | 카드 · S05 |
| 통합 검색 필드 | C06 | S02 · S03 · S04 · S07 |
| 정렬 드롭다운 | C07 · C12 | S04 · S09 · S11 |
| 제품 정렬 헤더 | C08 | S04 · S09 · S11 |
| 화면 제목 | C09 | 여러 곳 |
| 버튼 Primary · Secondary | C10 · C11 | 여러 곳 |
| 바텀시트 셸 + 딤 | — | S04a~d · S09a~b · S11a |

바텀시트는 디자인에서 `layoutPosition: absolute` 로 콘텐츠 위에 얹힌다. 딤(`#00000066`)과 시트를 한 셸로 만들고 내용만 갈아 끼운다.

검색 필드의 `검색어 지우기 Button` 은 입력이 있을 때만 보인다. 디자인에 `· 기본`(숨김)과 `· 입력 중`(표시) 두 상태가 있다.
