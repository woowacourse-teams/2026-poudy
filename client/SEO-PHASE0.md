# Phase 0 전체 진단 — 2026-09-26

## 진단 범위

`fire-your-seo-agency`의 원래 범위인 SEO·AEO·GEO·LLMO·NEO와 콘텐츠 운영을 조사했다. 기술 기반과 Google 기준선은 [이전 상세 진단](SEO-PHASE0-GOOGLE.md)을 사용하고, 이번에는 공개 검색 결과·브랜드·출처·콘텐츠 인벤토리를 추가했다. 사용자 타깃은 한국 여성이고 채널 우선순위는 네이버·다음·Google이다.

이번 작업은 진단이다. 앱 코드·운영 데이터·robots 정책을 바꾸거나 배포하지 않았다. 이전 턴의 미배포 구현은 운영 상태로 계산하지 않았다.

## 주요 발견 1 — 콘텐츠 정확성을 먼저 점검해야 한다

운영 `/ingredients/6313`의 비타민나무수는 다음 내용을 제공한다.

- 이름/영문명: 비타민나무수 / Hippophae Rhamnoides Water.
- 배합 목적: 연마제·완충제.
- 설명: 산성 유기화합물 계열 원료와 pH 조절 중심.
- 출처 문구: 대한화장품협회 성분사전, 성분코드 6313.

그러나 [대한화장품협회 원문](https://kcia.or.kr/cid/search/ingd_view.php?no=6366)은 동일한 한글·영문명의 성분을 **코드 6366, 배합 목적 착향제·피부컨디셔닝제(기타)**로 제공한다. 운영 API뿐 아니라 공개 HTML에서도 연마제·완충제와 산성 원료 설명을 확인했다.

이 표본에서는 출처의 코드·배합 목적이 운영 내용과 일치하지 않는다. 내부 ID를 외부 성분코드로 표시하는지, 수집·매핑·요약 과정이 어긋났는지는 추가 조사가 필요하다. 전체 성분이 잘못됐다고 일반화하거나 임의의 의료 설명으로 대체하지 않는다. **이 콘텐츠를 JSON-LD·FAQ·AI 안내로 더 널리 전달하기 전에 원본 대조와 검수를 우선해야 한다.**

## GEO — 정책과 인용할 수 있는 데이터

- robots.txt에는 AI 전용 그룹이 없으며 wildcard 그룹이 공개 상세를 허용하고 `/api/`, 대부분의 `/products` 조건 목록과 `/share/`를 차단한다.
- Yeti, Daum, bingbot, OAI-SearchBot, ChatGPT-User, PerplexityBot, Claude-SearchBot, GPTBot 이름으로 제품 `/312`를 요청하면 모두 200이다. 이는 User-Agent 표본 검사이며 실제 공급자 IP의 접근이나 봇 방문을 입증하지 않는다.
- 제품 전성분·브랜드 원문은 파우디가 원출처라고 주장할 수 없다. 파우디가 제공하는 제품별 성분 분류, 포함/제외 조건에 따른 자체 카탈로그 집계와 탐색 결과는 독자적인 서비스 데이터 후보다.
- 성분 `/2`의 포함 제품 수는 현재 API 기준 17개다. '파우디 카탈로그 중 17개'라는 범위와 기준일·집계 방법을 함께 제시해야 전체 시장 수량으로 오해하지 않는다. HTML 캐시의 정보 갱신일과 동적인 제품 수가 같은 기준이라고 가정하지 않는다.
- 출처는 이름·문헌 제목 중심이고 클릭 가능한 원문 주소는 표본에서 부족하다. 출처 표시가 정확한 원문 매핑까지 보장하지 않는다는 반례가 위에서 발견됐다.

표본 질문은 진단자가 URL 역할에서 추론한 의도이며 기존 편집 백로그가 있다는 뜻이 아니다. 제품/성분 전체의 발행일, 90일 이상 미갱신 수, 검수자, 노출 0 페이지 수는 현재 자료로 계산할 수 없다. 명시적인 질문·근거·검수·갱신 정책 파일도 저장소 검색에서 확인되지 않았다.

운영 일반 사이트맵에는 `/saved`가 아직 포함돼 있다. 최신 dev에서 이를 제외한 상태와 다르며, 기기별 빈 저장함을 중요 콘텐츠로 제출하는 정책도 재검토할 항목이다.

## 실행 우선순위 제안

### 사용자 합의에 따른 범위 조정 (2026-09-26)

- 성분 데이터 매핑 문제는 DB 작업으로 분리하고 이번 SEO 구현 범위에서 제외한다.
- `/search/products`, `/search/ingredients`에 SEO용 목록을 추가하지 않는다. 두 검색 화면의 색인은 상세 페이지 발견의 필수 조건이 아니다.
- 발견 경로는 홈 → 카테고리·브랜드 디렉터리 → 제품 목록 → 제품 상세 → 성분 상세와 사이트맵을 기준으로 한다.
- 최신 dev에는 목록의 다음·이전 페이지 링크, 페이지별 서버 조회와 canonical, 범위 밖 페이지의 404 처리가 이미 있다. 이 기능을 중복 구현하기보다 운영 반영 여부를 먼저 확인한다.
- 관련 기존 테스트 27개가 통과했다 (`ProductList.pages`, `product-page-range`, `seo/routes`). 제품 상세의 성분 링크와 제품·성분 사이트맵 생성 코드도 확인했다.
- 운영 `/brands/23?page=2`는 여전히 첫 페이지와 같은 제품 20개와 첫 페이지 canonical을 반환한다. staging에서는 브랜드의 다음 페이지 링크·페이지별 canonical과 2페이지 제품 3개를 확인했다. 카테고리 `/categories/1`과 `?page=2`는 서로 다른 제품 20개씩을 반환하며 다음 페이지 링크도 있다. staging의 `noindex, nofollow`는 유지한다.

따라서 다음 실행 순서는 **기존 dev 변경의 운영 반영 → 운영 HTML에서 페이지별 제품·링크·canonical 검증 → Google 미색인 URL 표본과 사이트맵 상태 대조**다. 아래 목록은 최초 진단 제안이며, 현재 작업 범위는 이 합의를 우선한다.

1. **성분 데이터의 출처·코드·배합 목적 매핑 검증.** 비타민나무수 표본의 불일치 원인을 찾고 주요 성분을 원문과 대조한다. 사실 검수를 AI 인용·구조화 데이터 확장보다 앞에 둔다.
2. **공개 발견 경로·서버 HTML·기존 개선 반영.** 검색 fallback, 목록 다음 장, 조건 목록의 크롤링 정책, #478 운영 반영, 저장함 사이트맵 정책을 함께 점검한다.
3. **엔진별 색인·등록 확인.** 접근 가능한 Google의 미색인 URL과 사이트맵 처리 상태를 먼저 대조한다. 네이버 소유자의 자료는 가능할 때 받으며 작업의 전제 조건으로 삼지 않는다. 다음·Bing 등록 여부도 확인한다.
4. **중요한 질문과 브랜드 설명 보강.** 공식 출처 링크·정확한 갱신일·카탈로그 범위와 집계 기준, 브랜드의 한국어/영문 기능 설명을 보강한다. 의료 효과·전체 시장 규모·검수자 신원을 만들어 넣지 않는다.
5. **AI 안내·콘텐츠 운영과 측정.** 출처 검수 후 llms.txt, 질문별 페이지 후보, 발행 게이트와 갱신 정책을 마련한다. 수요 데이터 없이 블로그 대량 발행부터 시작하지 않는다.

## 기준선과 재측정

- 기술 기준선: 현재 사이트맵 1,914 URL, 공개 상세 200, 상세 표본 index/follow, 검색·목록 발견 경로 공백.
- Google 지표: 9월 21일 색인 11개, 미색인 22,597개. 8월 28일~9월 24일 노출 122·클릭 3. 과거 22,000여 URL과 현재 사이트맵을 구분한다.
- 네이버 공개 기준선: 제품 전성분 질문 1개에서 파우디 링크 확인. 나머지 표본 질문은 위 표에 결과를 기록했다. 관리자 수치·순위 합계는 미확인이다.
- AI 유입: 사용자가 `utm_source=chatgpt`가 붙은 유입을 가끔 관측했다고 알려 주었다. 건수·방문 URL·답변별 출처 표시는 아직 대조하지 않았다. 독립 AI 검색 인용·무검색 모델 인지는 별도로 미측정이다.
- 콘텐츠 정확성: 원문과 다른 표본 1개 발견. 검수 대상 표본 수와 수정 여부를 추적한다.

변경 배포일 D0부터 같은 질문·URL·엔진·접속 조건으로 D0+14일에 수집·색인·인용을 다시 확인하고 D0+28일에 유입 추세를 비교한다. 9월 26일 배포한다면 각각 10월 10일·10월 24일이다. 아직 배포 전이므로 알림이나 고정 일정은 예약하지 않았다. 네이버 공개 검색 관측은 소유자 계정 없이 같은 방식으로 반복할 수 있다.

## 완료 범위

Phase 0의 6개 레인을 조사하고 증거와 우선순위를 작성했다. 계정 지표·외부 서비스·독립 모델에 접근하지 못한 측정은 명시적으로 남겼다. 따라서 진단 보고서 작성은 완료했지만 모든 항목이 실측됐다고 주장하지 않는다. Phase 1 구현으로 넘어가기 전 이 우선순위를 검토한다.
