# Phase 3·4 진단 — 2026-09-26

## 범위와 판정 기준

- Phase 3: 스킬의 AEO·GEO·LLMO. Phase 4: 네이버 검색과 AI 브리핑.
- 코드: `2026-poudy-seo`의 dev 기반 워크트리. 공개 응답: `poudy.site`와 `poudy-staging.vercel.app`의 홈, 제품·성분·카테고리·브랜드·큐레이션 표본, robots.txt, 사이트맵.
- staging은 `noindex, nofollow`와 `robots.txt Disallow: /`로 차단한다. 색인 성과를 staging에서 판단하지 않는다.
- 네이버 웹마스터도구 소유자 권한과 Bing 관리자 지표가 없으므로 해당 엔진의 수집·색인 수치를 판정하지 않는다. 사용자는 `utm_source=chatgpt`가 붙은 파우디 유입을 가끔 관측했다고 알려 주었다. 유입 건수·대상 URL·실제 ChatGPT 답변의 출처 표시는 아직 대조하지 않았다. 공개 검색 관측은 [Phase 0 보고서](SEO-PHASE0.md)에 분리했다.

## Phase 3 세부 관찰

### AEO: 답을 추출할 수 있는 본문

- 운영 `/products/312`, `/ingredients/6313`과 staging `/products/1`의 본문·제목은 HTML에 있다. staging 제품은 BreadcrumbList와 Product JSON-LD가 있고, 제품의 성분 링크도 HTML에 있다.
- staging `/curations/1`은 질문형 h1, `/curations/2`는 계절 주제의 h1을 갖고, 둘 다 제품 링크와 BreadcrumbList가 있다. 그러나 큐레이션 `description`은 메타데이터에만 쓰고 본문에 표시하지 않는다. `IMAGE` 블록은 항상 `alt=""`다. 그림의 문구가 핵심 설명인 경우 텍스트만 읽는 사용자와 검색엔진에 답이 충분히 전달되지 않는다. [#557](https://github.com/woowacourse-teams/2026-poudy/issues/557)에 서버 데이터·클라이언트 본문 작업을 기록했다.
- 성분 상세에는 설명과 출처 이름·갱신일이 보이지만, 출처는 링크가 아닌 문자열이다. Phase 0에서 `/ingredients/6313`의 설명·배합 목적과 대한화장품협회 원문 간 불일치 표본을 확인했다. 원본 대조는 DB·콘텐츠 작업으로 분리한다. 검수 전에는 이 표본을 FAQ·인용 홍보의 근거로 사용하지 않는다.
- Google 공식 안내는 AI Overviews/AI Mode의 별도 파일·특수 마크업을 요구하지 않고, 색인 가능성과 텍스트 본문·내부 링크·가시 내용과 일치하는 구조화 데이터를 기본 조건으로 설명한다. 따라서 FAQ나 스키마를 늘리는 것보다 본문의 정확성과 배포 후 색인 확인이 앞선다. [Google AI 기능 안내](https://developers.google.com/search/docs/appearance/ai-features)

### GEO: 수집과 인용 가능성

- 운영 robots.txt는 `/api/`, 대부분의 `/products` 조건 목록, `/share/`를 막고 공개 제품·성분 상세를 허용한다. Phase 0의 User-Agent 표본 요청은 200이었지만, 실제 공급자 IP의 방문이나 인용을 입증하지 않는다.
- 사용자가 PostHog 등에서 `utm_source=chatgpt` 유입을 가끔 본다는 관찰을 제공했다. 파우디로 향하는 ChatGPT 링크를 통한 유입의 신호다. 이 속성만으로 답변의 출처 칩에 인용되었는지, 일반 링크를 누른 것인지, 실제 유입량이 얼마인지는 구분할 수 없다.
- 이 워크트리에 `/llms.txt` 라우트가 준비되어 있고 운영 배포에서만 제공하도록 설계되어 있다. 9월 26일 운영과 staging에서는 모두 404다. Google 검색 AI 기능은 llms.txt를 요구하거나 사용하지 않는다고 명시한다. 이 파일을 색인 개선의 선행 조건으로 삼지 않는다. [Google 안내](https://developers.google.com/search/docs/appearance/ai-features)
- 제품 페이지는 출처를 `브랜드 공식 전성분`으로 설명하고 성분 페이지는 출처 이름을 보여 준다. 개별 제품·성분의 원문 URL, 추출 기준, 검수 상태를 연결하는 구조는 표본에서 확인되지 않았다. 인용용 주장·수치는 검수 가능한 원출처와 기준일이 있을 때만 제공해야 한다.

### LLMO: 서비스 정체성

- 홈 JSON-LD의 WebSite와 Organization은 안정된 `@id`를 쓰고, `Poudy`와 `파우디`를 같은 서비스로 표현한다. `sameAs`에는 공식 Instagram 하나가 있다.
- 문의 페이지와 footer는 있으나 `About` 페이지는 없다. 운영 주체, 서비스가 직접 수집·계산한 데이터의 범위, 수정 절차를 한곳에서 설명하면 사용자와 검색엔진이 정체성을 확인하기 쉬워진다. 외부 채널은 실제 공식 운영 여부를 확인한 것만 추가한다.
- ChatGPT·Claude·Gemini의 무검색 인지와 답변별 출처는 독립 세션으로 측정하지 않았다. ChatGPT 태그 유입 관찰을 무검색 모델 인지의 증거로 바꾸거나 점수를 임의로 부여하지 않는다.

## Phase 4 세부 관찰

- 운영 `robots.txt`는 사이트맵을 선언하고 공개 상세 경로를 허용한다. staging의 전체 차단은 의도된 설정이다. 네이버는 robots.txt, HTML 제목·설명, 내부 `<a href>` 링크와 사이트맵을 수집·이해의 기본 요소로 안내한다. [robots 안내](https://searchadvisor.naver.com/guide/seo-basic-robots), [리소스·링크 안내](https://searchadvisor.naver.com/guide/resource-and-link)
- 운영 홈 설명은 코드와 실제 HTML에서 82자다. 사용자가 제공한 네이버 간단 체크는 사이트 설명과 OG 설명의 80자 이내 작성 권고를 경고했다. 표현을 줄일지는 검색 결과 문구의 정확성을 고려해 판단한다. 이 경고만으로 색인 실패 원인을 단정할 수 없다.
- staging 카테고리·브랜드 목록은 제품 링크와 다음 페이지 링크를 HTML로 제공한다. 운영의 페이지네이션은 아직 이전 버전이다. 월요일 배포 후 두 번째 장의 제품이 첫 장과 다른지, canonical이 해당 장인지 확인한다.
- 네이버 계정 없이 URL별 수집 상태, 미색인 사유, 제출된 사이트맵 처리 결과, 검색어·노출·CTR을 볼 수 없다. 과거 공개 간단 체크와 `site:` 검색은 이 지표의 대체재가 아니다. 네이버는 수집 → 정제 → 색인 → 랭킹을 구분하며 수집 요청 성공도 노출을 보장하지 않는다. [수집 현황](https://searchadvisor.naver.com/guide/report-crawl-refine), [수집 요청](https://searchadvisor.naver.com/guide/request-crawl)
- AI 브리핑 출처 칩의 파우디 인용 여부는 확인되지 않았다. 검색 결과에 AI 브리핑 표시가 있다는 사실만으로 인용 여부를 판정하지 않는다.

## 월요일 배포 전후 실행 순서

1. **배포 전:** #557의 서버 계약·본문 작업을 준비하고, 대표 큐레이션의 질문·직답·근거 자료를 검수한다. 성분 데이터 불일치 표본은 DB 담당 작업으로 유지한다.
2. **배포 직후:** 운영 홈·큐레이션·제품·성분의 200/404, robots, canonical, 제목·설명, HTML 본문·제품 링크, 사이트맵의 큐레이션 URL을 점검한다. staging은 계속 차단한다.
3. **소유자 계정으로:** 네이버 서치어드바이저에서 대표 URL의 수집·색인 상태와 사이트맵 처리 결과를 확인한다. 기존의 하루 50개 수동 요청 중 성공/거절 사유가 있으면 URL 표본과 함께 받는다.
4. **2주 후:** 같은 URL과 질의로 네이버·Google의 색인/노출/클릭, AI 유입을 다시 기록한다. ChatGPT 유입은 `utm_source`, 방문 URL, 시각과 건수로 집계하고, 실제 답변 인용은 해당 서비스의 출처 링크 또는 답변 화면을 별도로 확인한다.

## 우선순위에서 제외한 일

- 색인 전 FAQPage·Product 스키마를 일괄 추가하거나, 출처가 검수되지 않은 성분 설명을 AI 답변용으로 확대하지 않는다.
- `/search/products`, `/search/ingredients`를 색인용 허브로 바꾸지 않는다.
- llms.txt 존재를 Google·네이버 색인의 해결책으로 취급하지 않는다.
