# 선반 분석: 유입, 로그인 전환, 회원 활용

[이슈 #968](https://github.com/woowacourse-teams/2026-poudy/issues/968) ·
[PostHog 대시보드](https://us.posthog.com/project/562550/dashboard/2256429) ·
[저장한 이벤트·쿼리 정의](./shelf-insights.json)

## 확인하려는 성과

선반의 성과는 로그인 수에서 끝나지 않는다. 제품을 기록한 회원이 그 기록으로 성분 필터를 만들고,
다음 제품을 찾을 때 다시 활용하는지 확인한다. 이를 세 영역으로 나눠 본다.

| 영역        | 질문                                                           | 주요 지표                                         |
| ----------- | -------------------------------------------------------------- | ------------------------------------------------- |
| 비회원 유입 | 어디서 선반을 알게 되고 사용하려 하는가?                       | 진입점별 노출·선택 수와 선택률                    |
| 로그인 전환 | 선반을 쓰려던 사람이 로그인하고 원래 하려던 행동까지 마치는가? | 로그인 요청 → 시작 → 성공 → 원래 행동 완료        |
| 회원 활용   | 기록을 쌓고 성분 분석·개인화 탐색에 다시 쓰는가?               | 담기·평가·필터 반영·개인화 상세 전환, 주간 재사용 |

회원 활용과 재사용을 핵심 성과로 보고, 유입과 로그인은 그 앞의 병목을 찾는 데 쓴다.
목표 전환율은 정하지 않았다. 배포 후 표본과 주간 코호트가 쌓이면 기준선을 정한다.

## 이벤트 계약

새 계약은 `analytics_schema_version=4`이다. 기존 검색 이벤트 이름과 GA4 전송 목록은 유지한다.
아래 이벤트는 PostHog에 보낸다. 자세한 속성 타입은 `lib/analytics/events.ts`에 있다.

| 이벤트                          | 기록하는 시점                                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------- |
| `shelf_entry_viewed`            | 알려진 로그인 상태에서 진입 버튼·탭의 절반 이상이 0.5초 보였을 때                         |
| `shelf_entry_selected`          | 하단 선반 탭, 소개, 제품 상세, 선반 가이드, 잠긴 개인 필터의 진입점을 선택했을 때         |
| `shelf_login_requested`         | 선반의 로그인 안내에서 계속하기를 선택하거나, 회원 전용 화면이 비회원임을 확인했을 때     |
| `login_started`                 | 카카오·Google 로그인을 실제 시작할 때. 외부 이동 전 비콘으로 전송                         |
| `login_succeeded`               | 시작한 로그인 흐름에서 회원 조회로 성공을 확인했을 때. 흐름당 한 번                       |
| `signup_completed`              | 가입 동의 저장과 프로필 입력을 마치고 회원 조회에 성공했을 때                             |
| `shelf_intent_completed`        | 선반에서 시작한 로그인 후 원래 의도한 선반 조회·해당 제품 담기·개인 필터 확인을 마쳤을 때 |
| `shelf_viewed`                  | 선반 상태를 받은 뒤. 비회원·빈 선반·제품이 있는 선반과 항목·평가 수를 구분                |
| `shelf_add_started`             | 회원이 제품 추가 화면을 사용하거나 상세에서 담기용 평가 창을 열었을 때                    |
| `shelf_search_results_viewed`   | 추가 화면의 최신 검색 응답을 그렸을 때. 0건과 이미 담겨 추가할 수 없는 제품을 구분        |
| `shelf_rating_step_viewed`      | 열린 평가 창의 잘 맞음·사용감 단계마다 한 번                                              |
| `shelf_rating_closed`           | 닫기·나중에·사용감 건너뛰기·저장으로 창을 닫을 때. 실제 저장 여부와 요청 진행 여부를 포함 |
| `shelf_product_added`           | 담기 API 성공 뒤. 일반 담기와 삭제 되돌리기를 구분                                        |
| `shelf_product_removed`         | 빼기 API 성공 뒤. 일반 빼기와 담기 취소용 되돌리기를 구분                                 |
| `shelf_rating_saved`            | API 응답의 평가 값이 직전 값과 달라졌을 때. 바뀐 필드와 평가 존재 여부만 전송             |
| `shelf_usage_status_changed`    | API 성공 뒤 사용 중·사용 완료 상태가 바뀌었을 때                                          |
| `shelf_analysis_viewed`         | 도움말에 가려지지 않은 분석 제목이 실제로 보였을 때. 반영 가능한 성분 수와 CTA 유무 포함  |
| `shelf_filter_selection_viewed` | 성분 선택 화면을 받았을 때. 후보 수와 기본 선택 수 포함                                   |
| `my_filter_updated`             | 성분 추가·삭제 API 성공 뒤. 선반·필터 관리 출처와 되돌리기 구분                           |
| `personalized_results_viewed`   | 내 필터가 켜지고 성분이 1개 이상 적용된 성공 결과를 그렸을 때. 0건도 포함                 |
| `personalized_product_viewed`   | 그 개인화 결과에서 선택한 제품의 상세를 봤을 때                                           |

`source`와 `placement`는 진입 위치를, `shelf_entry_source`는 같은 선반 이용 시도가 시작된 위치를 뜻한다.
`auth_state=unknown`은 회원 조회 전 상태이므로 비회원으로 합치지 않는다. 관리자는 별도 값으로 남긴다.

## 연결과 중복 처리

- `entry_view_id`: 같은 진입점의 노출과 선택을 연결한다. 화면을 다시 열면 새 ID를 만든다.
- `shelf_journey_id`: 로그인 전후의 선반 이용 시도를 연결한다. 같은 탭에서 1시간 유지한다.
  세션 저장소가 막히면 현재 화면의 메모리만 사용하므로 외부 로그인 왕복 연결은 보장하지 않는다.
- `login_flow_id`: 소셜 로그인 시도와 가입·로그인 성공을 연결한다. 1시간 뒤 폐기하며 성공은 한 번만 보낸다.
  선반과 무관한 로그인은 `login_source=other`로 남긴다.
- `rating_flow_id`와 `product_id`: 같은 제품의 같은 평가 창을 연결한다. 창을 다시 열면 새 ID를 만든다.
- `analysis_revision`: 분석 결과의 비교용 해시다. 같은 이용 시도와 같은 분석 결과의 노출·선택·반영을 연결한다.
- `exploration_id`: 같은 결과 목록과 그곳에서 선택한 제품을 연결한다. 제품·경로가 맞고 30분 이내인 문맥만 상세에 붙인다.
- `operation_id`: API 요청 전에 만든 변경 식별자다. 담기와 그때 저장한 평가가 같은 요청인지 구분한다.

회원 조회가 성공하면 내부 번호로 만든 `member:<id>`로 식별한다. 로그인 전 익명 기록과 회원 기록을 이어 보고,
다른 기기에서도 같은 회원으로 집계한다. 이메일·프로필 값은 식별 속성으로 보내지 않는다.
로그아웃·탈퇴 뒤에는 식별자를 초기화하며, 그 전에 시작한 늦은 회원 응답은 식별을 되살리지 못하게 한다.
이 동작과 추가 수집 항목은 개인정보처리방침 제2조에 반영했다.

## 퍼널을 읽는 기준

대시보드에는 전환 지표 8개와 주간 재사용 지표 2개가 있다.

| 지표                                       | 단위·전환 기간             | 해석                                                                |
| ------------------------------------------ | -------------------------- | ------------------------------------------------------------------- |
| 비회원 진입점 노출 → 선택                  | `entry_view_id`·1시간      | source/placement별 노출 수·선택 수·선택률                           |
| 선반 로그인 요청 → 시작 → 성공 → 원래 행동 | `shelf_journey_id`·1시간   | 로그인 완료와 선반 목적 달성을 구분. 같은 이용 시도의 재시도는 포함 |
| 회원 선반 조회 → 제품 담기                 | 순 사용자·7일              | 전체 활용 흐름. 같은 제품·탭을 강제하지 않음                        |
| 잘 맞음 단계 → 평가 저장                   | 평가 창·제품·1시간         | 실제 잘 맞음 값 변경과 평가 존재를 확인                             |
| 사용감 단계 → 평가 저장                    | 평가 창·제품·1시간         | 사용감을 지원하는 제품의 해당 단계 진입만 분모                      |
| 성분 분석 노출 → 선택 → 필터 반영          | 이용 시도·분석 결과·24시간 | CTA가 있는 실제 분석 노출만 분모                                    |
| 선반 필터 반영 → 개인화 결과               | 순 사용자·7일              | 기록을 다음 탐색에 활용하는 흐름. 같은 시도·탭을 강제하지 않음      |
| 개인화 결과 → 해당 제품 상세               | `exploration_id`·1시간     | 실제 필터 적용 결과에서 제품을 살펴본 탐색 비율                     |
| 첫 관측 담기 → 이후 주간 평가 저장         | 순 사용자·달력 주          | 기존 회원을 포함하는 첫 관측 이후 활용. 신규 회원 리텐션과 다름     |
| 첫 관측 개인화 상세 → 이후 주간 같은 행동  | 순 사용자·달력 주          | 개인화 탐색의 재사용. 아직 지나지 않은 주는 이탈로 보지 않음        |

같은 임의 속성을 단계 간 고정하는 조건을 네이티브 퍼널 API가 지원하지 않아, 시도·제품 단위 전환은 SQL 표로 저장했다.
SQL은 최근 30일 고정이며 대시보드의 날짜 선택으로 바뀌지 않는다. 일반 퍼널은 기본 최근 30일,
리텐션은 기본 최근 35일·한국 시간 달력 주 기준이다. SQL의 시간 비교는 초 단위이며 전환율은 첫 단계 대비 비율이다.
분모가 0이면 전환율을 공란으로 둔다. SQL의 시도 수와 네이티브 퍼널의 사람 수를 합치지 않는다.

리텐션의 `retention_first_time`은 선택한 관측 기간 안의 첫 행동을 기준으로 삼는다.
생애 첫 행동을 뜻하는 `retention_first_ever_occurrence`와 구분한다([PostHog 공식 설명](https://posthog.com/docs/product-analytics/retention)).

운영 `poudy.site`의 웹과 앱을 포함하고, 봇·프로젝트 내부/테스트 계정·스테이징 반복 방문 코호트를 제외한다.
기존 검색 대시보드의 웹 전용·일부 지역 제외 조건은 가져오지 않았다.

해석할 때 다음을 구분한다.

- 0.5초가 되기 전 빠른 선택은 노출 기반 선택률의 분모에 없다. 전체 선택 수는 별도 선택 이벤트로 확인한다.
- 담기와 평가는 별개다. 나중에 담기, 사용감 건너뛰기, 평가 지우기, 사용 상태만 변경하기를 평가 완료로 합치지 않는다.
- `mutation_reason=undo`와 `is_restore=true`는 새 담기·평가·필터 반영 전환에서 제외한다.
- `selected_count`는 성공한 요청의 중복 제거 성분 수다. 실제 DB 신규 추가 수가 아니다. 기본 전체 선택도 반영에 포함한다.
- `was_unrated`는 저장 직전 미평가 상태다. 생애 첫 평가 여부가 아니다.
- 내 필터의 URL 기본값이나 빈 필터는 개인화 사용이 아니다. API 실패도 결과 0건으로 기록하지 않는다.

## 배포 후 확인

현재 대시보드와 이벤트 정의는 생성했고 저장된 쿼리를 실행했다. 운영 수집 검증은 아직 하지 않았으며,
이벤트 정의의 `verified`도 `false`로 두었다. 테스트 이벤트를 운영 프로젝트에 주입하지 않는다.

1. staging에서 비회원 진입 → 소셜 로그인 → 원래 행동 완료의 ID·순서와 중복 여부를 확인한다.
2. 일반 담기·나중에·사용감 건너뛰기·평가 지우기·빼기·되돌리기와 API 실패를 각각 확인한다.
3. 도움말에 가려진 분석과 숨은 하단 버튼이 노출로 세어지지 않는지 확인한다.
4. 성분 필터 반영 → 실제 적용 결과 → 그 결과의 상세가 같은 탐색으로 연결되는지 확인한다.
5. 운영 배포 뒤 `environment`, 호스트, 버전, 웹/앱 속성과 식별 초기화를 확인한 다음 이벤트 검증 표시를 켠다.
6. 배포 전 0건을 전환 실패로 해석하지 않고, 다음 주가 지난 코호트부터 재사용을 읽는다.
