## 요구사항

### 선반(`/shelf`)

| 상태        | 동작                                                                                                                                                                                                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 불러오는 중 | 0.3초가 지나도 응답이 없으면 성분 카드, 보기 필터, 제품 행 자리에 스켈레톤을 둡니다. 기다리는 영역에 `aria-busy`를 답니다. 10초가 지나도 오지 않으면 스켈레톤 위에 '시간이 조금 걸리고 있어요'와 [다시 시도]를 함께 보이고, [다시 시도]를 누르면 다시 요청합니다(FEEDBACK F02). |
| 로그인 전   | 공감 제목, 좋은 점 셋, '선반 기능 자세히 보기' 줄을 두고, [로그인하고 내 선반 만들기]를 하단 내비 위 행동 영역에 둡니다(S54a).                                                                                                                                                  |
| 관리자 세션 | 관리자 세션 안내를 둡니다.                                                                                                                                                                                                                                                      |
| 오류        | 본문 가운데에 화면 오류(`ErrorState` screen)와 [다시 시도]를 둡니다. 상단 내비와 하단 내비는 남깁니다(S51).                                                                                                                                                                     |
| 빈 선반     | 가운데에 빈 상태 안내와 쓰는 순서 세 단계, [제품 추가하기], '선반은 어떻게 쓰나요?'를 둡니다(S54b).                                                                                                                                                                             |
| 제품 있음   | 성분 카드(안 맞은 제품이 있을 때), 보기 필터, 제품 목록을 둡니다(S52). 성분 카드는 보기 필터를 바꿔도 남깁니다.                                                                                                                                                                 |

- 상단 내비는 큰 제목 내비입니다. 오른쪽에 도움말(`help-circle`, 기능 설명 시트를 엽니다)과 추가(`plus`, `/shelf/add`로 갑니다)를 둡니다. 로그인 전에는 둘 다 숨깁니다(S54a).
- 제품이 담긴 채 선반에 처음 들어오면 기능 설명 시트(S54c)를 한 번 띄웁니다. 빈 선반과 로그인 전에는 본문이 안내를 맡아 띄우지 않습니다. 한 번 띄웠는지는 기기에 남기고, 그 뒤에는 도움말 버튼으로만 엽니다.
- 보기 필터는 상단 내비(64) 바로 아래에 붙습니다. 제품이 있으면 붙은 줄이 아래 선을 맡고, 상단 내비는 선을 긋지 않습니다.
- 보기 필터의 칩 트랙은 화면 폭 끝까지 두고, 좌우 거터를 트랙 안쪽 여백으로 가집니다(LAYOUT L09). 첫 칩은 거터에서 시작하고, 글자를 키워 칩이 넘치면 화면 끝까지 밀리며, 끝까지 밀면 마지막 칩 뒤에도 거터가 남습니다.
- 제품 메뉴(S52d)에서 옮기기·평가 지우기를 하면 결과를 반영한 뒤 '되돌리기'가 있는 토스트를 띄웁니다(S53g). 되돌리면 앞의 평가와 사용 상태로 돌려놓습니다.
- 선반에서 빼면 확인 시트(S52f)를 거칩니다. 뺀 뒤에도 되돌리기 토스트를 띄우고, 되돌리면 같은 사용 상태와 평가로 다시 담습니다.
- 저장·옮기기·빼기에 실패하면 토스트로 알립니다. 평가 시트는 열어 둔 채로 다시 누를 수 있게 합니다.
- 성분 칩을 누르면 그 성분의 설명(`/ingredients/{id}?from=shelf`)으로 갑니다.
- 성분 칩의 이름은 줄을 바꾸지 않고, 한 칩이 칩 묶음보다 넓으면 말줄임으로 자릅니다. 잘려도 칩의 접근성 이름과 성분 설명에는 전체 이름이 있습니다.
- 성분 카드는 머리(제목 · '필터 관리 ›') → 아직 제외하지 않은 성분 → 검색에서 제외 중 → 고르기 버튼 → 아래 안내(피부 타입 · 정확도) 순서입니다. 찾은 성분이 없으면 머리 아래에 '안 맞았던 제품에서 주의 성분을 찾지 못했어요.'만 둡니다(S53m).
- 머리에서 제목과 '필터 관리 ›'가 한 줄에 들어가지 않으면 '필터 관리 ›'를 제목 아래로 넘깁니다. 제목을 낱말마다 쪼개지 않으려는 것입니다.
- #1121부터 아직 제외하지 않은 성분은 서버의 `reasons`에 따라 빠른 제외·건성·지성·민감성 순서로 나눕니다. 분류 이름은 응답의 `name`을 표시하고 빈 분류는 숨깁니다. 여러 근거에 해당하는 성분은 각 분류에서 확인할 수 있지만 전체 성분 수와 검색 제외 선택에는 한 번만 반영합니다.
- 검색에서 제외 중인 성분은 기존처럼 하나의 목록으로 유지합니다. 후보에서 사라진 성분을 나만의 필터에서 자동 삭제하지 않습니다.
- 비회원용 결과 표시를 연결할 수 있도록 결과 카드에 읽기 전용 표시를 제공합니다. 이때 필터 관리·검색 제외·피부 타입 설정 링크를 숨기고 피부 조건별 예상 후보임을 안내합니다. 실제 비회원 선반과 공개 API 연결은 #1118의 후속 작업입니다.
- 고르기 버튼은 아직 제외한 성분이 없을 때 '검색에서 제외할 성분 고르기', 신규 성분이 생겼을 때 '검색에서 제외할 신규 성분 고르기'입니다. #1121부터 피부 타입이 있는 회원은 안 맞은 제품 하나부터 진행할 수 있습니다. 피부 타입이 없으면 기존처럼 두 개부터 제공하며, 나쁜 평가나 고를 성분이 없으면 버튼을 두지 않습니다.
- 평가 시트는 머리에 ✕ 를 두지 않습니다. 딤을 누르거나 끌어 내리거나 Esc 로 닫습니다(S52e · S52i).

### 평가 시트의 결과 미리보기(#1125)

- 평가 시트 1단계가 열리면 시트 위 딤 영역에 '안 맞을 수 있는 성분' 미리보기를 띄웁니다(`BottomSheet`의 `above`). 시트가 열릴 때 미리보기 API(#1134)를 한 번 불러 평가 없음·잘 맞았어요·안 맞았어요 세 결과를 받아 두고, 맞음 답을 바꾸면 고른 결과로 바꿉니다. 받지 못하면 오류 안내나 재시도 버튼 없이 미리보기만 숨기고, 평가 선택과 저장은 계속 허용합니다. 오류는 공통 API 계층에서 내부 기록합니다. 같은 제품을 다시 열어도 이전 요청의 결과를 재사용하지 않으며, 응답 전에 평가를 골랐어도 도착한 결과로 움직임을 시작합니다. 2단계(사용감)에서는 숨깁니다.
- 비교 기준은 시트를 열 때 저장돼 있던 평가의 결과입니다. 이미 평가한 제품을 열거나 원래 답으로 돌아오면 추가·제거 효과 없이 현재 결과를 표시합니다. 평가를 지우면 평가 없음 결과로 바뀌는 차이를 보여 줍니다.
- 결과를 바꿀 때는 기준 결과와 성분 ID로 비교합니다. 새 성분은 650ms 뒤부터 180ms 간격으로 하나씩 나타나고, 개수가 바뀐 성분은 250ms 뒤부터 살짝 커졌다 돌아오고, 빠지는 성분은 작아지며 사라집니다. 잘 맞았어요로 빠지는 성분은 먼저 초록 취소선을 긋습니다. 옆 칩은 자리가 바뀐 만큼 미끄러집니다(FLIP). 칩 움직임은 `transform`·`opacity`를 씁니다.
- 지금 결과에 없던 성분(안 맞았어요로 더해지는 성분)은 빨갛게 둡니다. 묶음은 근거별로 나누고(#1121), 새 칩이 묶음 순서대로 하나씩 채워지며 묶음 개수가 올라갑니다. 시트 위 자리가 좁아 묶음마다 4개까지만 칩으로 보이고 나머지는 '+N'으로 줄입니다.
- 피부타입 미등록 회원은 평가 전과 잘 맞았어요 결과도 전체 타입 기준으로 받아 비교합니다. 이미 있던 피부별 후보를 신규 성분으로 표시하지 않습니다.
- 비로그인과, 피부 타입을 넣지 않아 넓혀 계산한 결과(`ratedBadAcrossSkinTypes`)는 빠른 제외·건성·지성·민감성 묶음을 모두 채워 보여 주고, 안 맞았어요를 고르면 '지금은 모든 타입의 주의 성분을 보여드려요. (로그인 후) 피부 타입을 선택하면 내 피부에 해당하는 주의 성분만 볼 수 있어요.'를 붙입니다. 피부 타입을 아는 회원은 처음부터 해당 묶음만 보이므로 좁혀지는 예시 애니메이션은 따로 두지 않습니다.
- 안 맞았어요로 평가해도 성분·근거·포함 제품 수가 그대로면 기존 후보를 유지하고 성분 목록 아래에 ‘변경된 게 없어요’ 한 줄만 안내합니다. 이때 성분 추가 문구나 피부타입 안내를 덧붙이지 않습니다.
- 잘 맞았어요 결과는 피부타입별 분류 이름을 표시하지 않고 성분 ID 기준으로 중복을 없앤 한 목록에서 취소선·제외 움직임을 보여 줍니다.
- 잘 맞았어요로 빠질 성분이 없으면 최종 크기의 흰 공간을 미리 확보합니다. 초록색 ‘나에게 괜찮았던 성분’ 박스를 250ms 동안 위에서 아래로 펼친 뒤, 이 제품의 성분(`productCautionIngredients`)이 650ms 뒤부터 180ms 간격으로 하나씩 커지며 나타납니다. 박스는 `clip-path`로 드러내 카드 크기와 위치를 유지하며, 기존 성분 등장·종료 시각은 바꾸지 않습니다. 움직임 줄이기에서는 한 번에 표시합니다. 후보 목록에 잠시 표시했다 옮기지 않으며, 제목도 ‘잘 맞은 제품의 성분’으로 표시합니다.
- 미리보기는 대화 상자 밖이라 낭독되지 않으므로, 같은 내용을 시트 안의 상태 문구(`role=status`)로 알립니다. 움직임 줄이기에서는 움직임 없이 바뀐 결과만 보입니다. 짧은 화면이나 큰 글자 때문에 카드 전체가 들어가지 않으면 미리보기를 숨겨 잘린 내용을 표시하지 않습니다.

### 제품 추가(`/shelf/add`)

- 자동완성에서 [추가]를 고르면 아직 담지 않고 평가 시트만 엽니다(S52i). '지금 쓰고 있나요?'는 필수라 '네'를 미리 골라 둡니다.
- 시트에서 [나중에] · [다음] · [평가 저장]을 눌러야 담깁니다. 고른 사용 상태와 1단계 답을 함께 보내 한 번에 담고, 2단계의 사용감은 담은 제품의 평가로 고칩니다. 담은 행은 '선반에 있음'이 됩니다.
- 시트를 그냥 닫으면(딤 · 끌어 내리기 · Esc) 담기를 취소한 것으로 보고, 행은 [추가]로 남깁니다.
- [나중에]로 담으면 '선반에 저장했어요. 평가는 선반에서 언제든 할 수 있어요' 토스트에 [되돌리기]를 둡니다(S52j). 되돌리면 담은 제품을 뺍니다.
- 담기 전에 단계 수를 정할 수 있도록, 선반 자동완성 응답에 사용감 평가 여부(`sensorySupported`)가 들어 있습니다.
- 담지 못하면 토스트로 알립니다. 자동완성을 받지 못하면 목록 자리에 섹션 오류(`ErrorState` section)와 [다시 시도]를 둡니다.
- 등록 요청 시트(S53h)는 머리에 뒤로와 제목을 둡니다. 브랜드와 제품명은 둘 다 필수입니다. 빈 칸이 있으면 [요청 보내기]를 막습니다. 칸 라벨이 무엇을 채울지 이미 말해 주므로 막힌 이유 문구는 두지 않습니다. 보내면 시트를 닫고 토스트로 알립니다. 보내지 못하면 제품명 칸 아래에 오류를 둡니다.
- 등록 요청 줄은 하단 행동 영역이 아니라 자동완성 목록의 마지막 줄입니다(S52h). 결과가 없으면 결과 없음 안내의 [제품 등록 요청하기]가 같은 일을 합니다(S52h-1). 그래서 `BottomActionBar`로 바꾸지 않습니다.

### 검색에서 제외할 성분 고르기(`/shelf/filter`)

- 불러오는 중에는 제목과 성분 행 자리에 스켈레톤을, 실패하면 화면 오류와 [다시 시도]를 둡니다. 10초가 지나도 오지 않으면 스켈레톤 위에 '시간이 조금 걸리고 있어요'와 [다시 시도]를 함께 보이고, [다시 시도]를 누르면 다시 요청합니다(FEEDBACK F02).
- 아래 버튼은 하단 행동 영역(`BottomActionBar`, 화면 끝)입니다. 고른 성분이 없으면 버튼을 막고 이유를 안내 줄에 적습니다.
- 성분별 행은 한 번만 두고, 제품 수와 함께 서버가 제공한 선정 근거 이름을 보여 줍니다. 여러 분류에 속해도 선택과 전송 ID는 중복하지 않습니다.
- 넣으면 선반으로 돌아가 토스트를 띄웁니다. 처음 넣으면 '성분 N개를 나만의 필터에 넣었어요'(S53e), 이미 제외 중인 성분이 있었으면 '성분 N개를 나만의 필터에 더 넣었어요'(S53k)입니다. 명세의 두 프레임 모두 [되돌리기]가 없어서 행동 버튼을 두지 않습니다. 넣은 성분은 나만의 필터에서 뺄 수 있습니다.
- 넣지 못하면 토스트로 알리고 화면에 남습니다.

### 소개 페이지(`/shelf/guide`)

- 하위 상단 내비와 하단 행동 영역(화면 끝) '제품 추가하러 가기'를 둡니다.

### 접근성

- 시트는 패키지 `BottomSheet`·`ConfirmSheet`가 포커스 가두기, Esc·딤·끌어내리기 닫기, 연 요소로 포커스 돌려주기를 맡습니다(A11Y D02).
- 제품 메뉴와 평가 시트의 머리는 제품 썸네일을 함께 보여 주므로, 시트 제목(`h2`) 안에 썸네일과 제품 이름을 함께 둡니다. 썸네일 그림은 낭독에서 뺍니다.
- 토스트의 [되돌리기]를 누른 뒤에는 포커스를 원래 컨트롤로 돌려줍니다. 컨트롤이 사라졌으면 제품 목록 영역으로 돌려줍니다(A11Y D10).
- 아이콘 버튼은 대상이 드러나는 이름을 씁니다. 예: '선반 기능 설명', '제품 추가', '{제품명} 메뉴'.

### 반응형

- 320·360·390 폭에서 가로로 넘치지 않아야 합니다. 글자를 200%로 키워도 제목과 버튼 글자가 잘리지 않아야 합니다.

## 바꿀 옛 부품

| 옛 부품                           | 쓸 디자인 시스템 부품                                           |
| --------------------------------- | --------------------------------------------------------------- |
| `components/ui/TopBar` (root·sub) | `TopBar`(`large`), 하위 화면은 `SubTopBar` + `Screen`(document) |
| `components/ui/StickyBar`         | `ScreenStickyRow`. 붙었는지는 패키지 표식으로 판단합니다(#1025) |
| `components/ui/BottomSheet`       | `BottomSheet` + `BottomSheetHeader`·`Body`·`Footer`             |
| 빼기 확인에 쓴 `BottomSheet`      | `ConfirmSheet`                                                  |
| `components/ui/icons/Icon`        | `Icon`. 없던 그림은 패키지에 더했습니다(아래 참고)              |
| 직접 그린 하단 고정 버튼          | `BottomActionBar`(screen-end)                                   |
| 문구만 있던 불러오기 실패         | `ErrorState`(screen·section)                                    |
| 빈 본문으로 둔 불러오는 중        | `Skeleton` + `useDelayedFlag`                                   |
| 버튼 위 실패 문구와 미뤄 둔 알림  | `useToast`(앱 레이아웃의 `ToastProvider`)                       |

옛 `Icon`에만 있던 그림은 패키지 `Icon`에 더했습니다(#1025). `eraser`와 `zoom-exclamation`은 Tabler 원본을 옮겼습니다. 주의 표지(옛 `flask-solid`)는 Tabler에 없는 명세 그림이라 `flask-conical`의 채움 그림으로 넣고 `filled`로 그립니다.

토스트는 앱에 하나만 둡니다. 루트 레이아웃이 `ToastProvider`로 본문을 감쌉니다. 띄우는 높이(`--toast-offset`)는 `globals.css`가 화면 아래에 붙은 영역을 보고 CSS의 `:has()`로 정합니다. [되돌리기]는 자리가 있으면 문장 옆에 두고, 문장이 좁아지면 문장 아래로 내립니다(디자인 시스템 `Toast`). 문장 옆에 두었을 때 앞 12글자(더 짧으면 문장 전체)가 한 줄에 들어가지 않거나 문장이 두 줄에 담기지 않으면 좁아진 것으로 봅니다. 이 기준은 실제 글자 폭으로 판단하며, 안드로이드 WebView에서 글자 크기를 키워도 그대로 맞습니다.

| 화면 아래에 붙은 영역                            | `--toast-offset`                       |
| ------------------------------------------------ | -------------------------------------- |
| 하단 내비(`[data-bottom-navigation]`)            | `--bottom-navigation-height`           |
| 하단 행동 영역(`[data-toast-offset=action-bar]`) | 81px(선 1 + 위 12 + 버튼 56 + 아래 12) |
| 없음                                             | 0                                      |

### 남는 것

- 등록 요청 시트의 전성분 사진 첨부(S53h)는 서버의 등록 요청 API가 사진을 받지 않아 넣지 않습니다.

## PostHog 이벤트

이슈 #968부터 선반·추가·성분 선택·가이드와 나만의 필터 화면에도 `page_viewed`를 보냅니다.
유입·로그인 전환·담기·평가·성분 분석·필터 반영·개인화 재사용의 이벤트와 퍼널은
[선반 분석 계약](../../lib/analytics/shelf.md)을 따릅니다(`analytics_schema_version=4`).

| 이벤트              | 언제 보내나                                                       | 속성                                             | 이번 변경        |
| ------------------- | ----------------------------------------------------------------- | ------------------------------------------------ | ---------------- |
| `$pageview`         | 선반 경로에 들어올 때(PostHog `capture_pageview: history_change`) | PostHog 기본 속성                                | 없음             |
| `$pageleave`        | 선반 경로를 떠날 때                                               | PostHog 기본 속성                                | 없음             |
| `product_viewed`    | 선반 제품 행에서 제품 상세로 들어왔을 때                          | `product_id`, `entry_point: "shelf"`, `category` | 없음             |
| `ingredient_viewed` | 선반의 성분 칩에서 성분 설명으로 들어왔을 때                      | `ingredient_id`, `entry_point: "shelf"`          | **새 진입점 값** |

- `ingredient_viewed`의 `entry_point`에 `shelf`를 더합니다(`IngredientEntryPoint`, `TrackIngredientView`의 허용 목록). 값이 없으면 `product_detail`로 기록되어 선반에서 들어온 방문이 제품 상세에서 들어온 방문으로 섞이기 때문입니다.
- 이름과 기존 속성은 바꾸지 않습니다.
- 담기·평가·옮기기·빼기·되돌리기는 #968에서 성공한 API 응답을 기준으로 기록합니다. 되돌리기는 새 활용 전환과 구분합니다.
