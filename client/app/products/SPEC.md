## 요구사항

### 화면 구성

위에서부터 상단 내비(하위), 필터 칩 줄, 적용된 조건 줄, 결과 수, 상품 목록 카드, 더 불러오기 상태 순서로 놓습니다. 필터 칩 줄은 상단 내비 아래에 붙습니다.

- **필터 칩 줄**: 성분 → 카테고리 → 브랜드 → 유수분 → 피부 타입 순서를 고정하고 가로로 스크롤합니다. 값이 걸린 칩은 이름 자리에 값을 바로 씁니다.
  - 성분: `성분 N`(N은 담은 성분과 성분군의 수)
  - 카테고리: 대분류 전체를 골랐으면 대분류 이름, 소분류를 골랐으면 소분류 이름
  - 브랜드: 1개면 브랜드명, 여러 개면 `닥터지 외 2개`
  - 유수분: `수분감 보통~높음`, 둘 다 걸렸으면 `수분감 보통~높음 외 1개`
  - 피부 타입: `건성`, 여러 개면 `건성 외 1개`
- **적용된 조건 줄**: 포함 줄과 제외 줄을 세로로 쌓고, 칩은 `Tag`(`summary`)로 그립니다. 줄마다 한 줄로 고정하고, 넘친 칩은 숨긴 뒤 줄 끝에 `외 N개`로 셉니다. 비어 있는 줄은 숨기고, 두 줄이 모두 비면 전체를 숨깁니다. 누르는 동작은 없습니다.
- **결과 수와 정렬**: 왼쪽에 `총 N개`, 오른쪽에 정렬 버튼을 둡니다. 누르면 버튼 바로 아래에 정렬 드롭다운(명세 `APP · 드롭다운`)이 열리고, 고르면 바로 닫히며 주소의 `sort`를 바꿔 첫 장부터 다시 부릅니다. 드롭다운은 브라우저 popover와 CSS 앵커 위치로 열어 크기를 재지 않고, Esc나 바깥을 누르면 닫혀 포커스가 버튼으로 돌아옵니다. 선반만 정렬 없이 최근 등록순으로 보여 줍니다.
- **상품 목록 카드**: 카드 전체가 제품 상세로 가는 링크입니다. hover(마우스 기기)와 눌림은 화면 끝에서 끝까지 `ui-hover` 면을 깔고, 구분선과 글자는 그대로 둡니다. 면은 가상 요소로 그려 레이아웃 크기와 주변 배치를 바꾸지 않습니다.

### 필터 초기화 버튼

칩 줄 맨 앞에 `FilterResetChip`(명세 APP · 필터 초기화 버튼)을 둡니다. 칩이 넘치면 줄 끝은 가로로 밀어야 보이므로 앞에 둡니다. 값이 걸린 칩이 없으면 숨기지 않고 막습니다. 숨기면 조건을 걸고 지울 때마다 칩들이 버튼 폭만큼 옆으로 밀리기 때문입니다.

- 누르면 값이 걸린 칩의 조건(성분·카테고리·브랜드·유수분·피부 타입)을 한 번에 비웁니다. 시트를 거치지 않고 바로 주소에 반영합니다.
- 검색어와 정렬은 남깁니다. 화면이 고정한 조건(카테고리 상품의 카테고리, 브랜드 상세의 브랜드)도 칩이 아니므로 남습니다.
- 누른 뒤에는 버튼이 막혀 포커스를 잃으므로 포커스를 첫 칩으로 옮깁니다.

### 나만의 필터 칩 (#955)

초기화 버튼 바로 뒤, 시트를 여는 칩보다 앞에 `FilterToggleChip`(명세 APP · 필터 토글 칩)을 둡니다. 시트를 열지 않고 바로 켜고 끄며, 켜면 분홍 계열 면이 됩니다. 로그인 여부와 상관없이 보여 줍니다.

| 상태                    | 칩을 눌렀을 때                                                                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 로그인 전               | '로그인하고 나만의 필터를 쓸까요?' 시트(`ConfirmSheet`)를 띄웁니다. [로그인]을 누르면 설정을 켬으로 남기고, 지금 주소를 돌아올 곳으로 남긴 뒤 `/login`으로 갑니다               |
| 필터가 비어 있음        | '나만의 필터에 넣은 성분이 하나도 없어요' 시트를 띄우고 칩은 켜지 않습니다. 켜도 결과가 바뀌지 않으므로, 기능이 궁금해서 누른 사람을 성분을 찾는 선반으로 보냅니다([선반 보기]) |
| 성분 있음               | 바로 켜고 끕니다                                                                                                                                                                |
| 관리자 세션 · 읽기 실패 | 칩을 숨깁니다                                                                                                                                                                   |

- 켬·끔은 주소가 아니라 설정 쿠키 `poudy-my-filter`에 둡니다. 기본은 켬입니다. 주소를 공유해도 받는 사람은 자기 설정대로 봅니다.
- 이번 요청에 적용하는 것은 설정이 켬이고 로그인했을 때입니다.
  - 서버 컴포넌트(`page.tsx`): 설정 쿠키와 세션 쿠키를 읽어 정하고, 적용하면 세션을 실어 캐시 없이 첫 장을 받습니다. 설정 값과 적용 여부를 `ProductList`에 넘깁니다.
  - 클라이언트 컴포넌트(`ProductList`): 회원 상태를 읽기 전에는 서버가 넘긴 값을 써서 첫 장을 그대로 잇습니다. 읽은 뒤에는 같은 규칙으로 정합니다. 목록이 401을 받으면 이번 화면에서만 적용하지 않고 설정은 그대로 둡니다.
- 설정이 켬이어도 로그인 전이거나 필터가 비어 있으면 칩을 끈 모양으로 그립니다. 적용할 성분이 없기 때문입니다. 회원 상태를 읽는 동안에는 서버가 정한 적용 여부로 그려 칩이 깜빡이지 않게 합니다.
- 칩으로 끄거나 다시 켜면 설정 쿠키를 바꾸고 목록을 다시 받습니다. 성분 탭(S22)과 같은 설정을 씁니다.
- 초기화 버튼은 나만의 필터를 끄지 않습니다. 성분 조건이 아니라 회원의 설정이기 때문입니다.
- pen의 주석은 로그인 전과 필터가 비었을 때 이 칩을 숨긴다고 적었지만, 기능을 알리려고 보여 주기로 바꿨습니다.

### 필터 시트

시트는 디자인 시스템의 `BottomSheet`로 그립니다. 시트 안의 선택은 초안으로 두고 결과 수만 미리 조회합니다. [N개 제품 보기]를 눌러야 주소에 반영하고, 닫거나 끌어내리면 초안을 버립니다. 비울 것이 없으면 [초기화]를 막습니다.

| 시트      | 구성                                                                                                                                                                                                                                  |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 성분      | 원하는 성분, 피하고 싶은 성분(`Tag` `item`과 [+ 추가]), 자주 피하는 성분(`ToggleChip`)과 설명(ⓘ). [+ 추가]는 시트 안 검색 화면으로 넘어갑니다. 검색 결과는 탐색 조건의 성분 추가 화면(S33)처럼 '성분군 N', '성분 N' 묶음으로 나눕니다 |
| 카테고리  | 대분류마다 `Disclosure` 머리 행을 두고 펼치면 `RadioGroup`(`list`)으로 하나를 고릅니다. 펼침은 `DisclosureGroup`(`single`)이 맡습니다                                                                                                 |
| 브랜드    | `SearchField`로 좁히고 `CheckboxGroup`으로 여러 개를 고릅니다                                                                                                                                                                         |
| 유수분    | 수분감과 유분감마다 `RangeSlider`와 '상관없음' `ToggleChip`(`sm`)을 둡니다                                                                                                                                                            |
| 피부 타입 | 건성·지성·복합성·민감성을 `CheckboxGroup`으로 여러 개 고릅니다. 고른 타입 가운데 하나에 맞는 제품을 찾습니다                                                                                                                          |

#### 피부 타입 후보와 빈 상태 (#826 · #831 · #832)

- 건성·지성·복합성·민감성은 한 그룹이며 OR로 검색합니다. 검색어·브랜드·카테고리 등 다른 조건은 AND로 유지합니다.
- 일반 타입은 `filterOptions.skinTypes`, 민감성은 `filterOptions.sensitiveSkin`이 참일 때만 선택지로 표시합니다.
  서버는 이 두 후보를 구할 때 피부 타입과 민감성 조건을 모두 제외합니다.
- 후보가 없으면 빈 체크 목록 대신 '지금 조건에서 고를 수 있는 피부 타입이 없어요.'를 표시합니다.
  브랜드 시트의 빈 상태와 같은 본문 글자·보조색·가운데 정렬·위아래 여백을 사용합니다.
  중간 페이지로 바로 들어와 후보 응답을 받지 못했다면 빈 상태 대신 첫 페이지 이동 링크를 표시합니다.
- 이미 고른 타입이나 민감성이 후보에서 빠지면 '지금 후보에 없는 선택' 영역에 해제 태그를 둡니다.
  다른 후보를 고르거나 해제해도 이 값은 자동으로 지우지 않습니다.
- 다중 타입은 `skinType`을 반복하고, 민감성은 `sensitiveSkin=true`로 함께 보냅니다.
  시트의 예상 개수와 적용 후 목록은 같은 조건을 사용합니다.

#### 성분 조건 충돌 (S33a · S35a)

원하는 성분과 피하고 싶은 성분이 부딪혀 결과가 반드시 비는 조합은 묻지 않고 바로 정리합니다. 시트 안의 변경은 [N개 제품 보기]를 누르기 전까지 확정되지 않으므로, 확인 시트를 한 겹 더 띄우지 않고 `Notice`(안내 줄)와 [되돌리기]로 알립니다. 탐색 조건의 성분 탭(#735)도 같은 규칙을 씁니다.

| 상황                                                       | 정리                                            | 안내 줄의 자리와 문구                                                               |
| ---------------------------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------- |
| 자주 피하는 성분을 켰는데 원하는 성분이 그 안에 있음(S35a) | 켜고, 그 성분을 원하는 성분에서 뺍니다          | 시트 머리 아래. '리모넨은 ‘향료/알레르기 성분’에 들어 있어 원하는 성분에서 뺐어요.' |
| 반대쪽에 담긴 성분이나 성분군을 검색 화면에서 담음(S33a)   | 반대쪽에서 빼고 지금 고르는 쪽에 담습니다       | 검색 입력 아래. '판테놀을 원하는 성분에서 빼고 피하고 싶은 성분에 담았어요.'        |
| 원하는 성분으로 담는 성분이 피하는 성분군에 들어 있음      | 그 성분군 피하기를 풀고 담습니다                | 검색 입력 아래. '글라이콜릭애씨드를 담으려고 ‘AHA 성분군’ 피하기를 풀었어요.'       |
| 피하고 싶은 성분으로 담는 성분군에 원하는 성분이 들어 있음 | 성분군을 담고, 그 성분을 원하는 성분에서 뺍니다 | 검색 입력 아래. S35a와 같은 문구입니다                                              |

- [되돌리기]는 정리하기 바로 전 상태로 돌려놓습니다. 안내 줄은 다음 편집, 단계 이동, 시트 닫기 전까지 남고 ✕로도 닫을 수 있습니다.
- 안내 줄은 `Notice`가 polite로 한 번 알립니다. 초점은 누른 칩이나 담기 버튼에 그대로 두고, [되돌리기]를 누르면 그 칩이나 버튼으로 돌려줍니다.
- 검색 화면은 더 이상 반대쪽에 담긴 성분을 '○○에 있음'으로 막지 않습니다. 성분군으로 이미 담긴 성분만 회색 ✓로 둡니다.
- 안내 줄을 띄울 때 `filter_conflict_shown`을 보냅니다.

### 접근성

- 필터 초기화 버튼은 아이콘만 보이므로 이름을 '필터 조건 모두 초기화'로 읽습니다.
- 필터 칩은 `button` + `aria-haspopup="dialog"` + `aria-expanded`이고, 접근 가능한 이름은 `성분, 성분 5`처럼 조건 이름과 값을 함께 읽습니다.
- 적용된 조건 줄은 `role="group"`과 이름 '적용된 조건'을 갖고, 숨기거나 말줄임한 칩도 모두 읽습니다. `외 N개`는 화면에만 보입니다.
- 빈 상태와 결과 영역은 `aria-live="polite"`로 한 번 알립니다. 목록은 다음 장을 받는 동안 `aria-busy`를 겁니다.
- 카드의 사진은 대체 텍스트를 비웁니다. 제품명이 옆에 있기 때문입니다.

### 반응형

- 320·360·390 폭에서 가로로 넘치지 않습니다. 거터는 `--gutter`(360 미만 12, 그 이상 16)를 따릅니다.
- 글자를 200%로 키워도 칩 줄은 가로 스크롤로, 적용된 조건 줄은 `외 N개`로, 카드는 줄바꿈으로 버팁니다.

## 라우팅과 파라미터

`/products` 하나입니다. 조건은 모두 주소가 들고, 화면은 주소에서 매번 읽습니다. `lib/domain/filter.ts`의 `parseFilter`와 `serializeFilter`가 읽고 씁니다.

| 파라미터                                                 | 담는 값                                                                          |
| -------------------------------------------------------- | -------------------------------------------------------------------------------- |
| `keyword`                                                | 제품명 검색어                                                                    |
| `categoryIds`, `brandIds`                                | 카테고리와 브랜드 ID                                                             |
| `moistureLevel`, `oilLevel`                              | 수분감과 유분감 단계(0~3)                                                        |
| `includeIngredientIds`, `excludeIngredientIds`           | 원하는 성분과 피하고 싶은 성분                                                   |
| `excludeCodes`, `includeGroupCodes`, `excludeGroupCodes` | 자주 피하는 성분과 성분군                                                        |
| `skinType`(되풀이), `sensitiveSkin`                      | 피부 타입(여러 개), 민감성                                                       |
| `sort`, `page`, `size`                                   | 정렬(헤더의 정렬 드롭다운에서 고름), 장 번호, 장 크기                            |
| `from`                                                   | 기존 URL 호환용 진입 경로. 새 링크는 세션에 저장(`popular_keyword`, `skin_type`) |
