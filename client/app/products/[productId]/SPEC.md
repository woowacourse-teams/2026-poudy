# 제품 상세 디자인 시스템 적용 계획

- 이슈: [#731 \[FEAT\] 제품 상세에 디자인 시스템을 적용한다](https://github.com/woowacourse-teams/2026-poudy/issues/731) (상위 이슈 #722 · 단계 2-1)
- 브랜치: `feat/731-product-detail-ds`
- 디자인: `client/design/poudy-ui.pen`의 S24·S39 계열 프레임

S24 개편(분류 경로, 물방울 단계 이름, 주의 성분 확인 등)은 #788에서 이미 반영했습니다. 이번 작업에서는 화면 구성은 그대로 두고, client의 옛 부품을 디자인 시스템 부품으로 바꾸고 직접 적은 값을 토큰으로 옮깁니다. 이와 함께 명세에 새로 들어온 세 가지를 구현합니다.

- 스크롤한 뒤에는 상단 내비 제목 자리에 제품 사진과 이름을 보이고, 저장 버튼을 하단에 고정합니다(S24-1).
- 제품 저장을 '위시리스트에 담기'와 '선반에 저장'으로 나눕니다(S39f~S39k).
- 구성품 탭이 넘치면 [전체 보기]로 구성품 칩을 펼칩니다(S39c-1·S39c-5·S39c-8).

## 라우팅과 파라미터

| 경로                             | 파라미터                       | 쓰는 곳                                                         |
| -------------------------------- | ------------------------------ | --------------------------------------------------------------- |
| `/products/[productId]`          | `partId`(구성품), `from`(유입) | `partId`는 구성품 탭과 칩이, `from`은 `product_viewed`가 읽는다 |
| `/products/[productId]/markdown` | 없음                           | 마크다운 대체본. 바꾸지 않는다                                  |

- 경로와 파라미터 이름은 바꾸지 않습니다. 이슈 본문의 `?part=`는 지금 쓰는 `partId`를 가리킵니다.
- 구성품 탭과 칩은 `partId`를 붙인 링크(`replace`, `scroll={false}`, `prefetch`)이고, `from`을 이어 붙여 조회 이벤트가 다시 나가지 않게 합니다.
- `revalidate = 86400`은 그대로 두고, `searchParams`를 읽어 요청마다 렌더링하는 지금 방식도 유지합니다.

## 요구사항

### 화면 골격

- `Screen`(`document`) 안에 `TopBar`(`sub`)를 두고 본문을 문서 전체로 스크롤합니다. 하단 내비는 지금처럼 앱 레이아웃이 붙입니다.
- `TopBar`의 제목은 '제품 상세'이고 문서 제목은 본문의 제품명(h1)이 맡으므로 `titleAs="p"`로 둡니다. 오른쪽 행동은 공유(`share` 아이콘, 이름 '제품 공유') 하나입니다.
- 뒤로가기는 사이트 안 방문 기록이 있으면 이전 화면으로, 없으면 '홈으로' 링크로 바꿉니다.
- 공유가 주소 복사로 끝나면 토스트로 '주소를 복사했어요'를 알립니다. 앱 레이아웃에 `ToastProvider`를 붙입니다.

### 스크롤 후 제품 요약과 하단 행동 바(S24-1)

- 본문의 제품명이 상단 내비 아래로 지나가면 내비 제목 자리를 제품 사진(28)과 제품명으로 바꿉니다. 되돌아오면 다시 '제품 상세'를 보입니다. 바꿀 때는 겹쳐 보이며 바뀌고(fast), 움직임 줄이기에서는 불투명도만 바꿉니다.
- 본문의 저장 버튼 묶음이 상단 내비 아래로 지나가면 같은 버튼 묶음을 하단에 고정해 보입니다. 하단 내비 바로 위에 붙고, 숨어 있는 동안에는 포커스를 받지 않습니다(`inert`).
- 지나갔는지는 IntersectionObserver로 판단합니다. 스크롤 위치나 요소 위치를 읽지 않습니다.
- 지금의 별도 축약 머리(`CompactSummary`, 사진 40)는 지웁니다.

### 제품 저장(S39f~S39k)

| 상태        | 위시리스트 버튼(48, 회색 면)             | 선반 버튼(48, 폭 나머지)                     |
| ----------- | ---------------------------------------- | -------------------------------------------- |
| 로그인 전   | 누르면 로그인 안내 확인 시트(S39f)       | 누르면 로그인 안내 확인 시트(S39g)           |
| 담기 전     | 북마크 선, 누르면 위시리스트에 담는다    | '선반에 저장' + 보관함, 누르면 선반에 담는다 |
| 담은 뒤     | 분홍 면 + 북마크 채움(S39h), 누르면 뺀다 | 분홍 면 '선반에 저장됨'(S39i)                |
| 처리 중     | 다시 누를 수 없다(`aria-busy`)           | 다시 누를 수 없다(`aria-busy`)               |
| 관리자 세션 | 지금처럼 관리자 안내 창을 띄운다         | 같은 안내 창을 띄운다                        |

- 선반에 담으면 바로 평가 시트(S39j)를 엽니다. 시트는 선반 화면의 `ShelfRatingSheet`(`justAdded`)를 그대로 씁니다.
- '선반에 저장됨'을 누르면 빼기 확인 시트(S39k)를 엽니다. 제목은 '{제품명}{을/를} 선반에서 뺄까요?', 실행은 '빼기'(destructive)입니다.
- 로그인 안내 시트의 '로그인'은 돌아올 주소를 기억하고 로그인 화면으로 보냅니다.
- 선반 상태를 받아 오지 못하면 버튼은 '선반에 저장'으로 두고, 누를 때 다시 시도합니다. 실패하면 토스트로 알립니다.

### 구성품 탭과 칩 흐름(S39b·S39c)

- 구성품이 둘 이상이면 `Tabs`(밑줄)로 그립니다. 탭은 `Link`(`asChild`)이고 순서(01, 02 …)와 이름, 주의 상태 아이콘을 담습니다. 방향키와 Home/End로 옮깁니다.
- 탭이 다 들어가면 폭을 똑같이 나누고, 넘치면 내용 폭대로 두고 가로로 밉니다. 이 판단은 CSS(`flex-1 basis-0 min-w-max`)가 맡습니다.
- 넘칠 때만 오른쪽 끝에 44×48 크기의 [전체 보기 ⌄] 버튼을 둡니다. 넘치는지는 첫 탭과 마지막 탭을 IntersectionObserver로 지켜봐서 압니다.
- [전체 보기]를 누르면 탭 줄 자리에 '구성품 N개 · 주의 M개' 머리줄과 구성품 칩(높이 36, 칩 사이·줄 사이 8)을 펼칩니다. 최대 5줄까지 보이고 그 안에서 스크롤합니다. 아래에는 페이드를 둡니다.
- 칩을 고르지 않고 닫으면(접기, Esc, 바깥 누르기) 아무것도 바꾸지 않습니다. 칩을 고르면 주소의 `partId`를 바꾸고, 목록을 닫고, 고른 탭이 보이게 탭 바를 밀고, 패널 시작점으로 스크롤합니다.
- 탭이 위에 붙은 채로 탭을 바꿔도 패널 시작점으로 스크롤합니다.

### 성분 시트(S24a·S24b)

- `BottomSheet` + `BottomSheetHeader`(제목, 영문명, ✕) + `BottomSheetBody`로 바꿉니다. 피부 작용 태그는 본문 맨 위에 둡니다.
- 성분군 시트는 '이 제품에 든 성분 N종' 목록을 두고, 발에는 '{이름} 성분군 자세히 보기' 링크를 둡니다.
- 설명을 받는 동안에는 `Skeleton` 두 줄을, 받지 못하면 '설명을 불러오지 못했어요.'를 보입니다.

### 상태

| 상태    | 동작                                                                                   |
| ------- | -------------------------------------------------------------------------------------- |
| 기본    | 서버가 제품 상세, 비슷한 제품, 주의 성분군 목록을 함께 받아 그린다                     |
| 로딩    | 서버 렌더링이라 화면 단위 로딩은 없다. 시트의 설명만 열린 뒤에 받는다                  |
| 빈 상태 | 비슷한 제품·주의 성분·쓰임새가 없으면 그 섹션을 그리지 않는다                          |
| 오류    | 없는 제품이나 구성품은 404. 비슷한 제품과 주의 성분군을 받지 못하면 빈 목록으로 그린다 |

### 접근성과 반응형

- 포커스 링은 패키지의 `pressable`·`data-focus-ring`을 따릅니다. 아이콘 버튼은 모두 이름을 가집니다('위시리스트에 담기', '위시리스트에서 빼기', '구성품 전체 보기', '구성품 목록 접기', '제품 공유').
- 구성품 탭의 이름에는 '주의 성분 있음/없음'을 붙입니다. [전체 보기]는 `aria-expanded`와 `aria-controls`를 가집니다.
- 320·360·390 폭에서 가로로 넘치지 않고, 기기 글자 크기 0.85~2.0배에서 글자가 갈라지거나 넘치지 않게 합니다.

디자인 시스템 패키지에서는 다음을 고칩니다.

- `TopBar`: `sub`의 제목 자리를 다른 내용으로 바꿔 보이는 `titleSwap`을 더합니다.
- `Tabs`: 다 들어가면 폭을 나누고 넘치면 미는 배치 `fit`을 더합니다.
- `Icon`: 정보 출처 머리에 쓰는 `shield-check`를 더합니다. 구성품의 주의 상태 아이콘은 지금처럼 client의 `CautionStatusIcon`을 씁니다.

## 정한 것

- 하단 행동 바는 하단 내비 위에 붙입니다. S24-1 그림에는 하단 내비가 없지만, 앱은 `/products`에 하단 내비를 두고 있어 그 위에 놓습니다.
- `BottomActionBar`는 큰 버튼(56) 하나만 받습니다. S24-1의 바는 아이콘 버튼(48)과 버튼(48)을 함께 두므로, 같은 모양(윗선·흰 바탕·거터·위 12)을 client의 `ProductSaveActions`가 그립니다.
- 스켈레톤(S50b)은 두지 않습니다. 같은 경로에서 `partId`만 바꾸는 탭 이동에도 `loading.tsx`가 걸려 탭을 바꿀 때마다 화면 전체가 스켈레톤으로 깜빡입니다.
- S39a의 옵션 색상 줄과 S39e의 제조·판매 정보(CGMP)는 응답에 데이터가 없어 이번 범위에서 뺍니다.
