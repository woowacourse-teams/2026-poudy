## 화면 형식

한 화면에 필요한 항목을 모두 펼쳐 두고 마지막에 한 번 제출하는 게시판 형식을 유지합니다. 채팅처럼 나눠 보내게 만들면 이어서 쓰려던 내용을 잃고, `content`의 최소 길이인 10자에 걸려 거절당하기도 합니다.

## 요구사항

### 작성 화면(S40 · S40a · S40b · S40g)

| 상태             | 동작                                                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 유형을 고르기 전 | 제목 `무엇을 도와드릴까요?`와 유형 네 개, 그 아래 안내 줄 `문의 유형을 고르면 입력할 항목이 나타나요.`를 보여 줍니다. 제출 버튼은 막혀 있습니다  |
| 필수 입력 전     | 제출 버튼을 막습니다. 버튼 위에 이유는 적지 않고, 손대지 않은 빈 칸에는 오류를 띄우지 않습니다                                                   |
| 입력 오류        | 칸을 벗어날 때 검사하고, 한 번 오류가 난 칸은 입력할 때마다 다시 검사합니다(`FieldRule`, FEEDBACK F06). 오류 문구는 칸 아래 안내 자리에 놓습니다 |
| 사진 올리는 중   | 사진 위에 진행 표시를 두고 상태 줄에 올리는 중임을 적습니다. 다 올릴 때까지 제출 버튼을 막고, 올리는 중인 사진은 ✕로 업로드를 취소합니다         |
| 사진 올리기 실패 | 사진에 빨간 테두리와 다시 시도 배지를 두고, 상태 줄 자리에 실패 문구를 보여 줍니다. 사진을 누르면 다시 올립니다                                  |
| 보내는 중        | 제출 버튼이 처리 중 상태가 되어 다시 누를 수 없습니다. 입력과 유형도 바꿀 수 없습니다                                                            |
| 보내기 실패      | 적은 내용을 지우지 않습니다. 버튼 위 안내 줄 자리에 이유를 적고 낭독기에 바로 알립니다. 서버가 400으로 거절하면 내용 칸의 오류로 보여 줍니다     |
| 보내기 성공      | 접수 완료(S40c)로 바꿉니다                                                                                                                       |

- 유형을 바꾸면 앞서 적은 내용과 첨부한 사진을 비웁니다. 오류 신고에 적던 글이 다른 유형으로 접수되지 않게 하려는 것입니다.
- 화면 안에서 유형을 골라도 주소는 바뀌지 않습니다.

### 버튼 위 안내 줄

필수 입력이 비었거나 사진을 올리는 중이라 보낼 수 없을 때도 버튼 위에 이유를 적지 않습니다(2026-10-22 결정). 내용이 짧은 것은 내용 칸의 오류로, 사진 상태는 사진 상태 줄로 그 자리에서 알립니다. 버튼 위 안내 줄은 보내기에 실패했을 때만 실패 이유(아래 `오류 문구`)를 적습니다.

### 사진 첨부

디자인 시스템 `ImageAttachment`를 씁니다. 업로드 요청과 취소, 다시 시도는 화면(`useImageUpload`)이 맡습니다.

| 항목 | 값                                                           |
| ---- | ------------------------------------------------------------ |
| 형식 | JPG, PNG, HEIC(`image/jpeg,image/png,image/heic,image/heif`) |
| 장수 | 최대 5장(`imageIds` 최대 개수). 다 차면 추가 버튼을 막습니다 |
| 크기 | 장당 5MB 이하. 고르는 순간 검사하고 넘으면 올리지 않습니다   |

상태 줄은 같은 자리에서 문구만 바꿉니다.

| 상태           | 문구(명세 노드)                                                                   |
| -------------- | --------------------------------------------------------------------------------- |
| 기본           | `{n} / 5장 · 장당 5MB 이하 · JPG, PNG, HEIC` (`R969J`, `O7rfYX`)                  |
| 올리는 중      | `{올린 장수} / 5장 · {k}장 올리는 중 · 장당 5MB 이하` (`IAOoG`)                   |
| 올리기 실패    | `{k}장을 올리지 못했어요. 사진을 눌러 다시 시도해 주세요.` (`rgAam`, 빨간 아이콘) |
| 고른 파일 거절 | 형식이나 크기가 맞지 않는 까닭(`rejectionOf`, CONTENT W07 · IMAGE P04)            |

- 업로드 실패는 사진마다 표시하고, 전송 상태 문구는 정중하게(`aria-live="polite"`) 알립니다(A11Y D06).
- 사진을 지우면 포커스는 다음 사진, 앞 사진, 추가 버튼 순서로 옮겨 갑니다(부품이 맡습니다).
- 올리는 중이거나 올리지 못한 사진이 있으면 보낼 수 없습니다. `imageIds`가 빠진 채로 접수되지 않게 하려는 것입니다.
- 업로드를 취소하면 그 사진을 목록에서 뺍니다. 늦게 도착한 응답은 목록에 없는 사진이므로 무시합니다.

### 첨부 사진 전체 화면(S40d · S40f)

| 조작             | 버튼                              | 키보드                       | 제스처                  |
| ---------------- | --------------------------------- | ---------------------------- | ----------------------- |
| 이전 · 다음 사진 | 이전 · 다음(첫 · 마지막에서 숨김) | ← → (1배에서만)              | 좌우로 쓸기(1배에서만)  |
| 확대 · 축소      | + · − (1배 · 2배 · 3배)           | + · −                        | 두 번 누르기, 두 손가락 |
| 확대한 채 이동   | −로 1배 맞춤                      | ← → ↑ ↓, 보이는 영역의 10%씩 | 끌기                    |
| 닫기             | 닫기(✕)                           | Esc                          | 아래로 쓸기(1배에서만)  |
| 삭제             | 삭제 → 확인 시트(S40f)            | Enter                        | 없음                    |

- 방향키는 사진 영역(`tabindex=0`, 뷰어를 열면 처음 포커스를 받는 곳)에 포커스가 있을 때만 처리합니다(A11Y D03).
- 1배에서 −는 막고, 3배에서 +는 막습니다. 사진을 바꾸면 1배로 돌아갑니다.
- 확인 시트에서 삭제하면 다음 사진으로 넘어가고, 마지막 사진이었으면 뷰어를 닫고 첨부 목록으로 돌아갑니다.
- 조작 안내 `좌우로 넘기거나 버튼으로 옮기고, 확대할 수 있어요`는 뷰어를 연 뒤 처음 조작하기 전까지만 보여 줍니다.
- 브라우저가 그리지 못하는 사진(HEIC 등)은 `이 사진은 미리 보여 드릴 수 없어요. 첨부는 정상으로 됐어요.`라고 적습니다.

### 접수 완료(S40c)

- 제목 `문의를 접수했어요`, 설명 `보내 주신 내용을 꼼꼼히 확인하고 서비스에 반영할게요.`를 보여 줍니다. 반영 시점은 약속하지 않습니다.
- 접수 내용 요약에 문의 유형과 첨부 사진 장수를 적습니다. 사진을 받지 않는 유형(제품 등록 요청)은 사진 행을 두지 않습니다.
- 화면이 바뀌면 포커스를 완료 제목으로 옮겨 낭독기가 읽게 합니다(A11Y `문의 접수 완료`).
- 확인과 상단 닫기는 같은 동작입니다. `from`이 있으면 그 경로로, 없고 사이트 안의 방문 기록이 있으면 뒤로, 둘 다 없으면 홈으로 갑니다. 기록을 늘리지 않도록 `replace`를 씁니다.

### 접근성과 반응형

- 유형은 `RadioGroup`(`radiogroup`/`radio`)이라 Tab으로 들어가고 방향키로 옮깁니다.
- 입력 칸은 라벨과 이어지고, 필수 칸은 `aria-required`, 오류 칸은 `aria-invalid`와 `aria-describedby`로 문구를 잇습니다.
- 제출 버튼은 막혀 있어도 포커스를 받습니다(`aria-disabled`, STATE S06). 보내기에 실패하면 버튼 위 실패 이유를 버튼의 설명으로 읽습니다.
- 320 · 360 · 390 폭과 글자 200%에서 가로로 넘치지 않아야 합니다. 유형 버튼 두 칸, 정정 대상 제품명, 상태 줄은 줄을 바꿔 감쌉니다.
- 가상 키보드가 열리면 하단 행동 영역이 키보드 위로 올라갑니다(부품이 맡습니다).

## 라우팅과 파라미터

| 경로                            | 화면                            | 파일                                        |
| ------------------------------- | ------------------------------- | ------------------------------------------- |
| `/inquiry`                      | S40, S40a, S40b, S40g, S40c     | `app/inquiry/page.tsx`                      |
| `/inquiry?from=/products/123`   | 위와 같고 문의를 연 화면이 있음 | `app/inquiry/page.tsx`                      |
| `/inquiry/products/[productId]` | S40e, S40c                      | `app/inquiry/products/[productId]/page.tsx` |

| 파라미터    | 담는 값                                  | 없거나 틀릴 때                                                 |
| ----------- | ---------------------------------------- | -------------------------------------------------------------- |
| `from`      | 문의를 연 화면의 경로와 조건(최대 500자) | `path`를 보내지 않습니다. 우리 화면의 경로가 아니어도 같습니다 |
| `productId` | 정정 대상 제품 ID                        | 숫자가 아니거나 없는 제품이면 404입니다                        |

- `from`은 서버 컴포넌트가 `searchParams`로 읽어 화면에 넘깁니다(`toOriginPath`). `useSearchParams`를 쓰면 Suspense 경계가 필요합니다.
- 조건이 길어 500자를 넘으면 경로만 남기고, 조각 식별자(`#`)는 보내지 않습니다. 처리방침의 수집 항목과 맞물리므로 바꾸면 방침도 함께 고칩니다.
- 클라이언트 안에서는 `originPath`라고 부르고 보내기 직전에 서버 필드 `path`로 옮깁니다.
- 브랜드는 적지 않아도 되는 한 줄 입력(`TextField` `optional`)입니다. 브랜드 목록을 받아 고르게 하지 않습니다(2026-10-22 결정). 비우면 보내지 않습니다.

## 유형별 구성

| 유형           | 값                | 입력 항목            | 사진 | 엔드포인트                                           |
| -------------- | ----------------- | -------------------- | ---- | ---------------------------------------------------- |
| 오류 신고      | `BUG_REPORT`      | 문의 내용            | 선택 | `POST /api/feedbacks`                                |
| 개선 제안      | `IMPROVEMENT`     | 문의 내용            | 선택 | `POST /api/feedbacks`                                |
| 제품 등록 요청 | `PRODUCT_REQUEST` | 제품명, 브랜드(선택) | 없음 | `POST /api/products/registration-requests`           |
| 그 밖의 문의   | `OTHER`           | 문의 내용            | 선택 | `POST /api/feedbacks`                                |
| 제품 정보 정정 | 경로로 정해짐     | 제보 내용            | 선택 | `POST /api/products/{productId}/correction-requests` |

- 제품 정보 정정은 대상 제품이 정해져야 뜻이 서므로 `/inquiry`의 유형 목록에 두지 않습니다. 정정 화면에는 유형 버튼을 그리지 않고 제목 `제품 정보가 정확하지 않나요?`와 정정 대상 제품(`ProductImage` 48, 브랜드, 제품명)을 둡니다.
- 문의 내용 입력 칸의 안내 문구(placeholder)는 유형마다 다릅니다. `BUG_REPORT`는 S40g 문구를 씁니다.
- 자유 입력을 받는 화면에는 개인정보 안내 행(`개인정보는 빼고 보내 주세요`)을, 제품 등록 요청에는 등록 안내 행(`확인 후 제품 목록에 추가돼요`)을 둡니다.

### 입력 제약

| 항목      | 제약                                       | 근거                                     |
| --------- | ------------------------------------------ | ---------------------------------------- |
| 문의 내용 | 10자 이상 2,000자까지(앞뒤 공백은 빼고 셈) | `FeedbackRequest.content`                |
| 제품명    | 1자 이상 200자까지                         | `ProductRegistrationRequest.productName` |
| 브랜드    | 100자까지, 선택                            | `ProductRegistrationRequest.brandName`   |
| 사진      | 5장까지, 장당 5MB, JPG·PNG·HEIC            | `imageIds`, IMAGE P04                    |

### 오류 문구

| 상황                  | 문구                                             | 자리            |
| --------------------- | ------------------------------------------------ | --------------- |
| 보내기 429            | `요청이 잦아요. 잠시 후 다시 시도해 주세요.`     | 버튼 위 안내 줄 |
| 보내기 400            | `입력한 내용을 다시 확인해 주세요.`              | 내용(제품명) 칸 |
| 보내기 그 밖의 실패   | `접수하지 못했어요. 잠시 후 다시 시도해 주세요.` | 버튼 위 안내 줄 |
| 사진 업로드 413 · 429 | `uploadFailureMessage`의 문구                    | 사진 상태 줄    |

| ------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------- |
| `$pageview`         | 화면에 들어올 때(`AnalyticsProvider`가 자동으로 보냅니다)              | PostHog 기본 속성                                                                                                                                              | 그대로        |
| `error_occurred`    | 문의 · 정정 · 등록 요청 · 사진 업로드가 실패할 때(`lib/api/client.ts`) | `error_code`, `status`, `surface`(`/api/feedbacks`, `/api/products/:id/correction-requests`, `/api/products/registration-requests`, `/api/pending-images`)     | 그대로        |
| `inquiry_submitted` | 접수가 성공했을 때 한 번                                               | `inquiry_type`(`bug_report` · `improvement` · `other` · `product_registration` · `product_correction`), `image_count`, `has_origin_path`, `product_id`(정정만) | **새로 추가** |

`inquiry_submitted`는 어떤 유형의 문의가 얼마나 들어오는지, 사진을 얼마나 붙이는지 보려고 더합니다. 문의 내용과 제품명은 사용자가 적은 글이라 보내지 않습니다. 화면을 연 횟수는 `$pageview`로 셉니다.

## 명세와 다르게 구현한 곳

- **S40g · S40e 버튼 위 안내 줄:** 명세 그림은 막힌 제출 버튼 위에 이유(`문의 내용을 입력하면 접수할 수 있어요` 등)를 적지만, 2026-10-22 결정으로 두지 않습니다. 실패 이유만 그 자리에 적습니다.
- **S40b 제품 사진:** 등록 요청 API(`ProductRegistrationRequest`)에 사진을 받을 자리가 없어 그리지 않습니다. 받아 놓고 보내지 못하는 사진을 고르게 하지 않으려는 것입니다. 선반의 등록 요청 시트(S53h)도 같은 이유로 사진 칸을 비워 두었습니다.
- **S40c 상단 닫기:** 명세의 닫기 아이콘(`yTmax`)은 상태바 위(x 0, y 0)에 놓여 있고, 디자인 시스템 `TopBar`에는 왼쪽 닫기 변형이 없습니다. 하위 내비의 뒤로가기 칸을 `닫기`라는 이름으로 씁니다.
- **S40e 정정 대상 제품 사진:** 명세 그림은 회색 칸 없이 48 칸에 담깁니다. `ProductImage` 48(IMAGE P02)을 그대로 씁니다.

## 테스트

각 파일 옆에 `*.test.tsx`를 둡니다. 역할로 찾고 `userEvent`로 조작합니다.

- 유형을 고르기 전에는 입력 항목이 없고 제출할 수 없습니다.
- 유형을 고르면 해당 항목이 나타나고, 유형을 바꾸면 앞서 적은 내용이 비워집니다.
- 내용이 비어 있거나 10자보다 짧으면 제출할 수 없습니다. 버튼 위에 이유를 적지 않고, 짧은 내용은 칸을 벗어날 때 내용 칸의 오류로 알립니다.
- 제출하면 `type`, `content`, `path`, `imageIds`를 담아 보냅니다. `from`이 없거나 우리 화면의 경로가 아니면 `path`를 보내지 않습니다.
- 사진을 올리는 동안과 실패한 사진이 남아 있는 동안에는 제출할 수 없습니다. 실패한 사진을 누르면 다시 올립니다.
- 업로드를 취소하면 그 사진이 빠지고, 늦게 온 응답은 무시합니다.
- 상태 줄이 기본 · 올리는 중 · 실패 문구를 바꿔 보여 줍니다.
- 5MB를 넘거나 사진이 아닌 파일은 올리지 않고 그 자리에서 알립니다.
- 제품 등록 요청은 제품명과 적은 브랜드를 보내고, 브랜드 없이도 보낼 수 있습니다.
- 전체 화면에서 이전 · 다음, 확대 · 축소, Esc가 동작하고, 삭제는 확인 시트를 거칩니다.
- 정정 화면은 유형 버튼 없이 정정 대상 제품을 보여 주고 `POST /api/products/{id}/correction-requests`로 보냅니다.
- 접수가 성공하면 `inquiry_submitted`를 한 번 보내고 접수 완료 요약을 보여 줍니다. 실패하면 적은 내용이 남습니다.

## 법적 고지 문서와의 관계

| 문서     | 이 기능과 맞물리는 곳                                                                 |
| -------- | ------------------------------------------------------------------------------------- |
| 처리방침 | 문의 내용과 첨부 사진, 문의를 연 화면의 경로를 수집 항목으로 적었습니다               |
| 처리방침 | 첨부 형식을 JPEG·PNG·HEIC로 적고, 받은 파일을 JPEG나 PNG로 다시 저장한다고 밝혔습니다 |
| 이용약관 | 제7조 이용자 제출물에 권리 귀속과 삭제 근거를 두었습니다                              |

`path`에 조건까지 담는 방식은 처리방침의 `검색어와 선택한 조건이 주소에 담겨 있으면 함께 저장됩니다`와 맞물립니다. 이 규칙을 바꾸면 방침도 함께 고칩니다.
