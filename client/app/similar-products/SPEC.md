# 유사템 찾기

명세: `client/design/poudy-ui.pen` 구역 10(10-1 시작·내 파우치, 10-2 제품 고르기·검색, 10-3 결과, 10-4 로딩·오류). 2026-11-19에 시작 화면과 결과 화면을 다시 그렸다.
디자인 시스템의 Screen·TopBar·SearchField·Combobox·ToggleChip·Tag·EmptyState·ErrorState·Skeleton과 제품 이미지 규칙을 사용한다.

## 결과

- 경로: `/similar-products/[productId]?partId=구성품ID&sort=UNIT_PRICE_ASC|SIMILARITY`.
- 정렬을 생략하면 저렴한 순이다. 구성품을 생략하면 서버의 첫 구성품을 기준으로 한다.
- 기준 제품 판(S276): 사진 48, 세 줄이다. 표지 '기준 제품'(여러 구성품이면 '기준 제품 · 구성품명', 이름이 없으면 '02 구성품'처럼 순서), '브랜드 제품명' 한 줄 말줄임, '용량 · 가격'과 단가를 한 줄에 둔다. 가격이 없으면 '가격 정보 없음' 한 줄이다.
- 성분이 비슷한 상위 10개를 서버 정렬 그대로 표시한다. 섹션 머리는 '성분이 유사한 제품'과 실제 표시 개수(보조색)이고 더보기는 없다.
- 두 정렬은 행을 다르게 그린다. 둘 다 제품명('브랜드 제품명', 두 줄 말줄임)으로 시작한다.
  - 저렴한 순(S276): 둘째 줄은 '용량 · 가격', 셋째 줄은 가격 줄이다. 더 저렴하면 '15%'(success-text) · 'ml당 77원' · 취소선 기준 단가('90원'), 같거나 비싸거나 견줄 수 없으면 단가 뒤에 '단위 가격 동일' · '11% 비쌈' · '단위 가격 비교 불가'를 보조색으로 쓴다.
  - 성분 유사한 순(S277): 둘째 줄은 '겹치는 성분'과 성분군 태그(최대 2개), 셋째 줄은 '용량 · 가격'과 단가 · 차이(더 저렴하면 success-text 굵게)다.
- 가격 글자는 모두 12/700이다(T02 · T05). 비율은 정수로 쓰고, 소수점은 버린다. 단가가 없으면 '단위 가격 정보 없음'만 쓴다.
- 취소선 기준 단가는 응답에 없어 기준 제품 대표 용량으로 계산한다. 단위가 같은 행에만 쓴다.
- 겹치는 성분은 서버의 `sharedIngredientGroups`(기준 제품과 둘 다 있는 성분군, 글리세린 제외, 드문 순 0~2개)다. 생성 파일에 필드가 들어오기 전에도 받도록 `lib/api/products.ts`가 선택 필드로 덧붙인다. 필드가 없거나 비면 그 줄을 그리지 않는다.
- 주의 칩 '주의 있음'은 빠른 제외 성분(`containsExcludedIngredient`)이나 나만의 필터 성분(회원 정보의 `containsMyFilterIngredient`)이 든 행에만 제품명 줄 오른쪽에 붙인다. 회원 정보는 결과와 같은 개수·정렬로 받고, 받지 못해도 결과는 그대로 보여 준다. 걸리지 않은 행에는 '주의 없음'을 쓰지 않는다.
- 목록 끝에 각주를 둔다. 저렴한 순은 '성분이 비슷한 상위 10개 안에서 비교해요.', 성분 유사한 순은 '성분이 비슷한 상위 10개를 보여 줘요.'이고, 둘째 줄은 '가격은 대표 용량 기준이에요.'로 같다. 마지막 행 아래에도 구분선이 있다.
- 단위 가격 낮은 순에서 가격 없는 후보는 맨 뒤에 둔다.
- 결과 없음(S280 · S281)은 개수·정렬·각주 없이 '아직 비교할 유사템이 없어요'와 [다른 제품 찾기](시작 화면)만 둔다. 미계산·후보 없음은 같은 빈 상태다.
- 유사템 조회 실패(S286)는 개수·정렬·각주 없이 기준 제품 판 아래에 재시도를 둔다. 제품 조회 실패는 화면 오류다.
- 기존 상세의 최대 3개 미리보기는 유지하고, 그 섹션 머리의 '더보기'로 이 결과에 들어온다.
- 정렬은 URL을 replace하고 스크롤을 유지한다. 대상 구성품 상세는 partHref로 연결하며 문서 스크롤과 Next.js의 뒤로 가기 복원을 사용한다.
- 직접 진입한 결과의 뒤로가기는 `/similar-products`, 내부 진입은 이전 방문 기록으로 돌아간다.
- 로그인 없이 접근한다. 하단 내비게이션은 추가하지 않는다. 상단 내비 오른쪽 검색 버튼은 두지 않는다(#1233: 제품을 찾는 화면에만).

## 시작 화면

- 큰 제목 없이 입력칸 → 소개 판 → (회원) 내 파우치 → 요즘 많이 찾는 저렴이 순서다(S271). 위 24, 입력칸과 소개 판 사이 16, 섹션 사이 24다. 끝은 문의 버튼 자리(`pb-inquiry`)를 둔다.
- 소개 판: 홈 바로가기 '유사템찾기'와 같은 아이콘(40) + '성분은 비슷한데 가격은 절반이라면?'(16/700, '절반'은 brand-text) + '내 피부에 맞던 성분 그대로, 더 저렴하게'. 바탕은 brand-soft다. 누르는 동작은 없다.
- 입력칸을 누르면(S272) 소개 판·파우치·저렴이를 접고 최근 검색만 보여 준다. 최근 검색은 제품명 검색(S46)과 같은 기록·같은 모양이다. 행을 누르면 다른 화면으로 가지 않고 그 말(제품 기록은 제품 이름)로 이 화면에서 다시 검색한다.
- 입력하는 동안(S274)에는 입력칸과 검색 결과만 보인다. 접은 섹션은 입력칸에서 포커스가 빠지고 입력이 비면 다시 펼친다. 접은 섹션은 hidden으로 숨겨, 펼칠 때 파우치를 다시 받지 않는다.
- 관리자 세션은 파우치를 쓸 수 없어 파우치 섹션을 숨기고, 소개 판 위에 관리자 안내를 둔다.

## 검색

- 시작 경로: `/similar-products?q=검색어`. 검색어를 주소에 남기고, 별도 검색 결과 페이지는 열지 않는다.
- 입력 아래 이미지·브랜드·제품명이 있는 후보를 최대 5개 표시한다(S274: 위아래 16, 사진 48, 사진과 글 사이 8, 브랜드 12 · 제품명 15/500). 기존 suggestions API에 page=1·size=5를 요청한다.
- 제품명에서 입력어와 맞는 글자를 brand-text로 칠한다. 서버가 제품명으로 맞혔으면 `match` 범위를, 아니면 검색어를 이름에서 다시 찾는다.
- 입력이 300ms 멈추면 조회한다. 한글 조합 중에는 기다리고, 이전 요청의 응답은 현재 검색 결과를 덮어쓰지 않는다.
- 입력값은 기존 제품 검색 화면처럼 React 상태로 유지한다. 한글 조합 중에는 주소를 바꾸지 않고, 입력이 멈춘 완성 검색어만 URL에 저장한다.
- 조회 지연·이전 요청 취소·실패·재시도는 공용 `useSuggestions`를 사용한다. 유사템 전용 코드는 5개 조회와 목록 복원만 맡는다.
- 기존 Combobox·SearchField를 사용한다. 방향키로 후보를 가리키고 Enter로 선택하며 Esc로 닫는다. 후보를 가리키지 않은 Enter는 이동하지 않는다.
- 검색 중(S274-1)은 후보 행과 같은 자리의 스켈레톤 3행이다. 300ms 뒤에 켜고 최소 500ms 유지한다(F02). 결과 없음(S275)과 실패·재시도(S285)를 구분한다. 받은 후보는 메모리에 잠시 남겨 뒤로 가기에 복원한다.
- 선택한 제품은 `/similar-products/[productId]?sort=UNIT_PRICE_ASC`로 이동하고, 검색어를 제품명 검색과 같은 최근 검색 기록에 남긴다. 검색·파우치 모두 첫 구성품을 서버에서 선택한다.

## 내 파우치

- 섹션은 상태와 관계없이 높이가 같다(머리 32 + 16 + 내용 166). 불러오는 중 · 제품 · 빈 파우치 · 실패 · 로그인 전이 바뀌어도 아래 저렴이 목록이 밀리지 않는다. 기기 글자 크기를 키우면 늘어나도록 최소 높이로 둔다.
- 제품은 최근 등록 10개를 홈 제품 카드(`ProductGridCard`, 폭 100, 판매처 태그 없음)로 가로로 보여 준다. 넷째 카드가 걸쳐 보인다. 카드를 누르면 그 제품의 결과로 간다.
- 파우치 '전체' 버튼과 파우치 선택 시트는 없다. 11번째 제품부터는 검색으로 찾는다.
- 불러오는 중(S271-1)은 카드와 같은 자리의 스켈레톤 4장이다.
- 빈 파우치(S279)는 회색 판에 '파우치에 담은 제품이 없어요'와 고스트 '파우치로 가기 >'(`/pouch`)를 둔다. 설명 줄은 없다.
- 로그인 전(S271-2)은 같은 판에 '로그인하고 내 제품으로 찾아보세요'와 고스트 '로그인 >'을 둔다. 기존 rememberLoginReturn으로 현재 주소를 기억한다.
- 실패(S283)는 섹션 재시도이고, 검색은 계속 사용할 수 있다. 파우치는 기존 파우치 목록 API만 요청한다.
- 시작·결과 화면에 하단 내비게이션이 없다. 홈 바로가기의 유사템찾기가 시작 화면으로 연결된다.

## 로딩과 오류

- 시작 화면의 첫 로딩(S282)은 입력칸 · 소개 판 · 저렴이 섹션 스켈레톤이다. 저렴이 행의 사진과 글 사이는 실제 행처럼 0이다.
- 결과 화면의 로딩은 `[productId]/loading.tsx`가 따로 그린다. 기준 제품 판 · 섹션 머리 · 정렬 칩 · 행 자리이고, .pen에 결과 스켈레톤이 없어 결과 화면 구조에서 모양을 가져왔다.
- 없는 제품·구성품과 잘못된 ID는 404다(S284). 검색 아이콘 28 · '제품이나 구성품을 찾을 수 없어요' · [제품 선택으로]를 남은 높이의 세로 가운데에 둔다.
- 화면 오류(S287)는 경고 아이콘 28 · 제목 · 설명 · [다시 시도] · 오류 코드를 세로 가운데에 둔다.

## 요즘 많이 찾는 저렴이

- 내 파우치 영역 아래에 로그인과 관계없이 표시한다. 파우치의 로그인 전·빈 결과·조회 실패가 이 목록을 숨기지 않는다. 제목과 목록 사이는 띄우지 않는다(행 위 16이 간격이다).
- 모든 환경에서 `mocks/popular-dupes.ts`의 같은 고정 조합 3개를 표시한다. 제품명·이미지·단가·절감률은 공통으로 관리한다. `popularDupesForEnvironment`는 실제 DB에서 다른 제품·구성품 ID만 매핑하며, `NEXT_PUBLIC_ENVIRONMENT=staging` 외에는 운영 ID를 사용한다. 기존 제품 이미지·목록 행 규칙과 디자인 토큰을 따른다.
- 행(S271): 58 칸 안에 기준 제품 사진(32, 불투명도 45%, 왼쪽 위)과 대체 제품 사진(52, 오른쪽 아래)을 겹치고, 사진과 글 사이는 0이다. 글은 '기준 브랜드 제품명 대신'(12, 한 줄 말줄임) → '대체 브랜드 제품명'(15/600, 두 줄 말줄임) → 가격 줄 '46%'(success-text) · 'ml당 347원' · 취소선 기준 단가 '640원'이다. 가격 줄은 결과 화면 행과 같은 12/700이고, 절약률은 소수점을 버린 정수다.
- 섹션 보조 설명 없이 제목과 목록을 표시한다. 고정 목록이며, 실시간 순위는 아니다(제목 '요즘 많이 찾는'은 #1037 전까지 사실이 아니다).
- 행을 누르면 기준 제품·구성품의 유사템 결과로 이동한다. 표시할 조합이 없으면 검색을 안내하는 빈 상태를 보여 준다.
- 페이지에서 데이터를 받아 카드에 넘긴다. #1037의 후속 서버 작업에서 기존 대체 제품의 조회수 기준 공개 API로 교체한다.
- 공통 목록은 완료된 최근 7일(2026-11-05~11-11)의 staging 대체 제품 조회수 내림차순으로 3개를 고른다. 조회수가 같으면 대체 제품 ID 순이다. 같은 대체 제품의 여러 관계 중 기준 제품 조회수, 유사도 내림차순, 기준 제품·구성품 ID 순으로 하나를 선택한다. 자동 갱신 계약은 후속 서버 작업에서 정한다.
- 각 환경 API의 실제 유사제품 목록에서 같은 카테고리·단위의 판매 중인 제품을 고른다. 총가격과 단위 가격이 모두 낮은 조합을 사용하고 대체 제품은 중복하지 않는다.
- 결과의 단가·가격 차이·정렬에는 #1038 백엔드 배포가 필요하다. 제품이 있어도 해당 구성품의 유사도가 계산되지 않았으면 결과는 빈 상태다.
