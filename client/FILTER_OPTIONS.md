# 필터 시트의 선택지 조회

이슈: [#460](https://github.com/woowacourse-teams/2026-poudy/issues/460)

## 계산 기준

브랜드·카테고리·피부 타입 시트는 자기 조건을 제외하고 나머지 조건에 맞는 제품의 선택지를 보여 준다.

| 시트      | 제외하는 조건 | 유지하는 조건                             |
| --------- | ------------- | ----------------------------------------- |
| 브랜드    | `brandIds`    | 카테고리, 피부 타입, 검색어, 성분, 유수분 |
| 카테고리  | `categoryIds` | 브랜드, 피부 타입, 검색어, 성분, 유수분   |
| 피부 타입 | `skinType`    | 브랜드, 카테고리, 검색어, 성분, 유수분    |

브랜드와 소분류는 여러 개를 함께 고른다. 카테고리의 전체 선택은 해당 대분류에 속한 후보만 선택하거나 해제한다. 피부 타입은 하나를 고르고 다른 타입을 고르면 교체한다.

## 구현 결정

기존 `GET /api/products` 계약을 유지하고 시트를 열 때 자기 조건을 뺀 요청을 보낸다. 서버의 `Products.find`는 페이지를 자르기 전의 전체 일치 제품에서 `brands`, `categories`, `skinTypes`를 계산한다. 따라서 `page=0`, `size=1`로 제품 전송량을 줄여도 후보는 빠지지 않는다. 선택지에는 정렬 순서가 필요 없어 제품 정렬도 기본값을 사용한다.

목록 응답 전체의 집계 의미를 바꾸면 다른 소비자와 서버 변경이 함께 필요하다. 현재 계약으로 필요한 후보를 얻을 수 있어 클라이언트에서 조회 조건을 분리했다. 단점은 시트를 열 때 목록 API를 한 번 더 호출한다는 것이다. 서버 팀과 별도 협의가 완료된 것으로 간주하지 않으며, 추후 전용 후보 API를 도입한다면 같은 계산 기준을 유지한다.

## 책임과 요청 수명

- `filterForOptions`는 시트별 조회 조건을 결정한다.
- `useFilterOptions`는 조회·실패·재시도와 오래된 응답 무시를 맡는다.
- `FilterFacetOptions`는 조회 상태를 보여 주고 선택 컴포넌트에 후보를 전달한다.
- `FilterSheets`는 열 때마다 적용된 조건으로 초안을 시작한다. 취소한 초안은 다음 열기에 남기지 않는다.

시트 안에서 자기 조건을 바꿔도 후보 조회 조건은 같으므로 재요청하지 않는다. 제품 개수는 기존 개수 조회가 초안의 모든 조건을 반영해 계산한다. 조회 실패는 빈 결과와 구분해 재시도 버튼을 표시한다.

## 목과 회귀 검증

목 서버 역시 요청에 일치하는 전체 제품에서 후보를 계산하므로 응답 구조나 집계 알고리즘은 바꾸지 않는다. 실제 화면이 사용하는 새 요청을 기존 MSW 핸들러로 처리해 브랜드·소분류 추가 선택, 피부 타입 교체, 다른 조건에 맞지 않는 후보 제외를 검증한다.

별도 테스트로 다른 검색 조건 보존, 자기 조건 변경 시 재조회 방지, 오래된 응답 무시, 실패 후 재시도, 적용·취소 후 다시 열기와 대분류 전체 선택 범위를 검증한다.
