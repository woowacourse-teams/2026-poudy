# 제품 목록과 필터 선택지

[이슈 #460](https://github.com/woowacourse-teams/2026-poudy/issues/460)의 2026-09-18 최신 결정을 따른다.
닫힌 PR #472의 시트별 추가 목록 조회 설계는 사용하지 않는다. 당시 카테고리 다중 선택과
시트 재진입 시 초안 초기화 처리는 검토해 유지했다.

## 서버 계약

현재 페이지 번호는 1부터 시작한다(#476). `GET /api/products`의 `page=1` 응답에
`filterOptions: { brands, categories, skinTypes }`를 포함한다. 후속 페이지는 계산과 필드를
생략한다. 생략은 빈 배열과 다르다.

| 항목                                    | 적용 조건                 |
| --------------------------------------- | ------------------------- |
| `items`, `pagination`, 기존 최상위 집계 | 모든 조건                 |
| `filterOptions.brands`                  | `brandIds` 전체만 제외    |
| `filterOptions.categories`              | `categoryIds` 전체만 제외 |
| `filterOptions.skinTypes`               | `skinType`만 제외         |

검색어·성분 포함/제외·빠른 제외·유수분 조건은 유지한다. 후보와 카테고리 제품 수는
페이지 분할 전 전체 일치 제품을 기준으로 계산한다. 제품 결과가 0개여도 후보는 남을 수 있다.
`ProductFilter`가 조건 제외를, `Products`가 판정과 집계를 소유한다. 검색 후보를 재사용하며
후보별 제품 정렬이나 검색 로그를 추가 실행하지 않는다.

기존 최상위 집계는 호환성을 위해 유지한다. 저장소 밖의 이전 클라이언트·소비자 사용 여부를
확인할 수 없으므로 이번 변경에서는 제거하지 않는다. OpenAPI와 공용 TypeScript는 서버에서 생성한다.

## 클라이언트 책임

- `useProductPages`와 제품 페이지 캐시는 제품과 선택지를 같은 조건 키로 관리한다.
  후속 페이지의 필드 생략은 선택지를 유지하고, 첫 페이지의 빈 배열은 빈 값으로 갱신한다.
  재검증은 첫 페이지 응답의 선택지를 사용하고 조건 변경 시 이전 요청의 응답은 버린다.
- `ProductRows`는 `filterOptions`를 시트에 전달한다. 최상위 집계를 후보로 대체하지 않는다.
- `FilterSheets`는 적용된 조건에서 편집 세션을 시작한다. 초안 예상 개수만 기존
  `/api/products/count`로 조회한다. 적용할 때 URL 조건을 변경해 첫 페이지와 선택지를 갱신한다.
  취소한 편집·초기화는 다음 세션에 남지 않는다. 결과가 0개여도 적용과 초기화가 가능하다.
- `CategoryOptions`는 소분류 다중 선택을 지원한다. 전체 선택·해제는 해당 대분류의
  현재 후보만 대상으로 하며 다른 대분류나 표시되지 않는 기존 선택을 지우지 않는다.
- 후보에 없는 기존 선택은 별도 해제 영역에서 개별 해제한다. URL에 ID만 있고 이름을
  알 수 없는 브랜드·카테고리는 ID를 표시한다. 선택 자체를 자동 삭제하지 않는다.

시트를 열거나 편집할 때 추가 제품 목록 요청은 없다. 별도 필터 API나 클라이언트의 전체
제품 누적 필터링도 없다. 중간 페이지 URL로 직접 들어오면 기존 페이지 목록을 유지한다.
첫 페이지 선택지가 없는 이 경우에는 첫 페이지 이동 링크를 제공하고 기존 선택 해제·초기화는
계속 허용한다. 선택지 확보만을 위한 숨은 추가 목록 요청은 하지 않는다.

## 검증

서버 HTTP 테스트는 각 후보를 자기 조건만 제거한 기존 전체 집계와 대조한다. 첫 페이지,
후속 페이지 생략, 다중 ID, 빈 결과 및 검색·성분·유수분 조건 보존을 검증한다.
목 응답은 같은 계산과 페이지 계약을 따르고 생성된 Zod 스키마로 검증한다.

클라이언트 회귀 테스트는 브랜드 추가·카테고리 다중 선택·피부 타입 교체, 추가 목록 요청 부재,
캐시 복원·재검증·조건 변경·지연 응답, 적용·취소·초기화, 후보에서 빠진 선택 해제를 검증한다.
성능 측정 방식과 결과는 [서버 측정 기록](../server/docs/product/filter-options-performance.md)에 기록한다.

2026-09-18 검증에서 lint·포맷·타입 검사와 프로덕션 빌드가 통과했다. 기본 병렬 실행은
공유 머신의 CPU 경합으로 시간 제한 실패가 발생해, 승인된 `pnpm exec vitest run --maxWorkers=4`로
전체 88개 파일·806개 테스트 통과를 확인했다. 테스트 내용과 시간 제한은 변경하지 않았다.
