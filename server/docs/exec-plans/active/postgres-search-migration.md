# 상품과 성분의 PostgreSQL 검색 전환

- 이슈: [#492](https://github.com/woowacourse-teams/2026-poudy/issues/492), 선행 작업 #480
- 기준: `feat/backend-postgres-migration`의 `c1afc87`
- 작업 브랜치: `feat/postgres-search-migration`
- 상태: 기존 구조 조사 완료. 검색 구현과 신규 테스트는 아직 시작하지 않았다.

## 목표와 범위

상품과 성분 검색을 DB로 옮기고 전체 카탈로그 메모리 로딩 의존을 제거한다.
API 형식은 유지한다. #480에 따라 검색 순위 변경을 허용하고 상품 목록은 모든 검색
토큰이 맞는 결과만 사용한다. 구체적인 동작과 기대 결과는 구현 및 실행 가능한 테스트에 둔다.
문서에는 작업 순서와 코드만으로 알기 어려운 결정 이유만 남긴다.

기존 적재 파이프라인은 참고만 한다. 적재 스크립트 작성과 수정, 초기 데이터 적재,
실제 데이터 검증, 클라이언트와 모바일 변경, Docker 도입과 운영 배포는 제외한다.

## 구현 순서

1. [ ] **검색 SQL과 테스트**: 첨부 `poudy-full-schema.sql`을 검토하고 필요한 함수,
   뷰와 인덱스를 서버 스키마에 반영한다. 정규화, 초성, 별칭, 브랜드 조합, 오타 교정,
   순위와 강조 구간을 테스트 데이터로 검증한다. 첨부 구현을 검증 없이 그대로 채택하지 않는다.
2. [ ] **성분 조회 전환**: 검색 제안, 상세, 목록과 사용 성분 조건을 DB 조회에 연결한다.
   API 응답과 최대 5개 제안 규칙을 테스트한다.
3. [ ] **상품 조회 전환**: 검색과 제안, 필터, 정렬, 페이지, count와 필터 선택지 집계를
   DB로 옮긴다. 동일 조건의 목록과 개수가 일치하며 필터 후 페이지를 자르는지 테스트한다.
4. [ ] **연관 기능과 모델 정리**: 보관, 큐레이션, 공유, 랭킹, 존재 확인과 집계의 전체
   로딩 의존을 없앤다. 중복 엔티티와 도메인 매핑을 정리하고 불필요해진 변환, 메모리 검색
   코드와 설정을 제거한다. 전성분 순서와 중복 등 기존 규칙을 보존한다.
5. [ ] **전체 회귀 검증**: `poudy_test`의 테스트 데이터로 저장소와 API를 검증하고
   `sh ./scripts/verify.sh`를 통과시킨다. 필요한 실행 방법과 아키텍처 변경만 문서에 반영한다.

각 구현 단위에서 관련 테스트를 함께 작성하고 실행한다. 테스트를 통과한 기능 단위로
커밋한다. DB 환경이 없더라도 코드 작성은 진행할 수 있지만 실행 검증을 완료로 표시하지 않는다.
환경 설치나 권한 변경은 원인을 확인하고 사용자에게 적용 여부를 묻는다.

## 구현에 필요한 인수인계

- private repo `Seonwu-K/poudy-private`의 `db-script` (`b2f4360`)에서 `db-load` 구조를 확인했다.
  첨부 SQL의 기존 테이블은 서버 스키마와 동일하며 검색 구조가 추가되어 있다.
- 기존 적재기는 마지막에 `product_search_document`, `ingredient_search_term`,
  `search_vocabulary` 순서로 갱신한다. 서버 스키마는 이 계약을 유지하고 테스트 데이터
  삽입 후에도 뷰를 갱신한다. 적재기 자체는 변경하지 않는다.
- 기존 Java 검색 단위 테스트 79개는 통과했다. 신규 DB 검색의 검증 결과는 아니다.
- 이전 `verify.sh`는 Java 21 컴파일 후 `localhost:5432` 연결 거부로 실패했다.
  DB 통합 테스트에는 로컬 PostgreSQL이 필요하며 실제 카탈로그 적재는 필요하지 않다.
