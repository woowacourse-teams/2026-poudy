# 공통 제품 상세와 회원별 제품 정보 분리

- 이슈: https://github.com/woowacourse-teams/2026-poudy/issues/829
- 브랜치: `refactor/product-detail-save-status`

## 최종 계약

- `/api/products/{productId}`는 공통 제품 정보만 반환한다. 회원 쿠키에 따라 결과가 달라지지 않는다.
- `/api/users/me/products/{productId}`는 회원 인증을 요구하고 `wishlisted`, `shelved` boolean을 반환한다.
- 회원별 제품 응답은 `UserProductResponse`이며, 향후 해당 제품의 커스텀 필터 정보도 추가할 수 있다.
- 인증이 없거나 유효하지 않으면 401, 관리자 세션이면 403, 제품이 없으면 404이다.
- 기존 회원 인증·활성 상태 검사·캐시 금지 정책을 재사용한다. 별도 선택적 인증 필터는 두지 않는다.
- 저장함·선반 ID 조회 API를 제거한다. 각 제품 목록과 등록·수정·삭제 API는 유지한다.

## 프론트 전환

- 제품 상세는 요청마다 SSR로 렌더링한다. 공통 제품 데이터는 쿠키 없이 하루 동안 캐시한다.
- 서버가 받은 JSESSIONID가 있을 때만 회원별 제품 정보를 Cookie 헤더와 no-store로 조회한다.
- 공통 정보와 회원 정보는 병렬 조회하고, 완성된 저장 상태로 본문·축약형 버튼을 함께 렌더링한다.
- 인증 만료는 로그인 필요 상태로, 관리자 인증은 관리자 안내 상태로 전달한다. 장애를 false로 대체하지 않는다.
- SSR에서 소비한 앱 쿠키 연장이 브라우저에 유실되지 않게 X-Poudy-SSR 헤더로 구분한다.
- 목록에는 저장 버튼을 표시하지 않고 회원 조회도 하지 않는다.
- 저장함·마이페이지의 전체 제품 조회는 기존 제품 목록 API를 사용한다.

## 검증

- 비회원의 공개 상세, 회원별 저장 상태 4가지 조합, 다른 회원·제품과의 격리, 삭제 반영
- 인증 누락·잘못된 세션·절대 만료·탈퇴/삭제 회원·관리자·없는 제품
- 개인 응답 no-store, 공통 응답에서 개인 필드 제거, 기존 ID API 404
- 쿠키 전달·회원 간 캐시 분리·병렬 조회·초기 HTML·공유 버튼 상태·실패 복원
- 앱 쿠키 연장과 SSR 웹 절대 만료 유지
- 서버 공식 verify, 클라이언트 전체 테스트·타입·린트·프로덕션 빌드

- 서버 `sh ./scripts/verify.sh` 통과: 테스트 1,398개, 실패·스킵 없음. API 생성물 드리프트 없음.
- 클라이언트 전체 테스트 1,487개 통과. 후속 캐시 동기화 변경도 관련 테스트 87개 통과.
- 클라이언트 타입 검사·린트(오류 0개, 기존 디자인 경고 유지)·변경 파일 포맷·프로덕션 빌드 통과.
- 실제 프로덕션 서버에서 비회원·만료 세션 상세 200과 없는 제품 404를 확인했다.
- 상세 HTML의 private/no-store, SSR 초기 버튼 상태, 세션 ID 비노출을 확인했다.
- 검증은 기존 데이터와 분리한 임시 PostgreSQL 및 API 서버에서 수행했다.
