# 인기 검색어 구현·검증 기록

## 구현 범위

브랜치는 `feat/server-search-keyword-rankings`다. `GET /api/search-keywords/rankings`는
순위와 완성어만 최대 10개 반환한다. 일반어·브랜드·상품을 통합하고, 성공한 첫 페이지
검색만 입력별로 집계한다. 최소 5회, UTC 10분 칸, 완결된 168시간(1,008칸) 순위 기간을 적용한다.
사용자별 중복 제출 제거는 추가하지 않았다.

`SearchKeywordPolicy`가 칸 크기·순위 기간·최소 횟수·순위 크기·보고서 최소 횟수·60초 저장 주기를 소유한다.
인기 검색어 전용 환경 변수와 배포 스크립트는 추가하지 않았다.
서버는 제공된 사전을 읽기만 하며, JSON 생성은 private의 오프라인 파이프라인 책임이다.

개발 실행 디렉터리를 server로 두면 상태는 `./var/search-ranking/buckets.json`이다.
운영 기본값은 `/opt/poudy/state/search-ranking/buckets.json`이며,
운영 권한·배포·롤백 점검은 이번 로컬 구현과 별개다.
사전 누락·손상은 기동 실패다. 사전 검증은 리더와 도메인 생성자가 담당하고, 잘못된 사전이
올라오면 데이터 동기화가 health 실패로 판정해 이전 데이터로 되돌린다.

## 실제 기동·저장·복원

빌드 경로와 분리한 고정 JAR, 별도 임시 카탈로그와 상태 디렉터리, `-Xms128m -Xmx768m`으로
로컬 서버를 기동했다. 운영 데이터와 개발 상태 파일은 검증용 기록으로 덮어쓰지 않았다.

1. 빈 순위 응답을 확인했다.
2. 토너 5회, PDRN/pdrn 합계 5회, 독도 토너 5회, 구 사전에서 미해석인 ㄷㄷㄹㅅ 20회를 요청했다.
3. 후속 페이지·count·suggestions 조회가 추가 집계를 만들지 않는지 확인했다.
4. 0건 검색 20회는 집계 파일에 포함되지 않았다. 당시에는 Cf 문자를 포함한 검색도 거절했으나,
   현재는 정규화가 그 문자를 지워 같은 키로 센다.
5. 실제 60초 주기가 저장한 정규화 입력과 횟수는 위 네 입력의 5/5/5/20과 일치했다.
6. 접근 권한 0600의 내부 보고서는 미해석 성공 20회를 기록했다. 당시 보고서에 있던 0건 목록은
   이후 0건 저장소와 함께 제거했다.
7. 사전만 갱신해 재시작하자 기존 20회가 독도 로션 1위로 연결됐다. 저장된 횟수와 파일은
   그대로였다.

내부 보고서는 HTTP로 노출하지 않는다. 운영자가 필요할 때
`--poudy.search-keywords.report-file=/absolute/restricted/path/report.json`을 지정하면
60초 주기로 제한된 로컬 파일에 내보낸다. 사전·카탈로그·검색 구현 버전, 기동 시각, 순위 기간의
시작과 끝, 시계 역행 여부, 사전을 거치지 않은 섀도우 순위를 함께 기록한다. 기간은 완결된 칸
기준이며 전체 기간의 연속 관찰을 보장하지 않는다. 별도 복사본도 원본 시간창을 넘겨 보관하지 않는다.

## 로컬 자원 측정

2026-09-09 macOS, Java 21, `-Xms128m -Xmx768m`. 합성 입력으로 순위 저장소를
과거 전역 상한 실험에서 10%·50%·100%를 채웠다. 과거 100%는 각각 16,800/7,200개 항목이며 모든 입력을 서로 다르게
만들어 키 공유에 따른 메모리 절약을 가정하지 않았다. 입력 길이는 UTF-16 단위다.
스냅샷을 보존한 상태의 전체 측정 JVM live heap을 사용했으므로, 아래 값에는 합성 사전과
라이브러리 힙도 포함된다. 실제 카탈로그 서버의 전체 힙을 뜻하지는 않는다.

| 입력 길이 | 점유율 | 복사 p99 ms | 순위 p95 ms | live heap MiB | JSON bytes | 저장 ms | 복원 ms |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 20 | 10% | 0.36 | 0.95 | 9.69 | 107,039 | 31.41 | 54.25 |
| 20 | 50% | 0.49 | 0.88 | 13.93 | 504,611 | 13.68 | 58.87 |
| 20 | 100% | 1.07 | 1.59 | 16.87 | 1,001,504 | 14.14 | 98.75 |
| 300 | 10% | 0.13 | 0.27 | 13.20 | 1,518,239 | 11.78 | 114.80 |
| 300 | 50% | 1.05 | 2.65 | 27.57 | 7,560,611 | 23.27 | 534.28 |
| 300 | 100% | 1.73 | 6.93 | 38.81 | 15,113,504 | 32.77 | 1188.25 |

각 조건에서 1·10·100건/초의 반복 요청을 각각 2초씩 적용했다. 최대 항목 수를 먼저
채우는 단계와 반복 요청 단계는 구분했다. 장시간 운영 부하나 봇 공격을 재현한 결과는 아니다.
로컬 합성 측정은 복사 p99 10ms, 순위 p95 50ms, 추가 live heap 96MiB,
당시 임시 파일 64MiB, 60초 이내 저장 기준을 사용했다. 현재 구현에는 전역 entry/file cap이 없다.

최대 용량에서 지연이 발생했던 두 위치를 스레드 덤프로 확인했다. 큰 사전과 입력 합계에
`Map.copyOf`를 사용하면 유사 해시의 표현에서 선형 탐사가 길어졌다. 조회 인덱스와
스냅샷은 독립 HashMap을 외부에서 수정할 수 없게 감싼다. 이후 변경과의 독립성·불변성은
회귀 테스트로 확인했다.

실제 카탈로그 HTTP 비교는 당시 동일 JAR의 수집 활성/비활성 두 로컬 서버를 사용했다.
이 측정 이후 비활성 스위치가 제거되었으므로 아래 비교는 현재 설정 방법이 아닌 과거 측정 기록이다.
4종 검색어로 모드별 1,000회 워밍업 후 3,000회 요청을 5개 구간으로 나눠 순서를 교차했다.
초기 작은 표본에서는 워밍업 지연 변동이 컸으므로 표본을 늘려 재측정했다.

| 구간 | 수집 비활성 p95 ms | 수집 활성 p95 ms | 차이 |
| ---: | ---: | ---: | ---: |
| 1 | 4.787 | 4.474 | -6.53% |
| 2 | 5.032 | 5.147 | +2.28% |
| 3 | 3.930 | 3.611 | -8.12% |
| 4 | 4.774 | 4.777 | +0.06% |
| 5 | 3.584 | 3.403 | -5.05% |

재측정의 각 구간은 5% 증가 기준 이내였다. 활성 모드가 더 빠른 구간을 성능 개선으로
해석하지 않는다. 로컬 지연 변동을 포함하는 결과이며 운영 성능 보장은 아니다.
측정 후 RSS는 비활성 약 297MiB, 활성 약 357MiB였다. 비교 기준은 같은 코드에서 수집을
끈 경우이므로 집계 경로 자체의 도입 전후 비교는 포함하지 않는다.

## 추가 동시성 검토 (2026-09-09, 2026-09-11 갱신)

단일 JVM·단일 작성자 전제에서 집계, 만료, 조회, 저장의 잠금 순서와 공유 상태를 직접
검토했다. 칸 추가·만료·횟수 증가는 저장소 잠금 하나 안에서 처리하며, 조회와 저장에는 독립
복사본을 사용한다. 파일 I/O 중에는 저장소 잠금을 보유하지 않는다. 작성자는 한 번에 하나만
저장하고, 저장 중 다시 불린 작성자는 기다리지 않고 건너뛴다. 저장 중 들어온 요청은 다음
주기의 전체 쓰기에 들어간다. 사전과 순위 계산에는 변경 가능한 공유 작업 맵이 없다.

회귀 테스트는 다음을 확인한다.

- 4개 작성자의 100만 회 증가와 동시 조회·스냅샷: 항목 하나, 횟수 정확.
- 8개 작성자가 서로 다른 검색어 800개를 동시에 기록: 항목 800개, 모두 1회.
- 4개 작성자의 40,000회 기록과 200시간 전진·만료·조회·복원 가능한 스냅샷 생성을 병행:
  보관 범위와 항목 수 일치, 최종 만료 후 잔여 항목 없음.
- 저장을 지연시킨 동안 집계가 막히지 않고 겹친 저장은 건너뜀. 저장소는 목으로 대신한다.

구현 변경이 필요한 동시성 결함은 발견하지 못했다. 모니터링 지표와 보고서는 각각 다른 순간을
관찰할 수 있으며 여러 지표의 원자적 관측을 제공하지는 않는다. 여러 JVM이 같은 파일을
공유하는 경우의 덮어쓰기와 시작 시 임시 파일 정리는 이 잠금으로 보호되지 않으므로,
계획대로 단일 JVM·단일 작성자로 실행해야 한다.
