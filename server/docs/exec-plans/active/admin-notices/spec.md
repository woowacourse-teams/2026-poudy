# 관리자·공지사항 intent / spec

상태: 사용자와 확정한 제품 요구사항 + 구현을 위한 기본 선택. 2026-10-21.
아래 ‘구현 기본값’은 사용자에게 직접 확정받은 정책과 구분하며, 코드·실제 데이터 확인에 따라 조정한다.

## 목표와 범위

기존 관리자 기능을 첨부 디자인으로 개편하고 공지를 작성·게시해 사용자에게 전달한다.
문의 통합 목록·상세, 담당자·메모·처리 이력·일괄 처리, 회원 복구 목록·확인 모달,
공지 관리자 목록·작성/수정·실시간 미리보기와 사용자 공지 목록·상세·상단 띠를 포함한다.

캐러셀 관리, 개별 관리자 계정·권한, 예약 게시, 본문 서식 편집은 제외한다.
기존 로그인·세션·접수 기능을 유지한다. 제품 요청 승인·사진·선반 반영(#765),
사용자 문의 작성 화면 개편(#741)은 별도 작업이다.

## 확정한 정책

### 운영자와 문의

- 공지·메모 작성자와 수동 처리자는 `관리자`로 표시한다. 자동 접수는 `시스템`으로 구분한다.
- 담당자는 `미배정 / 관리자`만 선택한다. 단일 작성자 필터는 표시하지 않는다.
- 서비스 의견·제품 정보 정정·제품 등록 요청을 같은 관리 화면에서 조회하되 기존 접수 API와 저장 자원 구분은 유지한다.
- 상태는 `RECEIVED`(새 문의), `IN_PROGRESS`(확인 중), `REVIEW_PLANNED`(검토 예정),
  `COMPLETED`(처리 완료), `REJECTED`(반려)다. 기존 상태 값과 데이터를 보존한다.
- 상태/담당자 변경, 메모 추가를 실제 저장하고 처리 이력에 남긴다. 메모는 사용자에게 노출하지 않는다.
- 첨부 이미지 확대, 유입 경로, 상세의 이전/다음, 목록 선택·일괄 변경·선택 해제·새로고침을 제공한다.

### 회원 복구

- 기존 복구 요청을 기본 근거로 사용한다. 일반 문의를 새로 등록하거나 선택해야 하는 조건을 만들지 않는다.
- 복구 요청이 없는 계정은 복구할 수 없다. 디자인의 ‘연결 문의 필수’ 영역은 실제 복구 요청 정보로 바꾼다.
- 탈퇴 회원, 7일 이내 삭제 예정, 이번 달 복구·영구 삭제 통계를 제공한다.
- 이메일 정확 일치 검색, 로그인 제공자·상태 필터, 삭제 예정 빠른 순, 복구 완료 표시를 제공한다.
- 목록/모달 이메일은 마스킹한다. 복구 모달은 선반 제품·평가, 위시리스트, 프로필,
  나만의 필터 등 실제 유지되는 정보의 존재·개수를 보여 준다.
- 복구하면 보존 중인 기존 데이터로 로그인할 수 있다. 별도 알림은 보내지 않는다.

### 공지

- 비공개 저장 → 공개하기로 즉시 게시. 공개 중 저장하면 바로 반영한다. 예약 게시는 없다.
- 제목 최대 40자, 본문 최대 2,000자, 띠 문구 최대 24자다.
- 본문은 일반 텍스트와 줄바꿈이다. URL은 링크로 표시하고 이미지는 본문 뒤에 순서대로 표시한다.
  첨부는 최대 5장·장당 5MB·JPG/PNG/HEIC이며 실제 바이트를 검증·재인코딩한다.
- 띠는 공개 상태이면서 띠가 켜진 공지 중 최신 공개순 최대 10개다. 5초마다 교대하며 수동 전환도 지원한다.
- 띠 문구 클릭은 해당 공지 상세로 이동한다. 닫기 상태는 현재 탭을 닫을 때까지 유지한다.
- 최초 공개일을 유지한다. 재공개·수정으로 바꾸지 않는다.
- 사용자 상세 진입마다 조회수를 늘린다. 관리자 미리보기는 집계하지 않는다.
- 비공개 공지만 확인 후 삭제할 수 있다. 비공개 공지는 직접 주소로도 조회되지 않는다.
- 관리자 목록은 공개/비공개 수·띠 노출 수, 제목 검색·상태 필터·정렬·페이지 이동을 제공한다.
- 제목·본문·띠·이미지 편집은 사용자 화면과 같은 렌더러로 미리 보여 준다.

### 디자인과 대응 폭

- 색·서체·크기·반경은 `design-system/tokens.json`의 값을 기준으로 한다.
  `admin-bg`=#EFEFEB, `admin-text`=#262623, `admin-border`=#D8D8D2,
  `admin-brand`=#E85D75, 제목 22px, 지표 26px, 본문 14px, 캡션 12px,
  반경 4/6/8/10/12px가 현재 JSON에 있다. 글꼴은 `ui-font`→`app-font-pretendard`→Pretendard다.
- 원본 `.pen`이 없으므로 정확한 좌표·여백·행간·굵기는 첨부 화면과 대조해 정한다.
  원본을 읽거나 완전 일치시켰다고 보고하지 않는다.
- 관리자 화면은 데스크톱 우선, 좁은 화면의 표는 가로 스크롤을 제공한다.
- 사용자 공지는 기존 앱·웹의 모바일 프레임·내비게이션에 맞춘다.

## 구현 기본값

- 날짜 계산·표시는 Asia/Seoul이다. 현재 설정된 회원 보관 기간(기본 30일)을 재사용한다.
- 문의의 기본 조회 기간은 최근 30일, 페이지 크기는 기존 20개다. 화면의 페이지 이동은
  서버의 page/size를 이용하고, 정렬은 접수 시각·ID 내림차순으로 안정화한다.
- 문의 검색은 내용·브랜드·제품명·접수 ID·유입 경로를 대상으로 서버에서 처리한다.
  목록 필터와 count가 같은 조건을 사용한다. 오늘 접수는 서울 날짜, 상태 요약은 보존 중 원본 기준이다.
- 상세 이전/다음은 현재 목록 조건·정렬을 따른다. 필터 밖 항목으로 이동하지 않는다.
- 기존 유형은 원본 자원 종류를 바꾸는 재분류를 지원하지 않는다. 디자인의 ‘분류’ 이력은
  접수 유형을 표시하고, 존재하지 않는 과거 관리 행위를 만들어 넣지 않는다.
- 메모는 추가만 지원하며 내용은 1~2,000자다. 같은 상태/담당자로 다시 변경하면 이력을 중복 생성하지 않는다.
- 일괄 변경은 최대 100건, 중복 제거 후 모두 성공하거나 모두 실패한다. 실패 시 목록을 갱신해 재확인한다.
- 띠 10개 제한은 ‘설정 가능한 공지 수’가 아니라 ‘사용자에게 반환하는 노출 수’다.
  나머지 공개 공지는 목록/상세에서 볼 수 있고 상위 공지가 빠지면 다음 항목이 띠에 들어온다.
- 띠는 홈 상단에 표시한다. 관리자·로그인·가입·복구 화면에는 붙이지 않는다.
  페이지가 숨겨졌거나 사용자가 띠에 포커스를 둔 동안 자동 전환을 멈추고 수동 전환을 유지한다.
- 탭 단위 닫기는 sessionStorage로 유지한다. 공지가 갱신되어도 같은 탭에서는 다시 강제로 띄우지 않는다.
- 저장 전 편집값은 미리보기에만 반영된다. ‘공개하기’는 현재 편집값 저장과 공개를 한 번에 수행한다.
- 제목·본문은 공백만 입력할 수 없다. 띠가 켜졌다면 띠 문구가 필수다. 글자 수는 서버/클라이언트가
  같은 Unicode code point 기준을 사용하고, 띠 24자 제한과 2,000자 본문 제한에 첨부 이미지는 포함하지 않는다.
- 링크는 http/https URL만 링크로 만들고 HTML은 텍스트로 표시한다. 이미지 링크/경로를 임의 HTML로 받지 않는다.
- 조회수는 상세 화면 진입 시 명시적으로 요청한다. 미리 불러오기·미리보기·개발용 효과 재실행으로 늘지 않게 한다.
- 공개/비공개 전환 뒤 다음 사용자 조회부터 반영되도록 공지 데이터에 장기 공유 캐시를 두지 않는다.
- 이미지 원본은 비공개 저장소에 두고, 일반 사용자는 공개 상태를 검사하는 이미지 경로로만 조회한다.
  이미 다운로드한 파일이나 브라우저에 남은 사본까지 회수한다는 의미는 아니다.
- 복구 기간이 지난 회원은 삭제 배치가 아직 실행되지 않았어도 복구할 수 없다.
- 반복 탈퇴는 별도 회차로 관리한다. 새 탈퇴에 이전 회차의 복구 요청을 재사용하지 않는다.
- 기존 코드는 다시 로그인하는 것만으로 자동 복구하지 않는다. 이번에 자동 복구를 추가하지 않으며,
  디자인의 ‘다시 로그인 N’ 문구를 실제 동작에 맞춰 관리자 복구 집계로 조정한다.
- 신규 집계로 복구할 수 없는 과거 통계는 0으로 가장하지 않고 집계 시작일을 함께 표시한다.

## 완료 시 확인할 시나리오

- 기존 문의가 누락 없이 통합되고 검토 예정·반려가 필터·집계·일괄 처리에 포함된다.
- 새 문의/기존 문의 모두 담당자·메모·이력이 새로고침 후 유지된다.
- 복구 요청/기한을 서버가 확인하고 복구와 삭제의 동시 실행에서도 계정이 잘못 되살아나지 않는다.
- 공개 중 저장·비공개 전환·삭제가 사용자 목록/상세/띠/이미지에 일관되게 반영된다.
- 0·1·10·11개 띠, 24자/40자/2,000자 경계, 긴 URL·이모지·한국어·이미지 실패를 확인한다.
- 공지 초안이나 관리자 메모가 공개 API/생성 HTML에 섞이지 않는다.

## 구현 후 확인 사항

- `.pen`을 새로 만들거나 추정값으로 원본 파일인 것처럼 취급하지 않았다. JSON 관리자 토큰과 첨부 화면을 기준으로 구현했다.
- 공지 목록은 홈의 공통 Footer에서도 진입한다. 띠가 전부 꺼져도 목록을 찾을 수 있다.
- 공지 편집 미리보기는 공통 `NoticeBody`·`NoticeBannerLine`을 공유한다. 이미지 순서와 HTTP/HTTPS 링크도 동일하게 표시한다.
- 현재 구현은 API 선배포가 필요하다. 실제 이미지에는 공지 전용 비공개 S3 버킷을 먼저 설정해야 한다.
- 구현·검증 결과, 남은 외부 이관과 배포 확인은 [실행 계획](README.md)에 기록한다.
