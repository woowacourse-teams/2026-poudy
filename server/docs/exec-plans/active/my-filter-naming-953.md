# 나만의 필터 명칭 통일 (#953)

## 범위와 결정

- 나만의 필터는 피부 타입 필터가 아닌 회원의 제외 성분 목록이므로 `my-filter`로 통일한다.
- endpoint는 `/api/users/me/my-filter`와 `/ingredients`를 사용한다.
- 도메인·패키지·타입·클라이언트 파일명은 `MyFilter`/`myfilter`/`my-filter`로 맞춘다.
- 회원별 제품 응답의 필드도 `myFilterEmpty`, `containsMyFilterIngredient`로 변경한다.
- 기존 경로·응답 필드의 별칭은 두지 않으며 서버와 클라이언트를 함께 반영한다.
- 테이블명은 사용자가 지정한 `user_my_filter_ingredient`로 통일한다.
- V45가 기존 테이블·제약 이름만 변경해 데이터와 FK·유일성·삭제 연쇄를 보존한다.
- 화면 구성·동작은 유지한다. 제품 목록 적용 기능 #952는 보관해 이 변경 후에 이어서 처리한다.

## 검증

- 조회·추가·삭제, 제품 상세·추천·선반·복구 관련 기존 테스트를 새 계약으로 실행한다.
- 새 경로의 OpenAPI 계약과 응답 필드 및 이전 endpoint 제거를 확인한다.
- 기존 데이터가 있는 DB에서 V45 전후 데이터·제약이 보존되는지 확인한다.
- 생성 타입 재생성 후 서버 verify.sh 및 클라이언트 타입 검사·린트·관련 테스트를 실행한다.

## 결과

- 서버 `sh ./scripts/verify.sh` 통과(OpenAPI 드리프트·전체 테스트·아키텍처·스타일·빌드).
- 클라이언트 전체 1,535개 테스트와 타입·포맷 검사 통과. 전체 린트는 오류 0개, 기존 경고 111개.
- V45 전후 데이터·시각·유일성·FK·회원 삭제 연쇄 보존 확인(임시 PostgreSQL 트랜잭션, 완료 후 롤백).
- OpenAPI를 기존 문서와 비교해 경로·타입·필드 명칭 외 계약 변경이 없음을 확인했다.
- #952 변경은 `feat/product-skin-filter` 브랜치의 `issue-952-product-my-filter-in-progress` stash로 보관했다.
