# 백엔드 도메인 캡슐화 리팩터링 계획

## 상태

- 상태: 진행 중
- 시작일: 2026-09-02
- 대상 영역: 백엔드 도메인, 일급 컬렉션, Service와 저장소 경계

## 목표

도메인 상태의 권위 원천을 하나로 만들고, 상태에 관한 판단을 가장 가까운 도메인 객체가
소유하게 한다. 조립이 필요한 컬렉션은 정적 팩토리로 생성하고, 행동과 불변식을 가진
도메인 record는 내부 상태를 감춘 일반 클래스로 바꾼다.

## 유지할 동작

- HTTP 요청·응답 JSON, 상태 코드, 오류 코드와 OpenAPI 계약을 유지한다.
- 검색·필터·정렬·집계 결과와 요청한 ID의 순서를 유지한다.
- 피드백과 제품 등록 요청의 S3 JSON 및 피드백 claim/commit 절차를 유지한다.
- 제품 감각 추론 알고리즘과 모델 버전을 유지한다.
- 카테고리의 대분류·소분류 2단계 규칙을 유지한다.

## 결정

### 컬렉션과 생성 경계

- `Brands`, `Ingredients`, `Products`, `ExcludeCodeIngredients`는 입력을 인덱싱하거나 여러
  상태를 조립하므로 정적 팩토리와 private 생성자를 사용한다.
- `Ingredients`는 입력 순서를 보존하는 성분 검색 인덱스 Map 하나만 가진다.
- `Products`는 입력 순서를 보존하는 제품 검색 인덱스 Map 하나만 가진다. 원본 List, 검색
  List, ID Map과 미리 계산한 브랜드 집계를 함께 보관하지 않는다.
- 제외 성분군의 정방향·역방향 Map은 의미가 다른 조회이므로 유지한다.

### 도메인 행동

- 행동과 불변식을 가진 도메인 record는 `private final` 상태의 클래스로 바꾼다.
- 페이지·상세 결과처럼 값 전달만 하는 타입과 구현 내부의 작은 튜플은 record를 유지한다.
- `Ingredient`는 `IngredientTags`를 한 번 생성해 소유한다.
- `IngredientFilter`와 `ProductFilter`가 필터 판정을 소유하고, 제품은 자신의 상태에 관한
  의미 있는 판단만 제공한다.
- 값 동등성이 실제 계산과 테스트에 필요한 감각 값 객체에만 `equals`와 `hashCode`를 둔다.

### 계층 경계

- 제품 등록 요청 Controller는 HTTP DTO의 값을 Service 입력으로 복사하고 Service는
  Controller DTO에 의존하지 않는다.
- 제외 성분군 조립 실패는 도메인 불변식 오류로 만들고 구성 경계에서 기존 인프라 오류로
  변환한다.
- 아키텍처 테스트로 Service·Domain의 Controller 의존을 금지한다.

## 완료 조건

- `Ingredients`와 `Products`가 같은 원소를 여러 컬렉션에 중복 보관하지 않는다.
- 조립이 필요한 컬렉션을 호출자가 완성된 내부 상태로 만들 수 없다.
- Service와 Domain이 Controller DTO에 의존하지 않는다.
- 공개 API와 저장 문서 계약에 의도하지 않은 변경이 없다.
- 전체 서버 검증이 통과한다.
