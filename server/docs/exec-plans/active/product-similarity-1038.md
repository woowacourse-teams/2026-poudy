# 유사 제품 10개 조회와 단위 가격 정렬 (#1038)

## 범위와 계약

- 기존 두 조회 API에 `size`(기본 3, 1~10)와 `sort`(기본 `SIMILARITY`, `UNIT_PRICE_ASC`)를 추가한다.
- 판매 상태·점수·카테고리·중복 조건을 적용한 뒤 유사도 상위 `size`개를 확정하고, 같은 후보 안에서 정렬한다.
- 가격 동점과 비교 불가 후보끼리는 기존 유사도·제품 ID 순서를 유지한다. 비교 불가는 가격순 목록 뒤에 둔다.
- 대표 가격·용량은 기존과 같이 표시 순서가 가장 앞선 옵션을 사용한다. 총액 차이 필드는 유지한다.
- 단위 가격은 반올림 전 분수로 비교하고, 표시 금액은 정수·차이 비율은 소수 둘째 자리까지 반올림한다. 음수 비율은 더 저렴한 뜻이다.
- 용량 0과 서로 다른 단위는 가격 비교 불가다. 단위의 대소문자만 동일하게 처리하고 단위 간 환산은 하지 않는다.
- 기준 가격 0에서는 가격 관계와 정렬은 계산하되 차이 비율은 제공하지 않는다.
- 새 가격 정보는 기존 응답에 선택 필드로 추가한다. 기존 클라이언트의 기본 조회·필드는 유지한다.
- 회원별 판정도 같은 구성품·후보 수·정렬을 사용한다. 유사도 점수·등급과 계산 방식은 변경하지 않는다.

## 검증

- 기존 최대 3개와 최대 10개, 범위를 벗어난 입력, 두 정렬의 후보 일치와 11번째 저가 후보 제외.
- 단위 가격이 총액 순서와 다른 경우, 반올림하면 같아지는 값의 정확한 정렬과 가격 관계.
- 용량 0, 가격 0, 단위 불일치·대소문자, 제품·구성품 분리와 회원 간 판정 분리.
- OpenAPI 입력·선택 필드·enum 계약, 생성물 갱신과 `sh ./scripts/verify.sh`.

## 결과

- 이슈 #1036~#1040의 범위를 최신 합의에 맞춰 갱신했다.
- `feat/1038-similar-product-price-sort`에서 조회·단가 비교·정렬과 회원별 판정 범위를 구현했다.
- 관련 테스트 37개를 확인했고, 최신 dev 기반 전체 테스트 1,977개를 통과했다. 전체 빌드·스타일 검사와 생성물 드리프트 검사를 통과했다.
- 실행 명령은 `sh ./scripts/verify.sh -I /private/tmp/poudy-1010-test-environment.gradle`이다.
  기존 Gradle 테스트 JVM에 남아 있던 `AWS_ENDPOINT_URL_S3`를 임시 init 설정에서만 제거했다.
  이 설정은 테스트 프로세스의 환경만 분리하며 테스트·서버 코드와 검증 스크립트는 바꾸지 않는다.
- OpenAPI 변경은 공통·회원별 조회 두 경로와 유사 제품·정렬·단가 비교 스키마에 한정됨을 확인했다.
- 기존 클라이언트에서도 생성 타입을 사용할 수 있도록 새 가격 필드는 선택 값으로 추가했다.
  설치된 Next.js의 `typegen`으로 경로 타입을 갱신한 뒤 TypeScript 검사를 통과했다.
