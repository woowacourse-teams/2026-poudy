# 유튜버 홈 순서와 목록 정렬 분리

- 관리자: 드래그·방향키·이동 버튼으로 홈 표시 순서를 편집하고 명시적으로 저장한다.
- 기존 단건 Order API를 재사용한다. 부분 저장 실패 시 초안을 유지하고 전체 순서를 재전송한다.
- 유튜버 목록: 관리자 Order 대신 조회수 합계(기본), 구독자, 최신 업데이트, 추천 제품 수 내림차순으로 정렬한다. 동률은 채널 이름·ID로 결정한다.
- 조회수 합계: 등록된 업로드 영상 전체를 한 번씩 합산한다. 1년 이전·서비스 미노출 영상도 포함하며 미래 영상은 제외한다. YouTube 채널 전체를 새로 수집하지 않는다.
- 추천 제품 수: 공개 API가 반환한 제품 중 recommendedVideoCount > 0인 서로 다른 제품 수.
- 최신 업데이트: 기존 channel.updatedAt(채널 메타데이터 갱신 시각).
- 목록 제품 이미지 축소, 제품 상세로 직접 이동. 홈 카드의 제품 이동 동작은 유지한다.
- 검증: 드래그 저장·실패 재시도, 4가지 정렬·동률·링크, 서버 조회수 중복 방지, 생성 계약, 백엔드 verify와 프런트 정적 검사 및 브라우저 확인.

## 검증 결과 (2026-11-06)

- 최신 dev 통합 후 `sh scripts/verify.sh` 통과: 백엔드 1,979개 테스트, OpenAPI 생성물 드리프트 없음, 전체 빌드 성공.
- 기존 UserRepositoryTest는 탈퇴 시각의 원천인 DB 트랜잭션 시각과 정확히 일치하는지 검증한다. JVM 호스트와 DB 시계 차이에 따른 실패를 제거했고 허용 오차를 늘리지 않았다.
- GitHub Client CI: 210개 파일, 1,797개 테스트 및 형식·린트·타입·빌드·Lighthouse 통과. 로컬 관련 프런트 테스트 10개도 재실행 통과. 로컬 전체 UI 테스트 동시 실행에서는 자원 경합에 따른 시간 초과가 있어 중단했고, 동일 커밋의 CI 전체 검증으로 확인했다.
- 실제 브라우저에서 드래그→저장→새로고침 유지와 기존 순서 복원, 목록의 4가지 정렬, 홈 섹션 위치를 확인했다.
- 로컬 미러의 상세 화면 오류는 생략했던 카테고리·구성품·성분 정의 때문이었다. 공개 스테이징 카탈로그에서 브랜드·정식명을 대조하여 로컬 59개 제품, 60개 구성품과 관련 성분을 보완했다. 전체 59개 상세 API가 정상 응답하고 정식명·카테고리·옵션·유수분·민감성·구성품·선택 구성품의 전성분이 원본과 일치함을 검증했다. 실제 제품 상세 HTML도 오류 경계 없이 정상 렌더링한다.
- 상세 데이터 보완은 격리된 로컬 시범 DB에만 적용했으며 서비스 DB를 변경하지 않았다. 원본 응답·백업·가드가 있는 적재 SQL·대조 결과는 로컬 youtube-release-validation 산출물에 보관한다.
- 로컬 재시작에서 누락됐던 CLIENT_DOMAIN을 복구했다. 재시작 시 인증값뿐 아니라 기존 실행 환경 전체를 보존한다.
- 배포 대상: PR #1115 → dev → 스테이징. 운영 main은 변경하지 않는다.
