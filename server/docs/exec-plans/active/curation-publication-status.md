# 큐레이션 배너·상세 게시 상태 분리 (#491)

> 후속 #496에서 큐레이션 단일 게시 상태와 배너 노출 여부 모델로 대체했다.
> 이 문서는 #491 구현 당시의 결정과 검증 기록이다.

## 범위와 결정

- 공개 큐레이션의 배너와 상세 게시 상태를 독립적으로 저장한다.
- 배너 게시·상세 미게시 조합은 도메인에서 거부한다.
- 배너와 상세가 각자의 게시 상태와 콘텐츠를 소유하고, `Curation`이 두 상태의 관계를 검증한다.
- 저장 문자열을 게시 상태 enum으로 해석하는 책임은 Repository에만 둔다.
- 목록은 배너 게시 큐레이션만, 상세는 상세 게시 큐레이션만 조회한다.
- 게시 상태는 공개 API 응답에 추가하지 않는다.
- 관리자 API와 client/mobile 변경은 포함하지 않는다.

## 구현 및 검증

- [x] 게시 상태와 상태 관계를 도메인에 추가한다.
- [x] JSON 저장 표현과 fixture에 게시 상태를 추가한다.
- [x] 목록·상세 조회에 게시 상태를 반영한다.
- [x] 허용 조합과 금지 조합을 도메인·저장소·HTTP 테스트로 검증한다.
- [x] OpenAPI 설명과 생성물을 갱신한다.
- [ ] 전체 검증 통과: 기존 검색어 저장소의 Windows 디렉터리 동기화 오류 7건

## 검증 결과

- 큐레이션 테스트 36개 통과.
- OpenAPI·공통 타입 생성, 생성물 드리프트 검사, Spotless·Checkstyle·아키텍처 검사 통과.
- 전체 957개 테스트 중 변경하지 않은 `KeywordSnapshotRepository.syncDirectory`에서 Windows
  디렉터리를 `FileChannel`로 열 때 발생하는 기존 오류 7개만 실패했다.

## 배포 주의

- 운영 `curations.json`의 각 `banner.status`와 `detail.status`에 `PUBLISHED` 또는
  `UNPUBLISHED`를 넣은 뒤 서버를 배포해야 한다. 상태가 없거나 금지 조합이면 기동에 실패한다.
