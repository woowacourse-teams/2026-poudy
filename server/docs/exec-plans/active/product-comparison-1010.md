# 제품 비교 일괄 조회 (#1010)

## 범위와 결정

- #1007의 `597a73ff`를 기반으로 제품 비교 API를 구현한다.
- 최대 3개 제품을 요청 순서대로 반환하고 제품마다 구성품 하나를 선택한다.
- 요청은 `productIds`와 제품 ID를 키로 하는 `partIds` 맵으로 받는다. 구성품을 생략하면 첫 구성품을 고른다.
- 기능 태그는 기존 피부 작용 상위 3개를 유지한다. 유수분·주의 성분·내 필터는 선택한 구성품을 기준으로 한다.
- 제품과 공통 주의 기준, 회원 필터는 일괄 조회 흐름에서 한 번씩 읽는다.
- 구성품 선택용 요약과 선택한 구성품의 비교 결과를 제공한다. 가격·용량은 옵션별 쌍으로 제공한다.
- 비로그인·필터 미설정·필터 설정 상태를 구분하고, 필터 조회 실패는 성공한 빈 결과로 바꾸지 않는다.
- 비교 응답과 오류 응답에 `no-store`를 적용하고, 개인화에 사용하는 회원의 활성 상태를 검증한다.
- 기존 상세·회원별 응답 계약과 제품 단위의 첫 구성품 유수분 규칙은 유지한다.

## 검증

- 입력 개수·중복·잘못된 ID·순서·미존재 제품·다른 제품 구성품.
- 복수 구성품의 선택·서로 다른 유수분·빈 성분·구성품 없음·유수분 미제공 카테고리.
- 태그 상위 3개와 주의 기준별 성분 중복 제거, 복수 가격·용량 옵션.
- 회원별 필터 상태·결과 분리·조회 실패 전파·비활성 회원과 캐시 금지.
- 일괄 조회와 공통 기준·회원 필터의 요청당 재사용.
- OpenAPI의 입력·필수·nullable·enum 계약, 공통 생성물 갱신과 `sh ./scripts/verify.sh`.

## 결과

- 비교 전용 36개를 포함한 전체 1,846개 테스트와 아키텍처·스타일·빌드를 통과했다.
- OpenAPI와 공통 Zod·TypeScript 생성물을 갱신했고, 기존 경로와 기존 스키마가 이전 명세와 같은지 확인했다.
- 요청 맵과 컨테이너 제약이 자동 명세에서 누락·오표기되어 비교 경로의 query 명세만 전용 OpenAPI 설정으로 선언했다.
- 첫 전체 검증은 환경의 `AWS_ENDPOINT_URL_S3` 때문에 기존 S3 프로필 URL 테스트 하나가 실패했다.
  저장소의 이미지 코드와 테스트는 수정하지 않고, 임시 Gradle init 스크립트에서 테스트 JVM의 해당 변수만 제외했다.
  이 환경에서 `sh ./scripts/verify.sh -I /private/tmp/poudy-1010-test-environment.gradle`을 실행해 생성물 드리프트 검사와 전체 빌드를 통과했다.
