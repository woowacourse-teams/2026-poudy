# 회원 저장함

## 목표

저장함을 브라우저 localStorage 에서 회원 계정으로 옮긴다. 저장은 로그인한 회원만 할 수 있다.

## 결정

- 로그인하지 않으면 저장하지 않는다. 저장 버튼을 누르면 로그인 화면으로 보낸다(사용자 결정).
- 기기에 남아 있던 저장 목록은 계정으로 옮기지 않고 버린다(사용자 결정).
- 제품 목록·상세 API 에는 저장 여부를 넣지 않는다. 클라이언트가 저장한 제품 ID 를 따로 받아
  표시한다(사용자 결정).
- 저장함 화면은 ID 와 표시 정보를 한 번에 받는다. ID 만 주는 API 와 나눈다(사용자 결정). 브라우저가
  ID 를 들고 표시 정보만 묻던 `GET /api/storage` 는 쓰는 곳이 없어져 지운다.
- 회원 행을 지우면 저장함도 함께 지운다(`ON DELETE CASCADE`). 30일 보관 후 삭제가 저장함까지 지운다.
- 저장 시각은 `created_at` 하나로 둔다. 저장함의 최근 저장순에 쓴다.
- 저장·해제마다 클라이언트의 변경 번호를 올린다. 조회 중 변경이 생겼으면 오래된 응답을
  버리고, 진행 중인 변경 요청이 끝난 뒤 다시 조회한다. 명시적인 재조회도 진행 중인
  조회를 무효화하므로 로그아웃 후 갱신에 이전 응답을 재사용하지 않는다.
- 저장 훅은 요청 결과 Promise를 반환하며 로그인 화면으로 바로 이동하면 null이다.
  저장함 화면은 낙관적으로 표시를 바꾸고 실패하면 복원한다. 연속 변경의 실패는
  서버 목록으로 동기화하며 조회까지 실패하면 해당 표시 변경을 되돌린다.

## API

- `GET /api/members/me/saved-products/ids`: 저장한 제품 ID, 최근 저장순
- `GET /api/members/me/saved-products`: 저장한 제품의 제품 목록 항목, 최근 저장순
- `PUT /api/members/me/saved-products/{productId}`: 저장. 이미 저장했으면 그대로 두고 204, 없는 제품은 404
- `DELETE /api/members/me/saved-products/{productId}`: 저장 해제. 저장하지 않았어도 204

## 하지 않는 것

- 제품별 저장 회원 수 통계. 나중에 탈퇴하지 않은 회원(`deleted_at is null`)의 저장만 센다.
- 저장함에서 되돌리기를 했을 때 원래 저장 시각 복원. 다시 저장한 시각으로 남는다.

## 검증

- 저장소: 회원별 조회 순서, 중복 저장, 회원 삭제 시 함께 삭제
- API: 회원 세션 필요(401·403), 없는 제품 404, 저장·해제 멱등
- 클라이언트: 로그인 전 저장 시 로그인 화면 이동, 로그인 후 저장·해제가 API 로 반영
