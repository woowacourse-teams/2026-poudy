# 제품 목록 나만의 필터 파라미터 (#952)

## 범위

- 목록·개수 API에 `myFilter`를 추가한다. 기본은 꺼짐이며, 켜면 유효한 회원 세션이 필요하다(없으면 401).
- ProductService가 회원의 필터를 조회하고 ProductQuery가 직접 고른 원하는 성분을 우선해 합친다.
- 선행 명칭 변경 #953/#954가 반영된 최신 dev를 기반으로 한다.
- API 생성물을 갱신하고 클라이언트 주소·요청의 세션 및 캐시 처리를 연결한다.
- 사용자 요청에 따라 버튼·칩·빈 상태·분석 이벤트 등 클라이언트 화면 구현은 제외한다.

## 검증

- 도메인 병합: 원하는 성분 우선, 직접 제외 유지, 중복 제거, 원본 보존.
- API: 켜짐·꺼짐·빈 필터·회원 세션 없는 요청의 401·회원별 결과 분리·목록과 개수 일치.
- 클라이언트: 주소 왕복, 켜짐 요청 세션/no-store, SSR 쿠키 전달.
- 완료 전에 서버 verify.sh와 클라이언트 타입·관련 테스트를 실행한다.

## 결과

- `myFilter` 기본값은 false이며 true일 때만 유효한 회원 세션을 요구한다. 회원 세션이 없거나 비활성/없는 회원이면 401을 반환한다.
- 관리자별 별도 403 분기는 두지 않는다. 일반 목록(false/생략)은 공개 조회를 유지한다.
- 목록·개수는 ProductQuery의 동일한 병합 규칙을 사용한다. 직접 포함 성분 우선, 명시적 제외 중복 제거, 기존 명시적 충돌 거절을 검증했다.
- SSR 목록·장 범위 검사에 세션 쿠키를 전달하고, true 요청은 Next fetch 캐시와 브라우저 목록 복원 캐시를 사용하지 않는다.
- 서버 verify.sh 통과. 클라이언트 관련 72개 테스트·타입 검사·변경 파일 린트 및 포맷 검사 통과.
- UI 버튼·칩·빈 상태·분석 이벤트 구현은 사용자 요청에 따라 제외했다.

- 독립 리뷰에서 확인한 App Router 뒤로가기 SSR seed 재사용 문제를 보완했다. myFilter가 켜진 SSR 첫 장은 렌더링 후 재검증하며, 동일 seed를 복원해도 최신 결과로 바뀌는 회귀 테스트를 추가했다. 이는 개인화 목록의 정확성을 위해 첫 마운트에서 한 번 더 조회하는 선택이다.

- 후속 리뷰의 인증 만료 경로를 수정했다. 재검증·다음 장·이전 장 요청이 401로 실패하면 기존 상품·개수·필터 후보를 폐기하고 실패 상태로 전환한다. 재시도는 시작한 장부터 다시 조회한다. 일반 재검증 서버 오류의 기존 결과 유지 동작은 보존했다. 관련 훅 테스트 19개와 타입·변경 파일 린트 검사를 통과했다.
