# 제품 전체 성분의 주의 기준 API

이슈 #649. #648과 같은 `feat/product-ingredient-cautions` 브랜치에서 제품 상세의 개별 성분에 주의 기준을 추가한다. 사용자 결정에 따라 #649 구현은 백엔드 API 범위로 한정한다.

## 결정과 범위

- `ingredient_group.tag_name`을 추가하고 제외 성분군 6개의 짧은 문구를 채운다. 다른 성분군은 NULL을 허용한다.
- 문구는 향료, 건조 알코올, 자극성 방부제, 설페이트, 실리콘, 합성 색소로 한다.
- 제품 성분마다 필수 `cautions: [{code, label}]` 배열을 반환한다. 해당 기준이 없으면 빈 배열이다.
- 기존 성분군 소속으로 판정하며 제외 성분군 6개만 대상으로 한다. 기준 순서는 제품 상세의 주의 성분군 순서를 따른다.
- API는 기존 성분 순서와 피부 작용 응답을 유지한다.
- 화면의 주의 태그 표시와 디자인 적용은 프론트엔드 팀원의 후속 작업이다. 클라이언트 기능은 #648 완료 상태로 유지한다.
- 공유 API 계약의 새 필수 필드 때문에 클라이언트 목 응답과 기존 테스트 입력의 `cautions`만 보완한다. 배지, 화면 표시, 바텀시트의 성분 판정, 추가 조회 제거는 #649 변경에서 제외한다.

## 커밋 전략

1. 기능 커밋은 마이그레이션, 도메인·응답, 생성 계약과 서버 회귀 테스트를 반영한다. 이미 공개한 클라이언트 변경은 후속 수정 커밋으로 제거한다.
2. 문서 커밋은 최종 범위와 검증 결과를 기록한다.

## 검증

- 제외 성분군의 태그 문구를 DB에서 읽고 누락된 문구를 거절한다.
- 한 성분의 여러 주의 기준, 빈 배열, 구성품별 판정과 일반 성분군 제외를 검증한다.
- 필수 `cautions`, `code`, `label`의 OpenAPI 계약을 확인한다.
- 서버 `verify.sh`와 클라이언트 포맷·린트·타입·전체 테스트·프로덕션 빌드를 통과시킨다.
- #649 기준의 클라이언트 diff에 목 응답과 테스트 입력 보완만 남았는지 확인한다.

## 결과

- V10 마이그레이션으로 기존 주의 성분군 6개의 `tag_name`을 채운다. 실제 마이그레이션을 기존 행에 적용하는 테스트로 문구와 일반 성분군의 NULL을 확인했다.
- 제품 상세의 `cautions`는 기존 성분군 소속에서 계산하며 DB의 태그 문구를 사용한다. 여러 기준 소속, 빈 배열, 일반 성분군 제외, 구성품별 판정과 필수 API 계약을 검증했다.
- 사용자 결정에 따라 #649의 클라이언트 기능 변경을 제거했다. 공유 계약의 필수 필드에 맞춘 목 응답과 테스트 입력만 보완했다.
- `sh ./scripts/verify.sh` 통과: API 생성물 드리프트 없음, 전체 빌드 통과. 서버 소스와 테스트는 변경되지 않아 앞서 통과한 테스트 1,071개의 결과를 재사용했다.
- `pnpm run check` 통과: 린트·포맷·타입 검사, 126개 파일의 테스트 1,129개와 프로덕션 빌드 통과.
- #649 기준 클라이언트 diff에는 `IngredientList.test.tsx`의 테스트 입력과 `mocks/fixtures.ts`의 목 응답에 추가한 필수 `cautions`만 남는다. 클라이언트 기능 파일 7개는 #648 완료 상태와 동일함을 확인했다.
