# 로그인·마이페이지 디자인 반영 회원 API (#683)

> 구현 완료 기록: #683은 2026-10-12에 닫혔다. 아래 「남은 일」은 추가 화면 요구가 있을 때 판단하는 후속 범위다.

- 소유 도메인: `security`(로그인 세션·탈퇴 계정 조회), `member`(탈퇴 회원 조회·피부 타입)
- 연관 경계: `openapi`, `common/api.zod*`(생성물)

## 목표와 범위

로그인·마이페이지 새 디자인이 보여 주는 값 중 지금 API로 받을 수 없는 것을 채운다.

- `GET /api/auth/withdrawn`: 탈퇴한 계정으로 방금 로그인한 사람에게 제공자, 이메일, 탈퇴 시각, 복구를 요청할 수 있는 기한
- `GET /api/auth/registered-account`: 소셜 로그인이 이메일 중복으로 실패한 사람에게 이메일과 먼저 가입한 제공자
- 회원 피부 타입에서 `UNKNOWN` 제거. 저장된 값은 비운다(V11)

하지 않는 것: 즉시 복구. 디자인의 "계정 되살리기"는 지금처럼 복구 요청을 받고 관리자가 승인한다(사용자 결정).
위시리스트·프로필 저장·로그아웃·탈퇴는 지금 API로 충분하다.

## 결정

- 복구는 관리자 승인을 유지한다(사용자 결정). 복구 가능 기한은 "요청하고 승인받아야 하는 기한"이다.
- 기한은 탈퇴 시각 + `poudy.member.retention.max-age`(30일)다. 파기 작업은 그 뒤 첫 새벽에 돌아 이 시각까지는 행이 남는다.
- 이메일은 콜백 URL에 붙이지 않고 세션에 10분 맡긴다. 주소창·방문 기록·접근 로그에 남기지 않기 위해서다. 앱 로그인도
  WebView의 웹 페이지가 같은 콜백 화면으로 보내므로, 웹 OAuth와 앱 로그인이 함께 지나는 `SocialLogin`에서 맡긴다.
- 두 조회는 맡긴 값을 지우지 않는다. 새로고침해도 화면이 보여야 한다. 복구 요청·다른 로그인은 세션을 바꿔 값을 버린다.
- "잘 모르겠어요"는 나중에 피부 타입 설문으로 진단할 자리라 지금은 값을 저장하지 않는다(사용자 결정). 그래서 `UNKNOWN`을 없앤다.

## 검증

- 저장소: 탈퇴한 회원만 탈퇴 정보를 찾음, `UNKNOWN` 피부 타입은 CHECK 제약이 거절
- Service: 기한 = 탈퇴 시각 + 30일, 활성 회원 404
- API: 탈퇴 정보 반복 조회 후 복구 요청하면 404, 맡긴 값 없으면 404, 이메일 중복 세션 조회(웹·앱),
  피부 타입 `UNKNOWN` 400
- 로그인 처리: 이메일 중복이면 기존 세션을 버리고 새 세션에 계정만 맡김
- `sh ./scripts/verify.sh`

## 남은 일

- 이미 복구를 요청한 회원이 다시 로그인하면 세션을 맡기지 않아 탈퇴 정보를 보여 줄 수 없다. 화면이 필요하면 따로 정한다.
