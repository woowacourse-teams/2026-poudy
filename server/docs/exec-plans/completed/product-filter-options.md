# 제품 필터 선택지 (#460)

최신 이슈의 서버 계산 방식을 적용한다. PR #472는 미병합 종료 상태이며 카테고리 다중 선택과
시트 세션 초기화만 검토해 재사용한다. 서버와 클라이언트 동시 변경은 사용자 요청 범위다.

- ProductFilter는 자기 조건을 제외한 불변 조건을 만든다. Products는 검색 후보를 한 번 구하고
  기존 판정과 집계를 재사용한다. 목록 정렬과 검색 로그는 후보별로 반복하지 않는다.
- 현재 페이지 계약은 1부터 시작한다. page=1에서만 filterOptions를 계산·전송한다.
  기존 최상위 집계는 호환성을 위해 유지한다.
- 목록 훅과 캐시는 선택지를 조건별로 보존한다. 시트는 추가 목록 요청 없이 초안과 count만 관리한다.
- 중간 페이지 직접 진입은 그대로 유지하며 후보가 없으면 첫 페이지 이동을 안내한다.
  기존 선택 해제와 초기화는 후보 없이도 가능하다.
- 서버 도메인·HTTP 계약, 클라이언트 캐시·지연 응답·시트 및 목 테스트를 추가한다.
- 500개와 10,000개 카탈로그에서 단일·복합 조건 및 동시 요청의 변경 전후 성능을 측정한다.
- 서버 검증과 클라이언트 check 후 기능 단위로 커밋한다.

## 구현 및 검증 결과

- 서버 도메인·DTO·OpenAPI·공용 스키마와 클라이언트·목을 함께 변경했다.
- 브랜드·카테고리 다중 선택, 피부 타입 교체, 후보에서 빠진 선택 해제, 0개 결과,
  편집·초기화 후 취소와 재진입, 캐시 복원·재검증·지연 응답을 검증했다.
- `sh ./scripts/verify.sh`의 생성물 드리프트·포맷·Checkstyle은 통과했다.
  전체 테스트는 954개 중 947개 통과, 7개 실패다. 변경 전 949개에서도 같은 7개가 실패했다.
  Windows가 `KeywordSnapshotRepository.syncDirectory`의 디렉터리 FileChannel 열기를
  지원하지 않아 발생하는 기존 문제다. 사용자는 WSL 적용을 이번 작업에서 건너뛰도록 했다.
  실패 테스트를 제외하거나 코드를 우회하지 않았다.
- 클라이언트 lint·포맷·타입 검사와 프로덕션 빌드가 통과했다. 기본 병렬 테스트는 CPU 경합으로
  시간 제한을 넘겼다. 사용자 승인에 따라 작업 수만 4개로 제한해 88개 파일·806개 전체 테스트가
  통과했다. 타임아웃과 검증 조건은 유지했다.
- [성능 측정](../../product/filter-options-performance.md)은 500개·10,000개 카탈로그의
  계산·JSON 직렬화 구간을 기준 커밋과 비교한다. HTTP·네트워크·검색 로그는 측정하지 않았다.
- PR #472는 미병합 종료 상태다. 새 구현은 사용자 지정 현재 브랜치 `fix/server-filter-options`에
  기능 단위 커밋으로 남기며 닫힌 PR의 과거 코드를 새 구현으로 간주하지 않는다.
