# 루틴 커밋 성공 분석

클라이언트의 기능 퍼널과 별도로 루틴 생성·가져오기·제품 편집의 서버 커밋을 확인한다.
`RoutineController`는 트랜잭션 서비스가 반환한 뒤 `routine_change_committed`를 요청한다.
이 이벤트는 클라이언트 완료 이벤트와 이름을 나눠 중복 집계하지 않는다.

- 브라우저가 추적 허용 상태이고 실제 SDK 식별자·세션 ID가 준비됐을 때만 분석 헤더를 보낸다.
- 서버 식별자는 인증된 회원 번호의 `member:<id>`이며 요청 헤더의 임의 회원 번호를 신뢰하지 않는다.
- 이름·메모·댓글·이메일을 전송하지 않는다. 변경 종류·루틴 ID·제품 수와 세션 ID만 남긴다.
- 별도 32개 큐와 1초 네트워크 제한을 사용한다. 분석 실패가 사용자 요청에 전파되지 않는다.
- `POSTHOG_PROJECT_TOKEN`·`POSTHOG_HOST`가 없으면 서버 전송은 꺼진다. 클라이언트 퍼널은 기존 설정으로 동작한다.

2026-11-08 구현·검증 완료. 전송 형식·비활성화·전송 실패·추적 거부·인증된 식별자 사용 테스트를 추가했다.
로컬 전용 데이터베이스에서 `sh ./scripts/verify.sh`가 통과했으며 OpenAPI·TypeScript 생성물 드리프트는 없다.
