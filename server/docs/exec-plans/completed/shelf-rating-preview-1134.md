# 선반 평가 미리보기 API (#1134)

작성일: 2026-11-06. 상태: 구현·검증 완료.

## 범위

- 회원은 저장된 선반, 비로그인은 요청 본문의 선반에서 대상 제품의 호불호만 바꿔 계산한다.
- 평가 없음·좋음·나쁨 결과와 제품 자체의 주의 성분을 함께 반환한다. 없는 선반 제품은 임시로 담아 계산한다.
- 피부 타입이 없는 회원에게만 모든 피부 주의 후보로 넓힌 나쁨 결과를 별도 필드로 반환한다.
- 기존 `RatedProducts`·`SuspectIngredients` 규칙을 재사용하고 선반·직전 분석·필터·평가 이력에는 쓰지 않는다.
- 클라이언트 화면 구현은 #1125의 후속 작업이다.

## 계산 경계

회원의 실제 저장은 호불호가 바뀌거나 제품을 추가할 때 분석 스냅샷을 갱신한다. 미리보기에서도
그 갱신을 메모리 안에서만 계산해 `isNew`까지 저장 후 응답과 맞춘다. 같은 호불호를 다시 고른
경우에는 저장된 스냅샷의 표시를 그대로 쓴다. `inFilter`는 현재 회원 필터로 판단하고,
비로그인은 두 표시를 모두 `false`로 둔다.

## 진행 순서

1. 기존 stash의 도메인·서비스·HTTP 초안을 메인 작업 폴더에 복원한다.
2. 세 평가에 대한 저장 결과 일치, 프로필별 후보 범위, 읽기 전용 동작과 입력 오류를 통합 테스트로 검증한다.
3. 오류 코드와 nullable 응답 계약을 OpenAPI에 반영하고 공통 TypeScript API 생성물을 갱신한다.
4. `scripts/verify.sh`로 전체 검증한다.

## 검증 결과

- 회원·비로그인 미리보기 통합 테스트 31개 통과. 세 평가를 실제 저장·분석 응답과 비교하고,
  피부 타입·민감성별 후보, 좋은 평가의 성분 제외, 제품 자체 주의 성분 유지와 입력 오류를 확인했다.
- 선반·직전 분석·필터·평가 이력의 행과 수정 시각이 미리보기 전후 같고, 반복 조회 결과도 같다.
- OpenAPI의 공개·인증 경로, 제품 ID 검증과 필수 nullable 응답 계약을 테스트했다.
- `scripts/verify.sh` 통과. 서버 테스트 2,034개 성공, 생성물 재생성 결과 차이 없음.
  테스트 DB 주소와 인증값은 테스트 실행 환경에 전달했다.
- 갱신된 공통 API 타입으로 클라이언트 `typecheck` 통과.

## 리뷰 반영

- 비로그인 대상 제품 탐색은 기존 `Products.findById`에 맡기고 테스트의 삼항 연산자를 제거했다.
- 오류 설정을 그대로 확인하는 중복 테스트를 제거했다. 피부 조건 조합 중 기존 도메인 테스트와
  겹치는 세 경우를 줄이고, 주의 성분 응답 검증은 좋은 평가 시나리오에 합쳤다.
