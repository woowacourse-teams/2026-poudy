# 선택한 제품 필터 이름 응답 (#1078)

## 계약과 범위

- 선택 이름 응답 추가는 기존 후보 계산과 목록·count의 필터 판정을 유지한다.
  함께 포함한 마크 필터 변경은 아래 추가 작업 범위에 따른다.
- 첫 페이지에만 `selectedFilters: { brands, categories }`를 제공한다. 각 항목은 ID·이름이며,
  후보나 제품 결과와 무관하게 존재하는 선택을 요청 순서대로 반환한다. 카테고리는 평탄한 목록이다.
- 없는 ID는 선택 이름 목록에서 생략한다. 검색 조건을 제거하거나 400으로 거절하지 않으며,
  `unknown…Ids` 같은 별도 필드도 추가하지 않는다.
- 첫 페이지의 기존 브랜드 batch 조회에 선택 ID를 합치고, 이미 읽은 카테고리를 재사용한다.
- 클라이언트는 계약 문서·목 응답·생성물 호환성만 맞춘다. 시트·칩·훅·캐시의 소비 동작은 #1079 범위다.

## 확인된 결과

- PostgreSQL 17.11의 작업 전용 DB에서 HTTP·후보·조회 횟수·서비스·아키텍처 검증 통과.
  새 독립 HTTP 테스트는 8개이며, 목록 첫 페이지 5회·후속 페이지 3회 조회를 유지한다.
- `sh ./scripts/verify.sh --console=plain` 통과. 생성물 드리프트·포맷·Checkstyle·전체 빌드를
  검증했고, 현재 작업 트리의 서버 254개 suite·1,903개 테스트의 실패·오류·건너뜀은 모두 0개다.
- OpenAPI와 Zod 타입은 공식 태스크로 생성했다. `selectedFilters`는 후속 페이지 생략을 표현하는
  optional 필드이고 내부 `brands`·`categories`와 ID·이름은 필수다.
- 클라이언트 변경은 목 응답·목 계약 테스트·계약 문서뿐이다. UI·훅·캐시는 수정하지 않았다.
- 클라이언트 경로 타입 생성·타입 검사·lint 통과. 기존 lint 경고 49개는 유지한다.
- 클라이언트 전체 200개 파일·1,713개 테스트와 staging API를 사용하는 프로덕션 빌드 통과.
- 로컬 CLI 전체 포맷 검사는 기존 CRLF 파일을 경고한다. Git 원본과 LF 정규화본을 대조했고,
  Linux CI와 같은 LF 기준으로 전체 대상 675개 파일의 Prettier 검사를 통과했다.
- 검증용 PostgreSQL 인스턴스를 종료했다. 커밋·푸시·배포는 수행하지 않았다.

## 코드 리뷰와 리팩터링

- HEAD 대비 working tree 변경을 API·저장소·직렬화·생성물·목 계약까지 리뷰했다.
  독립 리뷰의 원본 및 리팩터링 판정은 `No actionable findings`, `correct`, confidence 0.95다.
- 저장소 내부 `Facets`만 정리했다. 브랜드·카테고리의 대표 상태를 읽기 전용
  `LinkedHashMap`으로 두고, 후보 표시는 순회 view를, 선택 이름은 직접 ID 조회를 사용한다.
  목록에서 임시 Map으로 변환하던 선택 조회 경로를 제거했으며 DTO나 다른 도메인으로 책임을 옮기지 않았다.
- 단순 조회 결과를 전달하는 record와 DTO 경계의 ID·이름 접근은 유지했다.
  API·SQL·조회 횟수·없는 ID 처리·패키지 의존 방향과 클라이언트 코드는 변경하지 않았다.
- 후보의 표시 순서와 선택의 요청 순서를 함께 검증하는 HTTP 테스트를 추가했다.
  후보·선택의 순서와 아키텍처 순환 의존 검사가 통과했다.
- 리팩터링 후 `sh ./scripts/verify.sh --console=plain` 재실행도 통과했다.
  생성물 드리프트가 없고 서버 전체 테스트·정적 검사·빌드가 통과했으며, 작업 전용 DB를 종료했다.
  클라이언트·공용 타입은 이번 리팩터링에서 바뀌지 않아 직전 호환성 검증 결과를 유지한다.

## 테스트 통합

- 별도 HTTP 테스트를 10개에서 8개로 줄였다. 선택 없음은 기존 첫 페이지·후속 페이지 계약 테스트에,
  부모 카테고리 선택은 후보에서 빠진 카테고리 테스트에 합쳤다.
- 부모·자식의 불필요한 추가, 요청 순서, 빈 배열, 필드 생략 검증은 유지하며 중복 요청 두 번을 제거했다.
- 동시 Gradle 실행의 결과 파일 잠금과 산출물 정리 영향을 피하려고 임시 init script로
  저장소 밖 ASCII 경로의 표준 `build/classes` 구조와 별도 프로젝트 캐시를 사용했다.
  검사 항목·조건과 저장소 빌드 설정은 변경하지 않았고, 동일한 `verify.sh` 전체 검증이 통과했다.

## 마크 필터 추가 작업과 후속 리뷰

- 마크 코드는 유지하고 자외선 차단 유형(`UV_FILTER_TYPE`)과 제품 특성(`PRODUCT_FEATURE`)으로
  필터 그룹을 정리했다. 자외선 차단 유형은 OR, 제품 특성의 이지워시·워터프루프·다이소는 AND,
  두 그룹도 AND다. 옵션별 개수는 자기 그룹의 조건 전체를 해제한 후보에서 집계한다.
- HEAD 대비 작업 트리와 직접 연결된 생성물·목 계약을 리뷰했다. 별도 독립 리뷰와
  리팩터링 후 재검토 모두 `No actionable findings`, `correct`이며 최종 confidence는 0.95다.
- 집계와 선택 조회 행동을 가진 저장소 내부 `Facets`를 `private final` 상태의 일반 클래스로
  바꾸고, 순서 보존 인덱스와 기존 일괄 조회를 유지했다. 순수 전달용 record와 응답 DTO는 유지했다.
- 마크 옵션 조립은 각 `MarkFilterGroup` 인스턴스에 두어 중첩된 정적 조립을 정리했다.
  그룹·옵션 순서, 양수 후보와 선택값 유지, 빈 그룹 제외 동작은 같다.
- 마크 필터 테스트는 중복된 쌍별 사례를 통합해 15개에서 12개로 줄였다. 빈 교집합,
  제품 특성 AND·유형 OR, 세 특성 중 하나라도 누락된 제품의 배제, 중복 선택과 집계는 검증한다.
  선택 이름의 핵심 HTTP 테스트 8개는 유지했다.
- 기존 조회 횟수 테스트에 후보 밖 선택 브랜드를 포함했다. 선택 이름을 함께 제공해도 첫 페이지
  다섯 조회를 유지하고, 후속 페이지에서는 정의 조회를 생략하는 것을 검증한다.
- 관련 응답·마크·조회 횟수·아키텍처 테스트 32개와 `sh ./scripts/verify.sh --console=plain`이
  통과했다. 서버 전체 테스트 1,904개, 실패 0개이며 생성물 드리프트·포맷·Checkstyle·빌드와
  패키지 순환 검사도 통과했다. 이번 리팩터링으로 공개 응답과 조회 규칙은 바뀌지 않았다.
- 추가 보안 리뷰에서도 실행 가능한 결함은 발견하지 못했다. 선택 응답은 기존 공개 카탈로그의
  ID·이름만 제공하고, 사용자별 필터 인증과 JDBC 값 바인딩을 유지한다. 신규 비밀정보나
  외부 전송 경로는 추가하지 않았다.
- #1081은 최신 마크 계약으로 본문을 갱신하고 클라이언트 UI 연동 이슈로 열어둔다.
  기존 클라이언트 PR #1084가 변경된 정책을 반영해야 하며, 이번 백엔드 PR의 종료 대상은 #1078이다.
