# 성분 상세 리뷰 지적 반영

## 목표

성분 검색과 상세 조회가 같은 실제 데이터를 사용하게 하고, 출처와 제외 성분군을 원천
데이터 의미대로 반환한다.

## 착수 시 상태

- 상세 조회는 JSON 기반 실제 성분을 반환하지만 검색은 샘플 응답을 반환한다.
- 출처 문자열은 모든 세미콜론에서 분리되어 인용문 내부 세미콜론도 손상된다.
- 합성 색소 판정은 정확한 `X색N호` 이름만 받아 공식 명칭 변형을 누락한다.

## 제약

- Controller는 응답 변환만 하고 검색 규칙과 조회 조합은 Domain과 Service가 담당한다.
- 런타임에서는 기존 JSON 데이터를 읽고 별도 Excel 처리를 추가하지 않는다.
- OpenAPI 생성은 gitignored 운영 JSON에 의존하지 않고 커밋된 테스트 fixture로 재현한다.
- 기존 미커밋 백엔드 작업을 보존한다.

## 단계

1. 여러 성분의 검색 규칙을 일급 컬렉션에 구현하고 Repository·Service·Controller를 연결한다.
2. 괄호 안 세미콜론을 보존하는 출처 분리를 구현한다.
3. 공식 색소명 접두사와 `호의(n)` 변형을 포함하도록 합성 색소 판정을 보강한다.
4. 각 회귀 조건을 테스트하고 전체 서버 검증을 실행한다.

## 검증

- `sh ./scripts/test.sh`
- `sh ./scripts/verify.sh`
- 실제 성분 데이터의 검색 ID, 내부 세미콜론 출처, 합성 색소 명칭 변형을 대조한다.

## 결정

- 검색은 한글명, 영문명과 별칭의 부분 일치로 제공하고 영문 대소문자를 구분하지 않는다.
- 출처 구분자는 괄호 깊이가 0일 때의 세미콜론으로 한정한다.
- 공식 한글 색소명 형식과 그 등록 성분에서 얻은 CI 코드로 판정하며, 모든 CI 원료를 합성
  색소로 보지는 않는다.

## 결과

- 검색과 상세 조회가 같은 JSON 성분과 태그 ID를 사용한다.
- 괄호 내부의 세미콜론을 보존하면서 출처 경계만 분리한다.
- 합성 색소 공식 명칭의 접두사형과 `호의(n)` 접미사형을 판정하고, 등록 색소와 같은 CI
  코드를 가진 별도 표기도 포함한다.
- 확정된 검색·출처·합성 색소 계약을 `ARCHITECTURE.md`에 반영했다.
- OpenAPI 생성용 앱은 테스트 fixture를 우선해 깨끗한 CI에서도 기동한다.
- `sh ./scripts/test.sh`와 `sh ./scripts/verify.sh`가 통과했다.
