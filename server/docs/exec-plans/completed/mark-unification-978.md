# 제품 마크 통합 (#978)

상태: 서버 구현·검증 완료 (2026-10-28). 클라이언트 계약 연동은 남아 있다.

## 목표

속성·마크를 `mark(code)`와 `product_mark`로 통합한다. 표시명·필터 그룹·목록 표시·선케어
적용 범위를 Java 코드에서 관리한다. 정책을 위한 DB 테이블은 두지 않는다.

## 구현 순서

1. Mark·필터 그룹·제품 마크 조합을 모델링하고 요청/선택지 계약을 교체한다.
2. 새 마이그레이션으로 테이블을 통합하고 검색 함수에 코드 정의를 전달한다.
3. 조회·집계·목록 표시와 쓰기 트랜잭션을 연결한다.
4. 필터/검색/스키마/동시성 회귀 테스트, 문서·API 생성물을 갱신한다.
5. `scripts/verify.sh`를 통과시킨다.

## 결정

- 다이소만 모든 카테고리에 허용하고 목록에 표시한다. 다른 다섯 마크는 선케어에만 허용한다.
- 같은 필터 그룹 OR, 그룹 간 AND; 검색 토큰과 검색/필터 조건은 AND다.
- 빈 값·미정의 코드·다이소 필터는 400, 중복 필터는 제거한다.
- 모든 쓰기는 제품 단위로 잠그고 최종 상태를 검증한다. 데이터 수정용 관리 API는 추가하지 않는다.
- 과거 Flyway 파일은 변경하지 않고 새 버전에서 최종 스키마로 전환한다. 구버전 호환 계층은 추가하지 않는다.

## 검증 기록

- 임시 PostgreSQL 16.15에서 `sh ./scripts/verify.sh --console=plain` 통과.
- 전체 1,734개 테스트 통과. 포맷·Checkstyle·아키텍처 검사·전체 빌드 통과.
- OpenAPI와 공통 TypeScript 생성물을 갱신하고 `marks` 요청 및 `markGroups` 응답을 확인했다.
- 필터 AND/OR·중복 제거·잘못된 입력·자기 그룹 제외 집계·선택값 0건 유지와 검색을 검증했다.
- 제품 행 잠금으로 배타적인 마크 추가와 카테고리 변경 경쟁을 검증했다.
- 기존 콘텐츠 수정 시각 트리거를 통합 테이블에 맞췄다. 마크 기준 테이블은 시각 컬럼을 참조하지 않는다.
- 과거 검색 마이그레이션 회귀 테스트는 독립된 해당 버전 스키마에서 수행한다.
- 쓰기 동시성 테스트는 공유 제품의 수정 시각을 복원한다.
- 임시 DB의 기본 연결 상한(100)이 전체 테스트 컨텍스트에 부족해 검증용 DB만 300으로 설정했다.

## 후속 코드 리뷰·리팩터링 (2026-10-27)

- 대상: HEAD 대비 서버 작업 트리 전체(신규 파일 포함)와 연결된 공통 생성물·소비자.
- 서버 리뷰 결과: No actionable findings. Verdict: correct. Confidence: 0.95.
- 독립 검토자가 동일 범위를 읽기 전용으로 확인했고, 리팩터링 이후에도 재검토했다.
- 필터 문자열 변환은 DTO, 선택값 중복 제거·필터 가능 여부 검증은 `ProductQuery`가 담당한다.
  `Mark → String → Mark` 재변환과 중복 검증을 제거했다.
- 마크 추가용 컬렉션 조립·조합 검증은 `ProductMarks.adding`으로 모았다. Writer는 검증된
  `ProductMarks`만 저장하며, `codes()`는 SQL 직렬화 경계에서 사용한다.
- 자외선 그룹 소속은 `contains` 행동으로 판단한다. 저장소 직렬화에 필요한 그룹 원소 접근은 유지한다.
- 마크 옵션 DTO를 별도 파일로 분리하고 OpenAPI `Option` 이름과 JSON 계약은 유지했다.
- `sh ./scripts/verify.sh --console=plain` 통과: 전체 1,738개 테스트, 포맷·Checkstyle·아키텍처·빌드 통과.
  아키텍처 검사는 전체 기능·계층·세부 패키지의 직접·간접 순환을 포함한다.
- 리팩터링 전후 `openapi.json`, `api.zod.ts`, `api.zod.types.d.ts`의 SHA-256이 동일하다.
- 소비자 확인: 클라이언트의 `tsc --noEmit --incremental false`는 16개 타입 오류로 실패했다.
  기존 필터 상태·URL 처리와 테스트 fixture에 `marks`·`markGroups` 계약 반영이 필요하다.
  이 문제는 이번 리팩터링으로 API가 추가 변경된 결과가 아니라 #978 계약 전환의 남은 연동 항목이다.
  `server/AGENTS.md`의 서버 외 수정 제한에 따라 클라이언트 소스는 변경하지 않았다.

## 마크 SQL 파라미터 정리 (2026-10-28)

- `MarkSql`을 Spring Bean이 아닌 `MarkSqlParameters` 변환 클래스로 바꾸고 저장소 생성자 주입을 제거했다.
- 필터 마크 코드와 그룹의 쌍을 한 번 만들고, 같은 매핑에서 SQL 배열 두 개를 생성한다.
- 동등 표기 검색의 임시 표시명은 각 테스트 범위에서만 적용하며 Spring Bean 재정의는 제거했다.
- 검색·필터 회귀 테스트와 `sh ./scripts/verify.sh --console=plain`을 통과했다.
  전체 1,738개 테스트가 통과했고 API 생성물의 SHA-256은 변경 전과 동일하다.

## 저장 제약과 필터 그룹 분리 (2026-10-28)

- `Mark.isUvFilterType()`이 마크의 자외선 차단 유형 여부를 판단한다.
- `ProductMarks`는 이 행동으로 배타성을 검증하며 `MarkFilterGroup`을 참조하지 않는다.
  필터 그룹 구성과 제품에 저장할 수 있는 조합의 책임을 분리했다.
- 세 유형의 모든 쌍을 생성·추가 경로에서 거절하고, 각 유형과 나머지 마크의 조합은 허용하는 테스트를 추가했다.
- 도메인 테스트와 임시 PostgreSQL 17.11에서의 `sh ./scripts/verify.sh --console=plain` 통과.
  전체 1,744개 테스트·포맷·Checkstyle·패키지 순환 검사를 통과했고 API 생성물의 SHA-256은 동일하다.

## 핵심 테스트 정리 (2026-10-28)

- 입력 오류·필터 AND/OR·자기 그룹 제외 집계·선택값 0건 유지·표시 정책은 API 테스트에서 검증한다.
- 카테고리 제한·원자성·동시성은 Writer 테스트에 두고, 도메인에는 조합 규칙과 입력 불변성을 남긴다.
- API와 겹치는 enum 검증, 일반 페이지 조회 재검증, 인덱스 이름·OpenAPI 세부 구조·레거시 함수 분리 검증을 제거했다.
  기동 실패 진단은 대표 실패 사례 하나로 유지했다. 기존 공용 검색 회귀 테스트는 유지한다.
- 상세 응답은 실제 마크 여러 개와 빈 배열을 검증하도록 보완했다.
- 중복·세부 구현 검증 24개를 줄였다. `sh ./scripts/verify.sh --console=plain`에서
  전체 1,723개 테스트·포맷·Checkstyle·아키텍처 검사가 통과했고 API 생성물은 동일하다.

## 기동 검증 정책 조정 (2026-10-28)

- 기동 검증은 DB 마크 코드와 enum 일치 여부로 한정한다.
- 기존 제품 전체 검사와 제품별 오류를 감싸던 진단 로직은 제거했다. 한 제품의 조합 오류가 전체 서버 기동을 막지 않는다.
- 제품별 카테고리·조합 제약과 제품 행 잠금은 `ProductMarkWriter`의 저장 경로에서 유지한다.
- 코드 누락 시 실패와 기존 제품의 조합 오류를 무시하는 핵심 테스트 두 개로 정책을 검증했다.
  `sh ./scripts/verify.sh --console=plain`에서 전체 1,724개 테스트와 빌드·아키텍처 검사가 통과했다.
