# 선반 성분 분석 도메인 리팩터링

## 목표와 승인 범위

PR #758과 후속 수정에서 도메인 판단과 내부 상태의 소유권을 정리한다.

- `AnalysisSnapshot`이 변경 여부와 새 성분 표시를 함께 결정하고 서비스는 변경된 결과만 저장한다.
- `SkinCautions`, `SuspectEvidence`는 불변 클래스로 바꾸고 내부 상태 접근자를 제거한다.
- `SuspectEvidence`의 개수 범위 검증은 집계 과정이 이미 보장하므로 제거한다.
- `ProductIngredients`를 제거하고 제품 한 개의 성분 포함·순서 판단은 `Product`로 옮긴다.
- 여러 제품의 집계는 분석 도메인에 남기고, `Shelf`는 기존 List 구조를 유지한다.

## 유지할 계약

- API 응답, 점수 계산, 동률 정렬, 구성품을 합친 성분 순서
- 성분 목록이 같을 때 저장을 생략하고 기존 `isNew`를 유지하는 동작
- DB 스키마, 회원별 변경 직렬화, 누락 성분군 조회 실패
- 기존 회원의 첫 조회 `isNew` 처리는 이번 범위에서 제외한다.

## 검증

- snapshot의 변경·유지·재등장·빈 결과 전이와 입력 변경 이후의 안정성
- 피부 조건에 따른 후보 선택, 점수와 상쇄 판단
- 제품의 구성품 간 중복 제거·포함 여부·합친 순서와 분석 정렬
- 기존 선반 API, 누락 성분군, 등록·수정·삭제 동시성 테스트
- 관련 테스트 후 `sh ./scripts/verify.sh`

## 결과

- 승인된 책임 이동과 중복 상태·검증 제거를 완료했다.
- 내부 상태 대신 새 성분 판단, 후보 선택, 제품 성분 포함·순서를 검증하도록 테스트를 바꿨다.
- 임시 복제본과 전용 DB에서 관련 선반 테스트와 `ProductTest`를 통과했다.
- `sh ./scripts/verify.sh`를 통과했다. 테스트 1,263개가 모두 성공했고 API 생성물 변경은 없다.
