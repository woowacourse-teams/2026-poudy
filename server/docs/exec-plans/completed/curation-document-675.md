## 블록 계약

기존 id(UUID), type, spacingTop, spacingBottom에 label과 query를 추가한다.
브랜드·성분별 블록 타입은 나누지 않는다. 아래 ID는 형식 설명용 예시다.

```json
{
  "id": "44444444-4444-4444-8444-444444444444",
  "type": "PRODUCT_LINK",
  "spacingTop": 0,
  "spacingBottom": 24,
  "label": "레티놀·레티노이드 제품 보러가기",
  "query": {
    "keyword": null,
    "brandIds": [],
    "categoryIds": [],
    "includeIngredientIds": [],
    "includeGroupCodes": ["RETINOIDS"]
  }
}
```

- query는 위 다섯 필드를 가진 명시적인 타입이다. keyword 미지정은 NULL, 배열 미지정은 []로 응답한다.
- label은 일반 텍스트 최대 100자, keyword는 기존 검색어 최대 100자 규칙을 따른다.
- 조건은 하나 이상 필요하다. ID·코드의 타입, 양수, 중복·배열 상한·현재 참조를 서버에서 검증한다.
  배열 상한은 필드별 100개다. 기존 제품 검색 API에는 배열 상한이 없지만,
  편집하는 링크 문서의 조회 조건과 URL 크기를 제한하기 위해 별도 상한을 둔다.
- 조건의 의미와 AND 결합은 기존 제품 검색을 따른다. 포함 성분 ID는 모두 포함,
  각 성분군은 소속 성분을 하나라도 포함해야 한다. 빠른 제외 성분군은 포함 조건으로 받지 않는다.
- page / size / sort / href / 외부 URL은 문서에 저장하지 않는다.

## 공개 조회와 화면 이동

- 상세 응답의 판별 유니온에 PRODUCT_LINK를 추가하고 OpenAPI·common 생성 타입을 갱신한다.
- 클라이언트는 받은 조건을 EMPTY_FILTER에 반영해 기존 serializeFilter로 `/products?...`를 만든다.
  이전 검색 조건을 섞지 않고 첫 페이지·기본 정렬로 연다. 문구는 일반 텍스트로 렌더링한다.
- 기존 제품 목록과 조회 API를 사용한다. 별도 리다이렉트 API는 만들지 않는다.
- 유효한 조건에 제품이 0개인 것은 정상 상태다. 링크를 유지하고 목록의 빈 결과를 보여준다.
- 조회 조건의 참조가 무효이면 해당 링크만 공개 응답에서 제외하고 ID·코드를 기록한다.
  조건을 제거해 더 넓은 결과로 보내지 않는다. DB 장애는 참조 부재로 처리하지 않는다.
- 서버·클라이언트가 새 타입을 모두 지원한 뒤 실제 큐레이션 데이터에 새 블록을 추가한다.

## 검증 결과

- `sh ./scripts/verify.sh`: 리팩터링 후에도 생성물 드리프트 없음, 전체 빌드·검사 및 서버 테스트 1,122개 통과.
- 클라이언트 린트·포맷·타입 검사 통과. 전체 포맷은 Windows 체크아웃의 CRLF를
  LF로 정규화해 검사했고, 기능과 무관한 파일의 줄바꿈은 원복했다.
- `pnpm exec vitest run --maxWorkers=2`: 클라이언트 테스트 1,195개 통과.
  기본 병렬 실행에서 기존 필터 시트 테스트가 5초 제한을 넘겨 동시 실행 수만 제한했다.
  테스트 시간 제한과 검증 내용은 바꾸지 않았다.
- `pnpm run build`: 임시 로컬 API를 연결한 프로덕션 빌드 통과.
- 목 응답을 끈 standalone 서버의 `/curations/12` HTML에서 PRODUCT_LINK 문구와
  `/products?brandIds=1` 링크를 확인했다. 검증 데이터는 임시 DB에만 넣었다.
- 실제 큐레이션 데이터의 새 블록 추가는 서버·클라이언트 배포 이후에 진행한다.

## 리팩터링 및 코드 리뷰

- 조건 검증과 참조 판단을 소유하는 `CurationProductLinkQuery`를 불변 클래스로 정리했다.
  검증을 모두 마친 뒤 상태를 할당하고, 저장소·운영 로그·DTO 경계에 필요한 읽기 접근자만 유지했다.
- 상세 서비스의 제품 조회·누락 로그·링크 참조 검증 단계를 나누고 제품 ID를 한 번만 추출한다.
  링크가 없는 상세는 이미 조립한 결과를 그대로 반환한다.
- 입력 컬렉션 변경 이후에도 참조 판단이 유지되고, 복합 조건의 참조 하나라도 없으면
  링크 전체가 무효가 되는 행동을 검증했다.
- HEAD `d133bc95` 대비 staged·unstaged·untracked 변경 전체를 코드와 계약으로 검토했다.
  독립 리뷰를 포함해 실행 가능한 결함을 발견하지 못했다. API·저장 문서 형태는 유지하며
  재생성한 OpenAPI·공통 타입의 해시도 리팩터링 전과 동일하다.
