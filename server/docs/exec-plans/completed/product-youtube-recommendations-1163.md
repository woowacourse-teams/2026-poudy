# 제품 상세의 유튜브 추천 응답 (#1163)

## 목표와 범위

제품 상세 API에 유튜버별 추천 횟수와 최신 추천 영상 1개(id/title/nullable thumbnailUrl)를 추가한다.
여러 유튜버를 지원하고 추천이 없으면 빈 배열을 반환한다. 발언 상세와 프론트 화면은 범위에서 제외한다.
기존 테이블과 최근 1년·공개 설정·명확한 추천·영상별 1회 집계 기준을 유지한다.

## 설계

- 기존 추천 SQL 판정 조건을 저장소 내부에서 공유한다.
- 제품 ID로 좁힌 영상에 채널별 count와 row_number를 적용한다. 전체 횟수를 계산한 뒤 최신 1개를 선택한다.
  게시일이 같으면 영상 ID 오름차순, 채널은 기존 display_order와 ID 순으로 정렬한다.
- product.domain이 조회 인터페이스와 결과 타입을 소유하고 youtube가 구현해 기능 간 순환을 방지한다.
- 제품 상세 조회 트랜잭션 안의 추천 조회에는 NESTED 세이브포인트를 사용한다.
  추천 SQL 실패 시 해당 조회만 롤백하고 로그와 빈 목록으로 기본 상세 응답을 유지한다.
- API 계약과 공통 타입은 생성 도구로 갱신한다. 스키마 변경은 없다.

## 커밋과 검증

1. 추천 판정 공유, 제품별 집계·최신 영상 조회와 회귀 테스트.
2. 제품 상세 조합·응답, 장애 격리와 API 테스트, OpenAPI/공통 타입 및 문서 갱신.

전용 PostgreSQL DB에서 추천/비추천/혼합/중립/불확실, 기간·공개 조건, 다채널, 반복 발언,
최신 영상과 전체 횟수, nullable 썸네일, SQL 실패 후 상세 응답을 검증한다.
마지막에 server/scripts/verify.sh를 통과시킨다.

## 진행

- 제품별 추천 조회 및 기존 유튜브 API·아키텍처 테스트 통과. Java 포맷과 Checkstyle 통과.

- 제품 상세 API와 OpenAPI 계약, 실제 SQL 오류 후 세이브포인트 복구를 포함한 관련 테스트 78개 통과.
- OpenAPI 및 공통 Zod/TypeScript 타입 생성 완료. `server/scripts/verify.sh` 통과:
  전체 2067개 테스트, 실패 0개, 오류 0개, 건너뜀 0개.
- 검증 DB는 기존 개발 DB와 분리된 PostgreSQL 18 전용 컨테이너를 사용했다.
- 프론트 파일은 범위에서 제외했다. 새 필수 필드 `youtubeRecommendations` 때문에
  클라이언트의 `ProductDetailResponse` 목 객체에도 빈 배열 등 계약에 맞는 값을 추가해야 한다.
