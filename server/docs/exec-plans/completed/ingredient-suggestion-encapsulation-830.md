# 성분 검색 제안 캡슐화 (#830)

PR #889의 성분 자동완성 경로를 사용자에게 제안한 범위로 리팩터링한다.

## 책임과 유지할 계약

- `MatchRange`가 원문 안에 들어가는 범위인지 판단하고, `IngredientSuggestion`은 기존 예외와 메시지를 유지한다.
- `IngredientSuggestion`을 불변 클래스로 바꾸고, 생성자는 검증 뒤 필드를 할당한다.
- 서비스는 `ingredientId()`로 일괄 조회를 연결한다. 여러 기능의 조회 결과를 결합하는 책임은 서비스에 둔다.
- DTO 변환에 필요한 접근자는 유지한다. JSON, 검색 순서, 빈 배열, 조회 횟수와 트랜잭션은 바꾸지 않는다.
- 데이터 전달용 `ExcludeCodeSummary`와 `IngredientSuggestions`는 record로 유지한다.

## 진행과 검증

- [x] 생성 위치, 조회 서비스, DTO와 관련 테스트를 확인한다.
- [x] 연결된 기능의 소스 의존 경로에서 순환이 없음을 확인한다.
- [x] 승인한 책임 이동과 불변 클래스 전환을 구현한다.
- [x] 범위 경계값과 성분군 교체·입력 변경에 관한 테스트를 추가한다.
- [x] 관련 테스트와 `ArchitectureTest`를 실행한다.
- [x] `sh ./scripts/verify.sh`로 API 생성물과 전체 빌드를 검증한다.

범위 끝과 UTF-16 원문 경계, 기존 예외 메시지, 성분군 교체 이후의 검색 정보와 입력 목록 변경에 대한 불변성을
검증한다. 성분 값과 검색 정보의 접근자는 DTO 변환에, `ingredientId()`는 서비스의 일괄 조회 연결에 사용한다.
카탈로그 조회나 DTO 조립 책임을 핵심 객체에 옮기지 않았다.

관련 테스트 77개와 공식 `verify.sh`의 전체 테스트 1,506개가 통과했다. API 생성물은 기존 파일과 일치했고,
Spotless·Checkstyle·전체 빌드도 통과했다. `ArchitectureTest`의 전체 패키지·계층·기능 순환 검사와 변경 도메인 및
서비스에서 도달하는 9개 패키지의 소스 의존 경로에서 순환을 찾지 못했다. 변경한 Java 코드에서 삼항 연산자와
도메인의 `switch`, 서비스의 `ingredient().id()` 탐색이 남지 않았음을 확인했다.

검증은 별도 PostgreSQL 컨테이너에서 실행해 다른 로컬 테스트의 DB와 연결 수를 공유하지 않았다.

상품 검색 제안과 `TextMatch`의 기존 범위 비교는 승인 범위 밖이므로 이번 작업에서 변경하지 않는다.
