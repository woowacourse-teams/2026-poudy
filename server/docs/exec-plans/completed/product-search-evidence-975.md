## 목표와 결과

입력 분석 → 후보와 확인한 사실 → 일치 근거 완성 → 포함·품질 정책 → 요청 필터·정렬·개수·페이지
→ 표시의 입출력을 분리했다. 분석은 PostgreSQL에 유지하고 MV·인덱스 확장, Java 이전,
검색엔진 도입과 검색 정책 변경은 하지 않았다.

| 순서 | 완료한 경계 |
| --- | --- |
| A | 이름·메타데이터는 일치 종류, 결합은 조각·방향·완전/접두 일치 사실을 반환한다. 품질과 최선 분할 선택은 별도 정책 함수가 소유한다. |
| B | 후보가 ID와 메타데이터·결합 사실을 전달한다. 근거 완성 단계는 이름 필드만 보완하며 메타데이터를 재검색하지 않는다. |
| C | 목록·개수는 `search_product_results`의 점수 행에 요청 필터를 적용한 뒤 최종 정렬·개수·페이지·선택지를 계산한다. 전체 JSON 생성·해체를 제거했다. |
| D | 제안·연관검색어는 선택한 페이지의 상세 근거로 표시한다. 표시 필드·원문 조각·강조 선택이 검색 포함과 순위를 바꾸지 않는다. |
| E | 분석 배열은 요청당 하나, 전체 결과는 간결한 점수, 상세 근거는 페이지에만 조립한다. 후보 ID 중복과 불필요한 결합 조회·재계획 비용을 줄였다. |

기존 공개 함수와 타입은 호환 어댑터로 유지한다. `search_products_v2`는 마지막에 JSON을 만들며,
limit=null의 전체 표시 계약은 그대로다. `match_evidence`는 후보 전체의 상세를 검사하는 호환 진입점이다.
현재 단계별 호출과 수정 지점은 [제품 검색 구조](../../product/product-search.md)에 있다.

새 테스트는 사실의 종류·결합 방향, 페이지 상세 범위, 표시 변경·빈 표시의 순위 독립성,

## 병합 전 성능과 남은 한계 (2026-10-27)

V43·V46·V47을 같은 자료에서 교대로 측정했다. 1,000개 공통 후보의 입력 9개·경로 6개와
10,000개 공통 후보의 입력 2개·경로 6개에서 표본 9,180개와 실행 계획 80개를 저장했다.
수치와 재현 명령은 [성능 보고서](../../performance/product-search-975.md)에 있다.

호환 필드 변환을 복합 ROW 한 값으로 표현해 필드마다 반복 평가되던 비용을 없앴다.
근거 평가의 복잡한 SQL은 요청별 재계획 비용이 커서 해당 함수 안에서만 generic plan을 재사용한다.
다른 DB 요청의 설정은 바꾸지 않으며, 표기 규칙 교체 후 기존 계획을 재사용하는 회귀도 다시 통과했다.

목록·개수와 대량 후보 경로의 비용을 줄였지만 일부 작은 표시 요청과 전체 JSON 호환 호출에는
회귀가 남는다. HTTP·JDBC 왕복과 준비된 문장 재사용, 실제 운영 자료·동시 요청은 측정하지 않았다.
구조 완료와 로컬 동등성 검증을 운영 성능 승인으로 해석하지 않는다.

중간 구현의 미완료 범위와 합의한 정책은 [이전 인계 기록](product-search-evidence-975-handoff.md)에 보존했다.

## dev 병합과 충돌 수정 (2026-10-29)

`origin/dev`의 `708ed0e6`을 병합해 #979 마크 통합과 #982 후속 수정을 반영했다.
이미 dev에 반영된 `V46__unify_product_marks.sql`은 유지하고, 이 브랜치의 검색 마이그레이션을

후보·메타데이터 사실·교정·점수·제안·연관검색어·호환 함수는 같은 `p_marks` JSON을 전달한다.
제거된 속성·badge 테이블을 참조하지 않으며 표시명은 Java가 소유한다. 독립 V33 스키마를 쓰는
마이그레이션 테스트는 dev 구현을 따랐다. 기존 335개 비교 범위는 dev V46의 마크 계약에 맞췄고,
요청의 마크 정의가 전체 경로로 전달되는 사례를 추가했다.

성능 스크립트는 dev V46·검색 V47·V48과 현재 마크 필터 집계를 비교하도록 변경했다.
보관한 표본은 병합 전 V43·검색 V46·V47 자료이며 번호나 수치를 소급 변경하지 않았다.
사용자의 검증 재실행 금지 요청에 따라 병합 후 테스트·포맷·생성물 검사·성능 측정은 실행하지 않았다.
이 문서의 통과 기록과 성능 수치는 병합 전 결과다.
