# 제품 피부타입 필터

이슈 #422. 공통 SkinType 정의를 사용해 제품 JSON 로딩과 목록·개수 공통 필터를 확장한다.
운영 분류 데이터와 클라이언트 UI는 범위 밖이다.

## 결정

- JSON skin_types는 누락 시에만 빈 집합으로 처리한다. null, 잘못된 타입·코드·중복은 로딩 실패다.
- Product가 불변 피부타입 집합과 일치 판정을 소유하고 감각 추론과 분리한다.
- 요청 skinType은 선택적인 단일 enum이며 기존 조건과 AND로 결합한다.
  기존 선택적 enum 바인딩처럼 빈 값은 미지정, 반복 파라미터는 첫 번째 값을 사용한다.
  쉼표로 연결한 복수 코드는 잘못된 enum 값이므로 400 INVALID_QUERY_PARAMETER로 거부한다.
- 집계는 페이지를 자르기 전 전체 필터 결과를 사용한다. 응답 필드는 확장하지 않는다.

## 검증 결과

- 제품 로딩 계약·도메인 대상 테스트 통과.
- `sh ./scripts/test.sh`: 전체 676개 테스트, 실패·오류·건너뜀 0개.
- 제품 상세, 검색 제안, 공유 매칭, 보관함, 큐레이션 등 기존 소비 경로 회귀 테스트 통과.
- OpenAPI 생성은 최초 서버 기동 약 23초와 문서 생성으로 기본 30초 제한을 초과했다.
  사용자 승인 후 `waitTimeInSeconds = 60`을 설정하고 별도 빌드 커밋으로 분리했다.
- `sh ./scripts/verify.sh`: 생성물 갱신을 확인한 뒤 재실행하여 드리프트 없음과 전체 빌드 통과.
- OpenAPI 차이는 `/api/products`, `/api/products/count`의 선택적인 단일 `skinType` 파라미터뿐이다.
  응답 스키마는 동일하며 공통 타입 선언만 변경됐다. `api.zod.ts`도 재생성했으나 차이가 없다.

운영 제품 분류 데이터는 이슈 범위에 따라 수정하지 않았다. 기존 누락 필드는 미분류로 로딩한다.
