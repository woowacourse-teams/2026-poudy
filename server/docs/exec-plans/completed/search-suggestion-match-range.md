# 검색 제안 일치 구간 제공 계획

## 상태

- 상태: **완료**
- 시작일: 2026-08-27
- 완료일: 2026-08-27
- 추적 이슈: [#268 검색 결과에 하이라이트 범위를 제공한다](https://github.com/woowacourse-teams/2026-poudy/issues/268)
- 소유 도메인: `search`, `product`, `ingredient`

## 목표

제품·성분 검색 제안이 실제로 일치한 원문과 UTF-16 반열림 구간을 함께 반환한다.
클라이언트는 서버의 정규화·초성·라틴 낱자 읽기 규칙을 다시 구현하지 않고 응답의
`match.text`, `startIndex`, `endIndexExclusive`만으로 일치 부분을 강조할 수 있어야 한다.

## 범위와 결정

- 공통 검색 도메인이 정규화된 표현의 각 UTF-16 코드 단위를 원문 구간으로 추적한다.
- 제품 제안은 `PRODUCT_NAME`, `BRAND_NAME` 중 실제 일치 필드와 문자열을 반환한다.
- 성분 제안은 `KOREAN_NAME`, `ENGLISH_NAME`, `ALIAS` 중 실제 일치 필드와 문자열을 반환한다.
- 성분 이명은 전체 목록을 노출하지 않고 실제 일치한 이명 하나만 반환한다.
- 범위는 항상 `match.text` 기준 `[startIndex, endIndexExclusive)`다.
- 같은 문자열에서 여러 구간이 일치하면 첫 구간을 사용한다.
- 제품 목록 검색, 성분 일반 목록 등 검색 제안이 아닌 기존 응답 계약은 유지한다.
- 기존 검색 등급과 동점 순서를 바꾸지 않는다.
- 새 검색 값 객체와 제품·성분 매칭 결과는 `record`가 아니라 불변 클래스로 구현한다.

## 구현 결과

1. 정규화된 검색 표현의 UTF-16 코드 단위를 원문 구간에 연결했다.
2. 공백 제거, NFC, 초성, 쌍자음 접기와 라틴 낱자 읽기에서도 원문 범위를 계산한다.
3. 제품 검색 결과가 제품명·브랜드명 중 선택된 일치 결과를 보존한다.
4. 성분 검색 결과가 한글명·영문명·이명 중 선택된 일치 결과를 보존한다.
5. 검색 제안 전용 DTO와 OpenAPI에 `match` 계약을 추가했다.
6. 공통 TypeScript 계약을 갱신했다.
