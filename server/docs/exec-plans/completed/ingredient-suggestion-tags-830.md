# 성분 자동완성 태그 추가 (#830)

성분 검색 자동완성에서 배합 목적과 빠른 제외 성분군을 함께 반환한다. 검색 순서와
일치 정보, 기존 피부 작용 태그는 유지한다. 두 기능은 각각 테스트·API 문서·공유 타입과
클라이언트 mock을 포함한 별도 커밋으로 구현한다.

## 배합 목적

- 상세 API와 같은 `formulationRoles: [{ id, code, name }]`을 사용한다.
- 기존에 조회한 성분 태그에서 배합 목적을 표시 순서대로 반환한다. 없으면 빈 배열이다.
- [x] 응답과 회귀 테스트, 클라이언트 mock·테스트 fixture를 갱신한다.
- [x] OpenAPI와 공유 타입을 생성하고 서버·클라이언트를 검증한다.

배합 목적만 추가한 상태에서 서버 `verify.sh`와 클라이언트 `pnpm run check`가 통과했다.
서버 테스트 1,496개와 클라이언트 테스트 1,508개를 실행했으며, 클라이언트 빌드는 staging API를 사용했다.

## 빠른 제외 성분군

- 제품 상세의 필드명에 맞춰 `excludeGroups: [{ code, name }]`으로 반환한다.
- `ExcludeCode`에 정의된 성분군만 담고, DB의 정식 표시명을 코드 순서로 반환한다.
- 여러 성분군에 속하면 모두 반환하고, 해당하는 성분군이 없으면 빈 배열이다.
- 기존 `ExcludeCodeLookup`을 확장해 검색된 성분들의 소속 성분군을 일괄 조회한다.
- [x] 응답과 회귀 테스트, 클라이언트 mock·테스트 fixture를 갱신한다.
- [x] OpenAPI와 공유 타입을 생성하고 서버·클라이언트를 검증한다.

최종 상태에서 서버 `verify.sh`와 클라이언트 `pnpm run check`가 통과했다. 서버 테스트 1,500개와
클라이언트 테스트 1,508개를 실행했으며, 소스·테스트·API 생성물은 분리 전 커밋과 일치한다.
로컬 DB의 연결 한도에 맞춰 최종 서버 검증에는 `SPRING_DATASOURCE_HIKARI_MINIMUM_IDLE=0`을 사용했다.

클라이언트 자동완성 mock과 테스트 fixture 수정은 서버 밖 수정 제한의 예외로 사용자와 합의했다.
