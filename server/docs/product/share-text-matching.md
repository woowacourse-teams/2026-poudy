# 공유 텍스트 매칭

## 목적

외부 쇼핑 앱에서 공유한 텍스트를 받아 카탈로그 제품을 찾거나, 찾지 못했음을 안전하게 반환한다. 단축 링크를 열거나 외부 페이지를 조회하지 않고 공유 텍스트만 사용한다.

## 처리 규칙

1. 공유 텍스트에서 안내 문구, 링크, 기획·용량 표기를 분리해 비교할 제품명 후보를 만든다.
2. 후보의 앞부분에서 브랜드를 분리한다. 브랜드를 알면 해당 브랜드의 제품만 비교한다.
3. 정확한 이름, 단일 후보, 안전 조건을 통과한 유사 후보 순서로 제품을 확정한다.
4. 후보가 모호하거나 형태·범위·버전이 다르면 확정하지 않는다. 이때 정제한 검색어를 반환한다.

괄호 표기는 내용 보존·제거 형태를 모두 비교하며, 버전 표식은 제품 식별에 보존한다. 공백, 대소문자, `SPF`·`PA`, `pH`, `앤`·`&` 표기는 비교 시 일반화한다. 용량과 기획 표기는 제품명 정제에만 사용하며 확정 조건에는 사용하지 않는다.

## API 계약

`GET /api/products/share-matches`는 원문을 `text`로 받는다. 서버가 원문을 정제하므로 클라이언트는 브랜드 목록이나 공유 문구 규칙을 보유하지 않는다.

- 제품을 하나로 확정하면 `MATCHED`를 반환한다.
- 확정할 수 없으면 `NOT_FOUND`와 검색어를 반환한다. 이는 정상 응답이며 HTTP 200이다.
- 링크가 없거나 제품명이 남지 않은 입력은 `INVALID_QUERY_PARAMETER`로 거절한다.

## 평가 기준과 결과

매칭 규칙은 학습 데이터로만 조정한다. 검증 데이터는 규칙을 바꾸지 않은 상태에서 평가에만 사용한다. 실제 공유 텍스트를 사용하고, 같은 브랜드가 한쪽 데이터에만 몰리지 않도록 제품을 나눈다.

| 데이터 | 실제 공유 텍스트 | 확정 | 확정률 | 확인된 오매칭 |
| --- | ---: | ---: | ---: | ---: |
| 학습 | 331 | 272 | 82.2% | 0 |
| 검증 | 274 | 232 | 84.7% | 0 |

검증 결과 중 원본 검색 결과의 제품 ID와 달랐던 14건은 실제 공유 텍스트의 제품명과 대조해 카탈로그의 형제 제품으로 올바르게 연결된 것을 확인했다. 확정하지 못한 결과는 오매칭으로 집계하지 않는다.

재현용 수집·평가 산출물은 로컬 빌드 보고서 디렉터리 `server/build/reports/share-match-oliveyoung/`에 둔다. 이 디렉터리는 생성물이며 저장소에 포함하지 않는다.
