# 제품 마크

제품의 속성값과 표식을 `mark(code)`와 `product_mark(product_id, mark_code)`로 관리한다.
`mark`는 FK 기준 코드만 저장한다. 표시명·공개 순서·필터 그룹·목록 표시·카테고리 제한은 Java 정의가 소유한다.

| 코드 | 표시명 | 필터 그룹 | 목록 표시 | 허용 대분류 |
| --- | --- | --- | --- | --- |
| MINERAL | 무기자차 | UV_FILTER_TYPE | X | 선케어 |
| ORGANIC | 유기자차 | UV_FILTER_TYPE | X | 선케어 |
| HYBRID | 혼합자차 | UV_FILTER_TYPE | X | 선케어 |
| EASY_WASH | 이지워시 | WASHABILITY | X | 선케어 |
| WATERPROOF | 워터프루프 | WATER_RESISTANCE | X | 선케어 |
| DAISO | 다이소 | 없음 | O | 전체 |

## 조회 계약

목록·count는 `marks=MINERAL&marks=ORGANIC&marks=EASY_WASH`를 받는다.
같은 그룹은 OR, 다른 그룹과 나머지 조건은 AND다.
생략은 조건 없음, 빈 값·공백·미정의 코드·DAISO는 400 `INVALID_QUERY_PARAMETER`다.
유효 코드의 중복은 하나로 취급하고, 무효 코드가 섞이면 전체 요청을 거절한다.
적용되지 않는 카테고리와 유효 필터를 결합하면 정상적인 0개 결과다.

첫 페이지의 `filterOptions.markGroups`는 그룹 `code`, `name`, `options`를 제공한다.
옵션은 `code`, `name`, `productCount`다. 자기 그룹 조건만 해제하고 검색과 다른 조건을
유지한 후보에서 집계한다. 양수 후보와 현재 선택값을 합쳐 공개하므로 선택값은 0이어도 유지한다.
빈 그룹은 제외하고 후속 페이지에는 `filterOptions`를 생략한다.

제품 목록·카드 응답의 `marks`는 코드의 표시 정책을 적용한 `{code, name}` 배열이다.
현재 목록 표시는 다이소만 제공하며, 없으면 빈 배열이다. 상세는 제품의 연결된 마크를 제공한다. 큐레이션의 기존 제품 응답에는 추가하지 않는다.
프론트는 서버가 준 표시 정보·필터 그룹·순서를 사용하며 정의를 복제하지 않는다.

## 검색

제품명·브랜드명·실제 연결된 모든 마크의 표시명을 검색한다. 표시 대상과 필터 대상은 독립적이다.
검색 토큰은 같은 제품에서 모두 충족해야 하며 검색과 명시적 필터도 AND다.
마크 코드·그룹명은 검색하지 않는다. 부분·초성·오타 교정과 UTF-16 강조 범위는 공통 검색 판정을 따른다.
검색 제안의 마크 일치 필드는 `MARK`다.

Java 코드에서 만든 코드/표시명 JSON을 PostgreSQL 검색 함수에 명시적으로 전달한다.
DB에 이름을 복제한 테이블이나 세션 전역 설정을 두지 않는다. 연결 변경은 검색 뷰를
REFRESH하지 않아도 반영된다. 제품명·브랜드명 변경은 기존 검색 문서 갱신 절차를 따른다.

## 데이터 변경

마크와 제품 카테고리를 변경하는 코드·배치·적재는 `ProductMarkWriter`를 사용한다.
기존 제품을 잠근 뒤 최신 상태를 읽고, 선케어 적용 범위와 자외선 차단 유형 최대 하나를 검증한다.
자외선 차단 유형 여부는 `Mark`가 판단하고, `ProductMarks`가 조합을 검증한다. 필터 그룹 구성에 저장 제약을 의존시키지 않는다.
동일 마크를 중복 부여하는 입력은 거절한다. 조회 필터의 중복 제거와는 별개의 입력 계약이다.
카테고리와 마크를 함께 바꾸려면 `replace(productId, categoryId, marks)`로 최종 상태를 전달한다.
트랜잭션 전체가 성공할 때만 저장하며 제품 수정 시각도 갱신한다.
신규 제품은 등록 트랜잭션에서 제품 행을 저장하고 같은 검증 경로로 마크를 등록한다.

정책 검증을 우회하는 직접 SQL 적재는 지원하지 않는다. SQL FK/PK는 코드 참조와 중복 연결만 보장한다.
기동 시에는 DB 마크 코드와 enum의 일치만 검사한다. 불일치하면 기동을 중단한다.
기존 제품 전체의 카테고리·마크 조합은 기동 시 검사하지 않으며, 제품별 규칙은 저장 시 검증한다.
마크 미등록은 부정값을 뜻하지 않는다.

V46은 기존 연결을 합친 뒤 속성 테이블·마크 조회 뷰를 제거하여 최종 테이블로 전환한다.
기존 Flyway 이력은 수정하지 않으며 구버전 서버와 동시 운영하는 호환 계층은 두지 않는다.
