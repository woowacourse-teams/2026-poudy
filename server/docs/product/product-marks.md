# 제품 표식

`Mark`는 제품에 직접 부여한 표식이며 `mark/product_mark`에서 읽는다.
속성값은 필터와 검색에 사용하고 표식으로 변환하지 않는다. 표식 필터는 제공하지 않는다.
`keyword`는 실제 연결된 마크 이름도 검색하며 제품명·브랜드명·속성값 조건과 AND로 결합한다.
마크 코드로 검색하지 않는다. 표시명과 연결 변경은 별도 REFRESH 없이 검색에 반영된다.

## 응답

목록·상세·검색 제안·랭킹·유사 제품·위시리스트·선반에 `marks: [{code, name}]`을 제공한다.
기존 `badges` 필드는 `marks`로 변경한다. 표식이 없으면 빈 배열이다.
큐레이션의 일반·필터별 제품에는 표식 필드를 추가하지 않는다.

표식은 코드의 C 정렬순으로 반환한다. 같은 표시명인 다른 코드는 합치지 않는다.
목록 카드와 전체 제품 로더는 같은 일괄 표식 조회를 사용한다.
속성 필터 선택지인 `filterOptions.attributes`는 유지하며 제품별 속성 표시 배열은 추가하지 않는다.

제품 검색 제안의 `match.field`는 `PRODUCT_NAME`, `BRAND_NAME`, `ATTRIBUTE_VALUE`, `MARK`다.
`match.text`는 실제로 맞은 필드의 원문이며 강조 범위는 그 원문의 UTF-16 반열림 구간이다.
새 enum 값은 OpenAPI·공통 생성 계약을 갱신한 client와 배포를 조율한다.

## 저장·전환

V26은 기존 `badge/product_badge`를 원본으로 유지하면서 `mark/product_mark` 조회 뷰를 추가한다.
뷰의 `mark_code`는 기존 `badge_code`다. 정의·제품 연결·시각을 복사하지 않으므로 구버전과 같은 데이터를 읽는다.
이 단계의 직접 적재는 기존 테이블을 사용한다. 표식 코드 변경 금지, 중복 연결 방지, FK는 유지한다.

구버전 서버와 기존 적재 경로 종료 후 `db/deferred/finalize_product_marks.sql`을 다음 배포의 새 Flyway
마이그레이션으로 승격한다. 이 단계에서 뷰를 제거하고 실제 테이블과 컬럼을 이름 변경한다.
V26과 같은 배포에 넣지 않는다. 실제 테이블의 최종 키는 `mark(code)`, `product_mark(product_id, mark_code)`다.

기존 속성 배지의 이관은 [제품 속성](product-attributes.md)의 적재 절차를 따른다.
다이소 연결과 알 수 없는 기존 표식은 보존한다. SNS 핫템 데이터·표시·선정 기능은 추가하지 않는다.

## 수정 시각

속성값 등록·수정·삭제와 선택값 표시명 변경은 DB 트리거가 영향 제품의 `updated_at`을 갱신한다.
직접 표식 정의·연결의 변경은 기존 계약대로 적재하는 쪽에서 제품 `updated_at`도 함께 갱신한다.
이름은 내부 공백을 허용하고 빈 문자열·공백뿐인 이름은 금지한다. 코드는 공백을 허용하지 않는다.
