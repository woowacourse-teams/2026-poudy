# 감각 추론 v0 기준과 한계

이 문서는 현재 서버가 제품의 수분감·유분감 `0~3`을 만드는 방식과 한계를 설명한다.
v0의 목표는 수동 레벨이 없는 제품에도 같은 입력에서 같은 결과를 제공하는 대략적인
기준선을 만드는 것이다.

## 출력 의미

- 수분감과 유분감은 도포 5분 후의 대략적인 사용감을 서로 독립적으로 표현한다.
- 두 값은 임상 보습 효능, 장벽 개선, TEWL 또는 피부 타입별 적합도 점수가 아니다.
- API에는 기존 계약대로 정수 `0~3`을 반환한다.
- 내부 `ProductSensory`는 두 레벨과 confidence, 계산에 사용한 모델 버전을 함께 보관한다.
- confidence는 실제 정답률이 아니라 현재 입력 근거의 상대적인 충실도를 나타낸다.

## 입력과 계산

서버는 기동 시 `products.json`의 각 제품을 한 번 생성하면서 다음 값을 사용한다.

1. 제품 category의 수분감·유분감 시작점
2. 원문 순서가 보존된 전성분 목록
3. `HUMECTANT`, `MOISTURISING`, `EMOLLIENT`, `ABSORBENT` 역할 태그
4. 기존 태그를 보완하는 소수의 canonical ingredient ID 프로필

전성분 앞쪽일수록 더 큰 가중치를 주지만 이를 정확한 함량으로 간주하지 않는다.
category 시작점에 제한된 성분 보정만 더한 뒤 `0~3` 범위로 제한하고 가장 가까운 정수로
변환한다. 중복 성분 ID는 점수에 한 번만 반영하고 confidence를 낮춘다.

모델 버전은 실제 계산에 사용되는 세 부분을 독립적으로 기록한다.

- 성분 감각 프로필
- category 시작점
- 단계 변환 모델

## 현재 장점

- 원천 JSON에 사람이 입력한 `moisture_level`, `oil_level`이 없어도 전 제품을 생성한다.
- 같은 category, 전성분 순서와 모델 버전에는 항상 같은 결과를 낸다.
- 수분감과 유분감을 독립적으로 계산한다.
- 목록·상세·filter·count가 같은 `ProductSensory` 값을 사용한다.
- 미분류 성분을 임의의 0점 근거로 사용하지 않고 confidence를 낮춘다.
- 성분 이름의 쉼표나 `/`를 해석하지 않고 canonical ingredient ID만 사용한다.

## 알려진 한계

| 한계 | 영향 |
| --- | --- |
| 전성분 순서만 사용하고 정확 함량을 모름 | 같은 순서지만 함량이 다른 처방을 구분하지 못한다. |
| 1% 경계를 모름 | 저농도 성분이 앞 순서 가중치로 과대평가될 수 있다. |
| category 시작점이 단순 규칙에 의존함 | 같은 category 안의 제형 차이를 충분히 나누지 못한다. |
| phase와 5분 dry-down을 계산하지 않음 | 휘발성 용매, 실리콘, 파우더, 왁스의 잔류감 차이를 축약한다. |
| 공식 사용법이 없음 | rinse-off 제품을 leave-on 감각으로 검증할 수 없다. |
| confidence가 입력 근거의 충실도만 표현함 | 실제 정확도 확률로 해석할 수 없다. |

외부 199개 제품으로 서버 기동과 전체 추론 성공을 확인했지만, 원본과 파생 제품·성분
식별 정보는 저장소에 커밋하지 않는다. 이 실행은 계산 경로가 동작한다는 확인이며 실제
정확도의 증거는 아니다.

## 후속 고도화

농도 추정, 상 조성, dry-down, 제형 분류와 원천 수집 파이프라인은
[제품 유수분 감각 추론 고도화 계획](../exec-plans/active/product-sensory-inference.md)과
GitHub 이슈 `#68`에서 진행한다. 해당 기능은 실제 입력과 소비 흐름이 생길 때 필요한
계약부터 단계적으로 추가하며, 오프라인 수집·검증 도구는 운영 Boot artifact에 포함하지
않는다.
