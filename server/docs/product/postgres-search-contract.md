# PostgreSQL 상품과 성분 검색 계약

## 목적과 적용 범위

#480과 #492의 DB 검색 전환에서 사용할 목표 동작이다. 기존 Java 구현과 전달받은
`poudy-full-schema.sql`을 비교해 정리했다. 아래 기대 결과는 후속 구현의 테스트 기준이며
첨부 SQL이 이미 모두 충족한다는 뜻이 아니다. 실제 데이터 적재와 검증은 범위에서 제외한다.

상품 목록, 상품 검색 제안과 성분 검색 제안에 적용한다. 브랜드 검색, 공유 텍스트 식별,
인기 검색어 사전의 키 정규화는 각 기능의 기존 계약을 유지한다. 공용 `SearchKeyword`를
일괄 변경해 다른 기능의 동작까지 바꾸지 않는다.

## API와 입력

| 경로 | 검색 조건과 결과 |
| --- | --- |
| `GET /api/products` | keyword 생략 시 검색 제한 없음. 지정 시 검색 결과와 필터를 AND로 결합한다. |
| `GET /api/products/count` | 목록과 동일한 검색, 교정 및 필터 조건의 개수를 반환한다. |
| `GET /api/products/suggestions` | keyword 필수. 관련도순 페이지와 전체 개수를 반환한다. |
| `GET /api/ingredients/suggestions` | keyword 필수. 관련도순으로 서로 다른 성분을 최대 5개 반환한다. |
| `GET /api/ingredients` | 현재의 ID 목록 및 사용 성분 조회다. keyword 검색 API로 확장하지 않는다. |

- 기존 요청과 응답 필드, 오류 형식은 유지한다. keyword는 기존 기준인 UTF-16 길이 100
  이내다. 누락 가능한 상품 목록과 달리 제안의 누락, 빈 문자열과 공백 입력은 기존처럼 거절한다.
- 현재 검증을 통과하는 기호 전용 입력(`---` 등)이 검색 정규화 후 비면 검색 결과 0건이다.
  keyword 미지정으로 해석해 전체 상품을 반환하지 않는다. SQL 내부의 빈 질의도 0건이다.
- 상품 페이지는 1부터, 기본 page 1과 size 20, size 1~100을 유지한다.
  결과를 넘긴 페이지는 빈 items와 원래 total을 반환한다.
- `tier`, `rank`, `tokenRatio`, `recentViews`, `corrected_query`는 내부 값이다.
  새 API 필드를 추가하지 않는다. 교정은 서버 내부 검색에만 사용한다.

## 정규화와 일치 판정

- 검색 비교용 문자열은 NFC, ASCII 영문 소문자화, 전각 영문과 숫자의 ASCII 변환을 적용한다.
  조합형 초성은 호환 초성으로 맞춘다. 한글, 자모, 영문과 숫자를 남기고 공백과 기호를 제거한다.
  표시 원문은 그대로 유지한다. 기호 제거와 전각 처리는 기존 Java와 다른 의도적인 변경이다.
- 공백 토큰은 정규화 전에 분리한다. NBSP 등 기존 검색에서 공백으로 취급한 문자도 포함한다.
  정규화 후 빈 토큰은 버리고 중복 토큰은 첫 등장만 남긴다.
  유효한 100자 입력의 토큰을 모두 판정한다. 첨부 SQL의 `LIMIT 10`은 채택하지 않는다.
- 완전 일치 0, 접두 일치 1, 포함 또는 전체 토큰 일치 2, 일부 토큰 일치 3 순이다.
  상품 목록과 count는 0~2만 사용하고, 상품과 성분 제안은 0~3을 사용한다.
- 상품의 여러 토큰은 상품명, 브랜드 한글명과 영문명에 나뉘어 맞아도 된다.
  각 토큰은 개별 필드 안에서 일치해야 한다. 필드 경계를 이어 붙여 만든 가짜 부분 일치는 제외한다.
- 성분은 한글명, 영문명과 각 별칭을 각각 판정한 뒤 가장 좋은 표현 하나를 선택한다.
  서로 다른 이름이나 별칭의 토큰을 합쳐 전체 토큰 일치로 승격하지 않는다.
- 토큰 일치율은 맞은 고유 토큰 수 / 전체 고유 토큰 수다. 인정된 붙임 복합 검색은 1이다.

### 브랜드와 상품의 붙임 검색

기존 `ProductSearchTest`의 양방향 조합과 브랜드 접두 규칙을 유지한다. 한 토큰을 두 조각으로
나눠 브랜드와 상품명을 판정하며, 브랜드는 완전 일치 또는 2글자 이상 접두 일치여야 한다.
브랜드 중간 부분과 한 글자 접두 일치는 인정하지 않는다. 브랜드 전체가 한 글자면 완전 일치는
인정한다. 성립한 복합 검색은 tier 2다. 공백으로 분리한 질의는 앞의 토큰 규칙으로 판정한다.

첨부 SQL은 붙임 검색에서 브랜드 완전 일치만 인정한다. 순위 변경과 별개인 기존 검색 가능
범위를 보존하기 위해 이 부분은 수정한다. 동일 상품에서 여러 분할이 가능하면 상품 조각이
긴 것을 고르고 동률은 정규화 조각의 고정 문자 순서로 결정한다.

### 초성과 라틴 읽기

- 한 글자 단자음은 대응 쌍자음도 찾는다(`ㅂ`은 `빨간`에 일치). 여러 초성은 정확히 맞춘다.
  `ㅂㄱ`은 `빨간`에 불일치하고 `ㅃㄱ`은 일치한다. `ㅃ`은 `바보`에 불일치한다.
- 숫자나 영문을 건너뛰어 초성을 이어 붙이지 않는다. 영문 전용 성분명은 초성 검색 대상이 아니다.
- 한글을 포함한 이름의 영문 연속 구간은 기존처럼 4글자 이하만 낱자로 읽는다.
  한글 없는 영문 이름과 5글자 이상 구간은 그대로 둔다. 질의도 4글자 상한을 적용한다.
- 영문 한 글자뿐인 질의는 읽지 않는다. `e`로 한글 `이`를 광범위하게 찾지 않도록 하는
  의도적인 변경이다. `비타민c`, `b5`처럼 붙은 한 글자는 읽는다.
- 원형 및 읽기 형태 양쪽의 초성 후보를 보존한다. 검색 판정과 강조 구간은 같은 형태를 사용한다.

## 순위와 정렬

| 대상 | 오름차순 기준. DESC 표시는 내림차순 |
| --- | --- |
| 상품 제안 | tier, 토큰 일치율 DESC, 최근 30일 조회수 DESC, 정규화 상품명 길이, 상품 ID |
| 성분 내부 표현 선택 | tier, 토큰 일치율 DESC, 필드 우선순위, 정규화 표현 길이, 별칭 표시 순서 |
| 성분 제안 | 선택한 표현의 tier, 토큰 일치율 DESC, 필드 우선순위, 정규화 표현 길이, 성분 ID |

성분 필드 우선순위는 한글명, 영문명, 별칭 순이다. tier가 먼저이므로 정확히 맞은 별칭은
부분 일치한 정식 이름보다 앞설 수 있다. 기존의 정식 이름 우선, 직접 표기 우선과 `/` 복합명
후순위는 별도 정렬 조건으로 유지하지 않는다. 이는 #480이 허용한 순위 변경이다.

조회수는 한국 날짜 기준 오늘 포함 30일 합계다. 오늘을 D라 하면 D-29~D를 포함하고
D-30과 미래 날짜는 제외한다. 기록이 없으면 0이다. 고정된 데이터에서 ID로 동점을 해소한다.
요청 사이 조회수가 바뀌면 순위도 바뀔 수 있으며 페이지 전체의 고정 스냅샷 API를 추가하지 않는다.

상품 목록은 위 관련도순으로 정렬하지 않는다. 기존 `NAME_ASC` 기본값과 이름/가격 ASC/DESC를
유지하며 동점은 ID 오름차순이다. 대표 가격은 첫 표시 옵션의 가격이며 최저가로 바꾸지 않는다.
Java 문자열 정렬과 DB 로케일 정렬 차이를 테스트로 확인해 기존 목록 순서를 보존한다.

## 오타 교정

첨부 SQL의 교정 흐름을 기준으로 구현한다.

1. 원질의의 tier 0~2 결과가 카탈로그에 하나라도 있으면 교정하지 않는다.
2. 없다면 검색 대상의 어느 이름에도 포함되지 않은 3글자 이상 토큰만 교정 후보로 삼는다.
   초성 토큰과 짧은 토큰은 바꾸지 않는다. 상품과 성분의 어휘 사전은 구분한다.
3. 자모 유사도 0.5 이상 중 유사도, 빈도, 고정 문자 순서로 교정어를 선택한다.
4. 질의가 바뀌고 해당 검색 범위에 결과가 있으면 교정 결과로 대체한다. 원질의 결과와 섞지 않는다.
   없으면 원질의 결과를 유지한다. 재귀 교정은 하지 않는다.

상품 목록은 교정 결과도 tier 0~2로 제한한다. 검색 질의 선택은 사용자 필터와 페이지를
적용하기 전에 한 번 결정한다. 필터로 0건이 됐다는 이유로 교정을 다시 시도하지 않는다.
목록, count와 필터 선택지 집계는 같은 선택된 질의를 사용한다.

## 일치 필드와 강조 구간

- 기존 match의 field, 원문 text, startIndex와 endIndexExclusive를 유지한다.
  상품은 PRODUCT_NAME/BRAND_NAME, 성분은 KOREAN_NAME/ENGLISH_NAME/ALIAS다.
- 구간은 UTF-16의 0 기반 반열림 구간이며 `0 <= start < end <= text.length()`여야 한다.
  빈 구간이나 null로 성공 응답하지 않는다. 일치 구간 계산 실패를 임의 구간으로 숨기지 않는다.
- 상품 질의 전체가 여러 필드에 같은 tier로 맞으면 상품명, 브랜드 한글명, 영문명 순으로 고른다.
  붙임 복합 검색은 상품명에서 맞은 조각을 표시한다.
- 전체 표현이 맞지 않는 토큰 검색은 상품명, 브랜드 한글명, 영문명 순으로 맞은 필드를 고른다.
  해당 필드에서 가장 긴 일치 토큰, 동률이면 입력 순서의 토큰을 사용한다.
  성분은 선택한 표현의 가장 긴 일치 토큰을 같은 방식으로 고른다.
- 선택한 조각의 첫 일치 구간 하나를 반환한다. 전체 표현 일치는 중간 공백과 기호까지 포함한다.
  읽기로 확장한 이름은 원문의 영문 위치로, 교정 검색은 교정어가 맞은 원문 위치로 되돌린다.

## 합성 데이터 테스트 명세

각 행은 독립된 최소 데이터셋을 사용한다. 명시하지 않은 조회수는 0이며 부수적인 이름이나
교정 어휘가 결과를 바꾸지 않도록 한다. DB 실행 테스트로 옮기기 전의 수용 기준이다.

| ID | 입력과 데이터 | 기대 결과 |
| --- | --- | --- |
| N01 | ` DR.G `, 브랜드 `Dr.G` | 대소문자, 공백과 점을 무시하고 해당 브랜드 상품 검색 |
| N02 | `ＰＤＲＮ`, 상품 `PDRN 크림` | 원형 검색 결과와 같음 |
| N03 | NFD로 입력한 `글리세린`, NFC 성분명 | NFC 입력과 동일 결과 |
| N04 | keyword `---` | 제안 0건, 목록과 count 0건. 전체 목록으로 변환하지 않음 |
| N05 | `토너` + NBSP + `수분` | 일반 공백으로 나눈 두 토큰과 동일 |
| N06 | `가 나 다 라 마 바 사 아 자 차 카`, 상품명 `가나다라마바사아자차` | 목록 제외, 제안 tier 3 및 일치율 10/11. 마지막 토큰을 버리지 않음 |
| N07 | `토너 토너`, 상품 `토너` | 중복 토큰을 한 번만 세며 단일 질의와 동일 |

| P02 | 같은 데이터에 `운드독도`, `라독도` | 중간 브랜드 조각 및 한 글자 접두이므로 불일치 |

## 첨부 SQL을 그대로 사용하면 안 되는 지점

1. `search_query_tokens`의 10토큰 제한은 전체 토큰 일치 계약과 충돌한다.
2. 붙임 검색의 브랜드 완전 일치 제한은 기존 2글자 이상 접두 검색을 누락한다.
3. 초성의 한 글자 쌍자음 접기와 원형/읽기 후보를 기존 테스트에 맞춰 보완해야 한다.
4. 라틴 읽기의 4글자 상한을 복구하고 단일 영문 질의의 읽기 제한은 명시적으로 적용한다.
5. SQL 검색용 정규화와 기존 Java 사전 키 정규화를 섞지 않는다. 토큰 구분을 잃은
   `SearchKeyword.value()`만 SQL에 넘기지 않고 원래 질의의 토큰 경계를 보존한다.
6. 기호 제거, 전각 변환과 강조 구간 계산이 같은 변환을 사용해야 한다. null matchRange를
   허용하는 내부 SQL 결과를 그대로 `@NotNull` API 응답에 전달하지 않는다.
7. 상품 목록에 제안용 관련도 페이지를 먼저 적용하지 않는다. 필터와 기존 정렬 적용 뒤
   페이지를 자르고 같은 후보 집합에서 count와 선택지를 계산한다.

## 검증과 후속 작업

기존 근거 테스트는 `SearchKeywordTest`, `LatinReadingTest`, `ProductSearchTest`,
`IngredientSearchOrderTest`다. 이 테스트는 현재 Java 계약을 설명하며 새로운 SQL의 통과
증거가 아니다. 위 사례를 3~5단계의 SQL, 저장소와 API 테스트에 옮긴다.
순위 변경에 해당하는 기존 기대 순서는 새 계약으로 대체하고 보존 사례는 그대로 검증한다.
전체 `verify.sh`와 DB 통합 테스트는 테스트 DB 준비 후 해당 구현 단계에서 수행한다.

2026-09-20에 위 4개 클래스의 기존 단위 테스트 79개를 실행해 모두 통과했다.
신규 검색 구현의 테스트 결과로 해석하지 않는다.

```sh
sh ./gradlew test \
  --tests com.poudy.search.domain.SearchKeywordTest \
  --tests com.poudy.search.domain.LatinReadingTest \
  --tests com.poudy.product.domain.ProductSearchTest \
```
