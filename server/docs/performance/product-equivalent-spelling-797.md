## 구현과 기능 확인

사용자가 조회 패턴 방식의 이전 구현을 폐기하고 상품 검색용 표준형 저장을 선택했다.
최종 V34만 추가하며 적용된 V1~V33은 변경하지 않는다. 규칙은
`search_product_spelling_rules()`의 `[대체 표기, 표준형]` 배열에 선언한다.
현재는 `[['썬크림','선크림']]`뿐이며 상품 원문·기존 정규화 열·공유·성분 검색은 보존한다.

기존 materialized view 끝에 표준형 열을 추가하고 표준 문서 GIN 인덱스 두 개를 만든다.
원래 값과 같은 표준값은 NULL로 저장하고 비교 시 원래 값으로 대체해 중복 저장을 줄였다.
완성 표현이 있는 조건만 표준값을 쓰며, 나머지 부분 토큰은 원래 값으로 비교한다.
이름 검색은 토큰 판정과 브랜드 분리 준비를 한 번 계산하고, 메타데이터 후보가 없으면
기존 이름 hit를 그대로 사용한다. 기존 page와 공개 함수의 인자·타입·JSON은 유지한다.

API 테스트는 양쪽 전체 ID 집합·개수, 붙여쓰기·브랜드·속성·표식 AND, 필터·정렬·전체 페이지,
실제 원문 강조·UTF-16·교정·인기 검색어 결과 존재 판단을 확인한다. 입력 간 페이지 순서는
비교하지 않는다. 현재 선반 경로 `/api/users/me/shelf/product-suggestions`와 기존 제안 API도
검증한다. `선크/썬크`는 실제 원문 부분 문자열이며, `선크리/썬크리`의 리→림은 기존 교정과
구분한다. 미완성 입력을 표준화 규칙으로 완성시키지 않는다.

추가 규칙 테스트는 임시로 `['검증짧','검증긴표기']` 한 행과 문서 갱신만 적용해 이름·붙여쓰기·
개수·존재 확인·다른 길이의 원문 강조가 동작하고 core 정의가 바뀌지 않는지 검사한다.
이 테스트 표현은 운영 규칙에 등록하지 않는다. 업그레이드 테스트는 V33 정의를 복원한 뒤
V34를 적용하고 원래 열·함수 OID·소유자·SELECT 권한·5개 인덱스·1~4인자 호출·공유·성분을 확인한다.
빈 스키마 전체 적용은 SpringBootTest의 clean/migrate로 확인한다. MV 재생성에 CASCADE는 사용하지 않는다.

## 최종 성능 결과

PostgreSQL 18.6, UTF8/C.UTF-8, shared_buffers=128MB, work_mem=4MB,
max_parallel_workers_per_gather=2, statement_timeout=0이다. 양쪽 환경과 상품 수 1,029개가 같다.
호스트는 Apple M5 Pro·macOS 26.6.2이며 Gradle Java 21 toolchain을 사용했다.
버전별 4,800개 표본에서 사전 고정한 48개 조합 중 **44개 통과, 4개 초과**다.
표기 확장 입력 4개 × 경로 4개는 모두 허용 시간 안에 들었다.

**#703 전체 성능 기준은 미통과다.** 나머지 4개 조합의 확인이 남아 있다.
확장 입력의 실행 계획에서는 표준값 GIN 두 개가 실제 실행됐다. shared hit 281~297,
shared read·임시 블록 읽기/쓰기는 0이다. 일반 입력은 기존 원문 인덱스를 계속 사용한다.

원시 표본·구간별 p50/p95·전체 요약·고정 한계·환경·실행 계획·측정 코드는 하나의
[최종 측정 자료](product-equivalent-spelling-797.json.gz)에 보관한다. `benchmark_source`를
server/src/test/java/com/poudy/product/controller/Search797BenchmarkTest.java에 추출한 뒤
동일 fixture를 기준 커밋과 최종 코드에 넣고, server/에서 각각
`POUDY_797_PHASE=before sh ./scripts/test.sh --tests '*Search797BenchmarkTest'`와
`POUDY_797_PHASE=after sh ./scripts/test.sh --tests '*Search797BenchmarkTest'`로 재현한다.
출력 디렉터리 `/private/tmp/poudy-797-standard`를 먼저 만들고, 측정 후 임시 Java 파일은 제거한다.
일반 검증에는 이 측정 코드를 포함하지 않는다. 중간 구현·중간 실험 자료는 최종 diff에 넣지 않았다.

로컬 합성 데이터·동시 호출 1개·jit=off의 결과다. 측정 fixture에서는 메타데이터 후보가 없어
이름 hit를 재사용하는 경로를 사용한다. 속성·표식 혼합 검색의 정확성은 별도 API 회귀로 검증했지만
그 부하의 성능·운영 자료·HTTP 왕복·기본 JIT·동시 부하·문서 재생성 비용을 보장하는 측정은 아니다.

## 전체 검증

`server/`에서 `sh ./scripts/verify.sh` 통과. API 생성물 드리프트 없이 전체 빌드·Spotless·
Checkstyle·구조 검사를 완료했다. 테스트 1,700개, 실패·오류·건너뜀 0개이며, 동등 표기 33개와
업그레이드 1개를 포함한다. 임시 성능 측정 테스트는 제거했고 검증을 우회하거나 약화하지 않았다.
