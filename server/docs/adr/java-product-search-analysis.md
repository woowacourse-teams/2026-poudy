# 상품 검색의 Java 분석

## 결정

상품 검색의 한글 조합·역할별 기본 자모·영문 읽기와 UTF-16 원문 위치는 Java가 소유한다. 검색어와 카탈로그 이름을
같은 `ProductSearchAnalyzer`로 처리한다. 성분 검색·공유 매칭·인기 검색어의 집계 표현은 변경하지 않는다.

`product/search/domain`은 분석(`analysis`), 조건(`query`), 이름(`name`), 위치를 보존한 표현(`text`)을 구분한다.
한글 조합과 영문 읽기는 분석기 아래의 전용 협력 객체다. 원문 위치는 검색 표현이 소유한다. Domain은 Spring·JDBC·JSON을 알지 않는다.

`ProductSearchService`는 요청 분석과 오타 교정 후 재검색을 조율한다. `ProductSearchRepository`는 기존 상품 필터·목록·개수와
제안을 조회한다. SQL은 JSON으로 전달한 분석 조건을 행으로 풀고 `product_search_name`의 표현과 비교한다.
검색 결과를 JSON으로 만들었다가 다시 행으로 푸는 기존 목록 경로는 사용하지 않는다.
일반 검색 결과와 필터 전 전체 일치 여부는 한 번의 SQL에서 계산한다.

## 검색 자료와 일치 근거

`product_search_name`은 상품 ID·이름 필드·표현 종류·분석 버전을 키로 한다. 원문, 정규 문자열, 검색 표현과 시작·끝 위치 배열을
보관한다. 이름 필드끼리는 이어 붙여 판정하지 않는다. 역할별 자모와 음절 끝 표시로 `닭/달고`, `크리/크림`을 구분한다.
복합모음 7개와 겹받침 11개를 기본 자모로 나누며 쌍자음·ㅐ/ㅔ는 합치지 않는다.

표현은 DIRECT·READING·INITIALS·READING_INITIALS다. 읽기 형태가 원형과 같으면 별도 읽기 행을 만들지 않는다.
순위에는 가장 좋은 등급을 쓰고, 강조에는 기존처럼 원문 표현을 먼저, 읽기 표현을 다음으로 사용한다. 일치한 행의 위치 배열이
강조 범위를 결정한다. 초성도 원문을 다시 추측하지 않는다. 현재 일치는 모두 직접 일치다. 미완성 해석과 별칭 확장은 별도 작업이다.

일반 검색과 초성 검색은 부분 GIN 인덱스를 따로 쓴다. 질의 전체와 토큰이 같은 조건이면 이름 비교를 공유한다.
브랜드 표현은 브랜드별 대표 상품 한 곳에서 읽고, 브랜드와 상품 조합은 실제 브랜드 ID로 연결한다.

## 적재와 버전 전환

server 디렉터리에서 `./gradlew productSearchAnalyzerJar`를 실행하면 같은 클래스에서
`build/libs/product-search-analyzer.jar`를 만든다. 명령은 Java 21 표준 라이브러리만 사용하고 DB에 접속하지 않는다.
Python 적재기가 실제 상품 ID와 이름을 배치로 보내면 버전·표현·원문 위치를 반환한다.
UTF-8 TSV의 원문과 검색 문자열은 Base64로 전달한다.

`poudy-private/db-load/product_search_analysis.py`는 결과의 버전·원문·중복·누락·위치를 검증하고 기존 psql 연결에 COPY한다.
초기 적재와 추가 적재 모두 같은 JAR를 쓴다. 추가 적재의 상품·사전·검색 자료·기존 뷰·유사도는 같은 트랜잭션에서 커밋한다.
분석 실패와 후속 단계 실패 시 전체를 롤백한다. 미리보기는 읽기 전용이며 JAR 버전을 확인한다.

기존 DB의 전환 순서는 다음과 같다.

1. 기존 서버 코드에 V21 스키마 확장만 포함한 선행 배포를 한다. 기존 함수와 뷰는 보존한다.
2. 새 서버와 같은 JAR를 포함한 적재 패키지를 준비한다.
3. `rebuild_product_search.py`를 기본 읽기 전용으로 확인하고, 승인된 적재 작업에서 `--apply`로 자료를 만든다.
4. 새 서버로 전환한다. 새 서버는 시작할 때 상품·브랜드 원문과 현재 분석 자료의 누락 여부를 검사한다.

Flyway에서 Java를 실행하거나 자료를 만들지 않는다. 자료를 준비하지 않은 채 새 서버부터 올리면 기동을 실패시킨다.
서버만 롤백하면 기존 함수와 뷰를 그대로 사용할 수 있다. 새 적재기는 구형 스키마에서는 기존 경로를 사용하며,
새 테이블이 있는 스키마에서는 JAR가 없거나 버전이 다르면 쓰기 전에 중단한다.
실제 배포·운영 자료 반영은 이 코드 변경에 포함하지 않는다.

## 검증

분석기는 현대 한글 11,172자의 조합·분해·음절 경계, NFC/NFD·호환 자모와 영문 읽기의 UTF-16 범위를 검증한다.
DB·API 테스트는 기존 검색의 순서·강조·필터·개수·페이지, 분리 입력의 동등성과 잘못된 음절/필드 경계의 불일치를 검증한다.
Python 통합 테스트는 실제 JAR의 결과, 실제 ID로 저장, 분석 실패와 이후 SQL 실패 시 전체 롤백을 확인한다.
